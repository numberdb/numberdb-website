## The audit

The audit's form is right, but on this table its conclusion is wrong. The two
values of `normalisation` are the same number in two conventions, related by
the factor $2^{1/4}$. The skill keeps those in one table ("where two entries
are one object in two conventions, one table"). $2^{1/4}$ is not a factor a
reader holding one value would guess, so both rows are worth having. The table
should stay one table.

The trouble is how the finding was answered. The last commit, `23a175c`
("clarify Ramanujan Weber convention"), rewrote the Definition to say "one
number in two invertible conventions". In doing so it deleted the only
sentence that said what $G_n$ is. See finding 1.

## Findings, most worth doing first

### 1. The Definition no longer defines $G_n$. Worth doing.

It renders:

> For $n\in\mathbb{Z}_{>0}$, take $\sqrt{-n}=i\sqrt n$ and $\tau=i\sqrt n$.
> The rows store one number in two invertible conventions: Ramanujan's
> class-invariant convention $G_n$ and Weber's convention
> $\mathfrak f(i\sqrt n)=2^{1/4}G_n$.

This defines $\mathfrak f$ in terms of $G_n$, and $G_n$ in terms of nothing.
A reader has to go to Formula (1) to find what $\mathfrak f$ is, and derive
$G_n$ from it. Two people could not build the same table from the Definition
alone. The previous revision had it:
$G_n=2^{-1/4}q^{-1/24}\prod_{m\geq1}(1+q^{2m-1})$ with $q=e^{-\pi\sqrt n}$.
The rest of the sentence has smaller faults:

- $\tau$ is set and then never used in the Definition.
- "take $\sqrt{-n}=i\sqrt n$" exists only to reconcile the title's notation
  with the text's (finding 6).
- "invertible conventions" says nothing that "conventions" does not, since
  every normalisation by a nonzero constant is invertible.
- "Ramanujan's class-invariant convention $G_n$" makes $G_n$ sound like a way
  of writing something, when it is the object itself.

**Fix:** restore the product and keep the audit's answer in one clause:

> For a positive integer $n$ let $q=e^{-\pi\sqrt n}$. Ramanujan's class
> invariant is $G_n=2^{-1/4}q^{-1/24}\prod_{m\geq1}(1+q^{2m-1})$, and Weber's
> function at the same point is $\mathfrak f(i\sqrt n)=2^{1/4}G_n$. Each $n$
> is stored in both normalisations. CITE{BorweinBorwein} CITE{Duke}
> CITE{BerndtChanZhang}

### 2. At even $n$ the classical invariant is $g_n$, which the table does not hold, and `complete-note` gives no reason for the range. Worth deciding.

Ramanujan's and Weber's tables use two functions:

- $G_n$, from Weber's $\mathfrak f$, chiefly for odd $n$;
- $g_n=2^{-1/4}q^{-1/24}\prod_{m\geq1}(1-q^{2m-1})$, from Weber's
  $\mathfrak f_1$, for even $n$.

For even $n$, $G_n$ is still defined and algebraic. It is simply not the
number the literature quotes, so a reader arriving with an even-index class
invariant most likely holds $g_n$. Computed in Sage:

| $n$ | $G_n$ (stored) | $g_n$ (not stored) |
|---|---|---|
| 2 | 1.0238072749… | 1 |
| 4 | 1.0945882885… | 1.0905077326… |
| 6 | 1.1592874161… | 1.1582330346… |
| 10 | 1.2721429622… | 1.2720196495… $=\sqrt{\varphi}$ |
| 58 | 2.2787238543… | 2.2787238541… |

A reader holding $g_{10}=\sqrt{(1+\sqrt5)/2}$ to eight places finds nothing.
The two functions converge as $n$ grows, which is why $g_{58}$ happens to
match $G_{58}$ to ten digits: a coincidence, not coverage.

The `complete-note` reads "for every integer $1\leq n\leq100$". It says
what the table holds but not why. The skill asks the note to carry that
argument.

**Fix:** the owner has to choose between two options.

- Keep the range, and add a clause to `complete-note` giving the reason
  (for example, the shared index with T295 and T296). Add a comment saying
  that for even $n$ the published tables give $g_n$, which is not here.
- Or make $g_n$ its own table. It is a different function, not another
  normalisation of this one, so it should not go into this table as a third
  value of `normalisation`.

I would not drop the even rows: they are correct values of the function the
title names.

### 3. Both parameters render with their title repeated. Worth doing; two strings.

### 4. Comment (1) points at "the other singular-value tables" instead of naming them, and `Similar tables` omits the closest relative. Worth doing.

It renders: "The index $n$ is the $r$ used for the CM point in the other
singular-value tables." A reader cannot tell which tables are meant, and
nothing on the page links to them. They are T295 and T296. T296 already links
its sibling as `HREF{T295}`, so the same form works while both are drafts.

T295 is also the table Formula (2) needs. $G_n^{-24}=4m_n(1-m_n)$, and
$m_n=\lambda(i\sqrt n)$ is stored in T295 as $m_r$. Yet `Similar tables`
lists T97, T83 and T129, and not T295. The notation also changes silently
between tables: $m_n$ here, $m_r$ in T295.

**Fix:**

- Comment (1): "The index $n$ is the $r$ of HREF{T295}[the singular moduli
  $k_r$] and of HREF{T296}[$K(k_r)$]. The point is $\tau=i\sqrt n$, and the
  order is $\mathbb{Z}[\sqrt{-n}]$, of discriminant $-4n$."
- A `Similar tables` entry for T295: "holds $m_r=\lambda(i\sqrt r)$, and
  $G_r^{-24}=4m_r(1-m_r)$ by CITE{formula-singular-modulus}".

### 5. Comment (2) and `rigour details` name rows by parameter key. Worth doing.

Comment (2) renders as "The `ramanujan` rows store $G_n$. The `weber` rows
store $\mathfrak f(i\sqrt n)$. These are two invertible normalisations
because …", with the two keys in code font. `rigour details` has "The

**Fix:** delete comment (2). In `rigour details`, write "The $G_n$ entries
divide the same real ball by $2^{1/4}$".

### 6. The title writes $\mathfrak f(\sqrt{-n})$; everything else writes $\mathfrak f(i\sqrt n)$. Small.

The Definition spends its first clause equating the two. $\sqrt{-n}$ is
Weber's own notation, so it has a claim to the title. But the page should use
one notation, and the column header, the parameter values and the Formulas
all use $i\sqrt n$.

**Fix:** either retitle "Ramanujan's class invariants $G_n$, with Weber's
$\mathfrak f(i\sqrt n)$", or keep the title and let the Definition say
"Weber's function at $i\sqrt n$, written $\mathfrak f(\sqrt{-n})$ by Weber".
The second option replaces the current clause rather than adding one.

### 7. Formula (3) uses $G_{1/n}$, which the page never defines. Small.

It renders: "The reciprocal-index identity is $G_{1/n}=G_n$." $G$ is
defined only at positive integers, so $G_{1/n}$ has no meaning on this page.
The generator evaluates the product at $x=1/n$ (`generate.py`, line 154),
which is right but not written down. "The reciprocal-index identity is"
announces a name the page does not otherwise use.

**Fix:** "$G_{1/x}=G_x$ for every real $x>0$, where $G_x$ is defined by the
same product."
