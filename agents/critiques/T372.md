# T372 critique: Secondary polynomials of the Hermite polynomials in probabilist's convention $q_n$

Read 2026-09-20. T372 is a private draft: `/T372` answers 404 with and without
`Authorization: Bearer <key>`, because the table view reads a session and not a
key. The SOCKS proxy on 127.0.0.1:1080 served `/skill` once and then refused
every connection (`curl: (7)`); `curl https://numberdb.org/...` direct answers,
so every fetch below went direct.

I read the document through `GET /api/table?id=T372` with the key (18,638
bytes) and rendered it through `GET /preview?table=<json>` in eight pieces —
YAML is a superset of JSON, so the API document goes straight back. Every piece
answered 200. A piece must carry a `Numbers` key or the view answers 200 with
"Error while parsing numbers: cannot access local variable 'number\_section'"
and renders nothing; that is written up in `docs/agent-environment.md`. The
`RequestFactory` path for a draft's real page is closed here: the image
`agents/sage.sh` runs has no Django. `GET /api/table/T372/audit` returns
`"clean": true`, and I agree with it — see the last section for the two checks
that could not fire and the one that was switched off.

The table holds 51 entries, $n = 0$ to $50$, in numeric order; type `Z[]`,
rigour `exact`; entries block 13,938 characters, largest entry 764. Every limit
is far away and the largest entry is still something a person reads. The
definition is 278 characters, under the audit's 320.

## What I checked hardest, and found right

* **Three of the page's own claims reproduce every stored value.** The
  recurrence in `formula-recurrence` gives all 51 entries. So does
  `formula-moments`, run against T104's stored $He_n$ with $m_{2r}=(2r-1)!!$ —
  a route that shares nothing with the recurrence. And every entry equals
  $2^{-(n+1)/2}q^{H}_n(x/\sqrt2)$, where $q^H_n$ is T371's physicist-convention
  entry: 51 of 51, exactly, in `Fraction` arithmetic. That last one also says
  the two tables are consistent with each other, which is the fact finding 2 is
  about. I did not re-verify the values themselves against the integral; the
  build and `verify` do that.

* **`complete-note`'s factual claim.** T104, *Hermite polynomials in
  probabilist's convention*, holds exactly $n=0$ to $50$. The range this table
  gives as its reason is the range that table has.

* **The TeX typesets.** All 50 `$…$` fragments in the prose, converted with
  MathJax 3 under node: 0 errors, with a control (`\frac{1}{`) the same run
  flagged as "Missing close brace". Every field has an even number of `$`. The
  one `<` in the document is in the Sage snippet and reaches the page as
  `&lt;`, so nothing is eaten. `\dfrac{1}{z-}\dfrac{1}{z-}\dfrac{2}{z-}\cdots`
  in `formula-continued-fraction` is ugly and is the standard notation, and it
  renders.

* **The links resolve and the citations number.** All three `Similar tables`
  slugs answer 200, and the `HREF` in `comment-hermite` renders as
  `<a href="Hermite_polynomials_He">`, which is right from a page at the root.
  `Wiki`, `DLMF-defs`, `DLMF-cf` and `DLMF-associated` render `[1]`–`[4]` and
  each is pointed at from the prose. `https://dlmf.nist.gov/18.2#x` is a real
  anchor on a real page, and §18.2(x) is indeed "Orthogonal Polynomials and
  Continued Fractions", which is what the link's title says.

* **The `orthogonal polynomials` tag is earned, which is not obvious.** $q_0=0$
  is not a member of any orthogonal family, and the sequence as indexed here is
  not monic-indexed-from-zero. What is true is that $p_n = q_{n+1}$ satisfies
  $p_{n+1}=xp_n-(n+1)p_{n-1}$ with every $b_n>0$, so Favard applies to the
  shifted sequence — and `comment-names` says exactly that reindexing. All
  three tags exist in the corpus.

* **It is one table.** One parameter, an index and not a name; one quantity;
  the value column heads `$q_n(x)$`, a symbol true of every row, not the
  fallback `value`; no `param-latex`. The parameter describes the family
  ($n\geq0$) and the run is in `complete-note`, which is the fault that recurs
  most in this corpus and is not on this page.

* **The format is searchable.** `api/lookup?text=8*x^2 - 8` answers with T371,
  so entries of this shape are found by their digits. `x^2-2` today answers
  with T217's Hecke polynomial alone; after review it will answer with both,
  which is the database working.

## Findings

### 1. The Sage program is stored as one line with literal `\n`, and does not run

What a reader sees under `Programs`, in the `<pre><code>` block, all on one
line:

    R.<x> = ZZ[]\nq = [R(0), R(1)]\nfor n in range(1, 50):\n    q.append(x*q[n] - n*q[n-1])\nq[8]

The stored string contains no newline at all: it holds backslash-`n` as two
characters, where the sibling T371's `code` field holds real ones. Nothing in
the pipeline catches this — the audit reads the code only for a stale range
pattern, `verify` does not run it at all, and the escaping is invisible in the
JSON the API returns unless you look at the `repr`.

Fed to Sage's own preparser exactly as stored, and then again with the
backslashes turned into newlines (`agents/sage.sh /tmp/prog372.py`):

    as stored on the page: FAILED -> SyntaxError: invalid syntax (<page>, line 1)
    with real newlines:    OK -> x^7 - 27*x^5 + 185*x^3 - 279*x

So the code is right — that is the stored entry for $n=8$ — and only its
storage is broken. `Programs` is the one section whose whole purpose is to be
copied, and this is the only section on the page that a reader cannot use.

Smallest fix: rewrite `Programs[program-sage].code` with real newlines. While
it is being rewritten, end it on a value the table does not hold, which is what
`scripts/one-off/fix-polynomial-programs.py` did to T108 and T109 for this same
reason: `q[8]` asks a reader to build all 51 polynomials in order to read back
one that is already printed in the values table at the top of the page.

    R.<x> = ZZ[]
    q = [R(0), R(1)]
    for n in range(1, 51):
        q.append(x*q[n] - n*q[n-1])

    q[51]        # the next one after this table

**Worth doing.** This is the one finding that stops a reader outright.

### 2. Nothing on the page points at T371, the same table in the other convention

T371, *Secondary polynomials of the Hermite polynomials in physicist's
convention $q_n$*, is public, is the same construction, shares all three tags,
cites the same Wikipedia article and the same DLMF section, and holds the same
range $0\leq n\leq50$. T372 does not name it, link it, or say it exists.
`Similar tables` reaches T104, T134 and T133 — the three next-nearest tables —
and skips the nearest one.

What a reader loses is concrete. Both tables call their entries $q_n$ and head
their value column `$q_n(x)$`, and the two hold different polynomials: $q_3$ is
`x^2 - 2` here and `8*x^2 - 8` there. Somebody who arrives holding one of them
has landed on the answer to a question they did not ask, and the page they are
on does not tell them the other reading exists.

The corpus holds the Hermite polynomials themselves twice on purpose, and it
has already decided how to say so: T103 and T104 carry no `Similar tables` at
all, and each names the other in a comment that gives the conversion —
T104's `comment-standardization` is "$He_n$ relates to the
`HREF{Hermite_polynomials_H}[Hermite polynomials in physicist's convention]`
$H_n$ via $He_n(x) = 2^{-n/2} H_n(x/\sqrt{2})$". The secondary polynomials
obey the same identity with one more half power of two, so the parallel
comment writes itself:

    comment-standardization: $q_n$ relates to the secondary polynomials of the
      HREF{Secondary_polynomials_of_the_Hermite_polynomials_in_physicist's_convention}[Hermite
      polynomials in physicist's convention] $q^{H}_n$ via
      $q_n(x) = 2^{-(n+1)/2} q^{H}_n(x/\sqrt{2})$.

A `Similar tables` row would also do, and says less. That slug answers 200 with
the apostrophe in it. I checked the identity on all 51 entries of both tables;
it is exact.

**Worth doing.** For whoever publishes this: the reciprocal mention cannot be
added to T371 until T372 is public, because an `HREF` at a draft answers 404
and the audit reports it. It is worth adding then.

### 3. The relation given for the quadrature table is not true of that table

`Similar tables` says of T134:

> the standard-normal quadrature weights are $q_n(y_k)/He_n'(y_k)$ at the roots
> $y_k$ of $He_n$

T134 holds neither of those things. Its definition is the physicists' rule,
$\int f(x)e^{-x^2}\,\mathrm{d}x\approx\sum w_kf(x_k)$, and its entries are the
roots of $H_n$ and the weights for $e^{-x^2}$: at $n=2$ it stores
$x_k=\pm0.70710678\ldots$ and $w_k=0.88622692\ldots$, where this sentence's
$y_k$ are $\pm1$ and its weights are $1/2$. The mathematics of the sentence is
right, but the relation is what `Similar tables` exists to carry, and a reader
who follows the link to compare numbers finds two columns that match nothing in
the sentence. T371's row for the same table does state the conversion: "the
weights divided by $\sqrt{\pi}$ are $q_n(x_k)/H_n'(x_k)$ at the nodes".

Smallest fix: say the conversion, e.g. "the same rule in probabilists' form:
its nodes are $y_k=\sqrt2\,x_k$ and $q_n(y_k)/He_n'(y_k)=w_k/\sqrt{\pi}$".

**Worth doing.** A link that mis-describes what is on the other end is worse
than no link.

### 4. `Links` carries the request issue, and nothing cites it

`Links` declares five entries. Four are cited from the prose and render `[1]`
to `[4]`. The fifth, `Request` — "Requested in numberdb-data#93" — is cited by
nothing, so it renders as a bare `[5]` at the end of a numbered list of
sources, which is the one form a reader reads as "this was used for
something".

The skill is explicit on both halves: a "table wanted" issue is answered in the
issue and "the table carries no trace of the request: it is encyclopedic, and
who asked for it is not a fact about the mathematics"; and "a reference is for
citing, not for listing". Issue 93 carries no derivation, convention or source
that a reader of the mathematics needs.

Smallest fix: delete `Links[Request]`. (T371 carries the same link under
`Request93`, also uncited — this is a habit of the batch rather than a slip in
one table, and worth fixing in both.)

**Worth doing**, and cheap.

### 5. `complete-note` is an appositive fragment, and names a table it does not link

It renders as

> Table is complete: no (every $n\leq 50$ is here, the range of the table of
> Hermite polynomials in probabilist's convention)

Two things. A reader cannot tell what "the range of the table of…" is in
apposition to — "$n\leq50$", or "here", or the whole clause — and has to work
out that it is offered as the *reason* for the bound rather than as a second
fact. And the table it names is T104, which this document links in
`comment-hermite` and in `Similar tables`, and does not link in the one place
where a reader is being told to go and look at it.

T371's is the model, and it is the same sentence done both ways:
"it holds every $n\leq50$, matching the range of
`HREF{Hermite_polynomials_H}[the physicists' Hermite polynomial table]`".

Smallest fix: "it holds every $n\leq50$, matching the range of
`HREF{Hermite_polynomials_He}[the probabilists' Hermite polynomial table]`".

**Worth doing.**

### 6. The fold hides the sentence that says the checks were run, and $n=0$ has no degree

`rigour details` is 404 characters and the site folds a note above 400
(`numberdb_app/prose.py`, `FOLD_ABOVE`), so it folds by four characters: the
last sentence that fits shows and the rest goes behind "more". What shows is:

> Every value is exact, a polynomial with integer coefficients, so there is no
> precision to choose. Each entry is built by the recurrence and, before it is
> written, must equal the defining integral evaluated exactly from the standard
> normal moments. It must also have degree $n-1$, the parity of $n-1$, and
> leading coefficient $1$ for $n\geq 1$.

and what is behind "more" is the single sentence "The generator checks these
conditions over the listed range." So the visible part reads as a specification
— two sentences of "must" — and the part that says anybody checked is the part
a reader has to click for, over a margin of four characters. T371 folds too,
and above its fold it says what the generator *did*; the checking is hidden
there as well, but the first paragraph is not left sounding like a wish.

Two smaller things in the same sentence. "for $n\geq 1$" is doing work for the
whole list and is attached to the last item, so a reader must guess its scope;
and the degree claim is false at $n=0$, where $q_0=0$ has no degree at all.
`comment-hermite` makes the same claim ("an integral polynomial of degree
$n-1$") and needs the same guard. "the parity of $n-1$" is also loose: the
polynomial does not have a parity, it is an even or odd *function* according to
the parity of $n-1$.

Smallest fix: lead with what was done and guard the range — "Every value is
exact… so there is no precision to choose. Each entry was built from the
recurrence and checked, before it was written, against the defining integral
evaluated exactly from the standard normal moments. For $n\geq1$ it was also
checked that $q_n$ has degree $n-1$, is an even or odd function according to
the parity of $n-1$, and is monic."

**Worth doing**, mostly for the $n=0$ claim.

### 7. `comment-density` opens on a citation number and says "fixes none"

It renders as

> (2) [1] defines the secondary polynomials for a density and fixes none. This
> table uses the probability density…

A comment beginning with a bracketed numeral reads as a list marker before it
reads as a source, and "fixes none" has nothing to bind to — no plural has been
mentioned, so a reader guesses "none of the densities" and moves on without
being sure. The sentence is doing an important job, which is to say that the
convention this table chose was not forced on it.

Smallest fix: "Wikipedia CITE{Wiki} defines the secondary polynomials against an
arbitrary density and does not choose one."

**Worth doing if the page is being edited anyway**; it is one sentence.

## Noted only

* **The parameter has no `title`**, so the list reads "$n$ — integer ($n\geq
  0$)" where T371's reads "$n$ — degree". Do not copy the sibling: $\deg q_n =
  n-1$, so "degree" is wrong on both pages, and T372's silence is the safer of
  the two. If a word is wanted, "index" or "order" is true.

* **The definition's closing clause, "using the standard normal probability
  density", names a density the same sentence has already displayed.** I had
  this down as a redundancy until I read the other two: T133 ends "the integral
  taken against the density $1$ on $[-1,1]$" and T371 ends "where
  $\rho(t)=e^{-t^2}/\sqrt{\pi}$ is the probability density proportional to the
  Hermite weight". Naming the density in words is the house pattern for this
  family, and it is what makes the three definitions comparable. Leave it.

## The audit, and what it could not see

`GET /api/table/T372/audit` reports `{"findings": [], "clean": true}`, and
every finding above is outside what it reads. Three are worth naming:

* **The unlinked-family check is switched off for this table's own family.**
  `_prose_faults` skips any corpus title that is a substring of this table's
  title, or contains it; "Hermite polynomials in probabilist's convention" is a
  substring of "Secondary polynomials of the Hermite polynomials in
  probabilist's convention", so the check can never fire on it — which is why
  finding 5 survives a clean audit. The guard is there so that a table is not
  told to link itself, and it takes the one family the table is *about* with
  it.

* **It cannot ask for a link to a table that is never named.** Finding 2 is a
  missing relation, not a missing link, and no deterministic check reaches it.

* **The `Programs` range check looks for `range(0, N)` or `[0..N]`.** This
  snippet says `range(1, 50)`, so nothing matched; the range happens to be
  right. Nothing anywhere reads the code as code, which is how finding 1 got
  this far.

There is one place where I wanted a finding and the audit is against me, and it
is worth recording because the skill and the audit disagree there. The skill
says to link the first mention of a family the corpus holds, "first mention,
once per section" — and the Definition's first words are "let $He_n$ be the
Hermite polynomial in probabilist's convention", unlinked. But `audit_table`
reports any `HREF{` in a definition: "Definition links to another table; a
cross-reference belongs in Similar tables or a comment". The corpus follows the
audit — T371 and T133 both leave it plain and link it in a comment — so this
table is right as it stands, and finding 5 asks for the link in `complete-note`,
where nothing forbids it. That conflict is in this run's lesson proposals.

I did not run `--links`, which needs the command and a database; I fetched the
five external URLs by hand instead and all five answer 200.
