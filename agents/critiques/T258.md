# T258 critique: Orders of finite groups of Lie type as polynomials in $q$

Read 2026-09-16. T258 is a private draft — `/T258` answers 404 anonymously and
with the owner's bearer token, and `/preview/T258` refuses a draft the same way
— so it was read through `GET /api/table?id=T258` and rendered in nineteen
`/preview?table=` pieces. It holds 90 entries, one integer polynomial $P(q)$
for each of sixteen families of finite groups of Lie type, under two parameters
`family` (the type name) and `n` (the rank); type `Z[]`, rigour `exact`,
`complete: no` with a note giving the ranges. `GET /api/table/T258/audit`
reports `{"findings": [], "clean": true}`. I agree with everything it says, and
one thing it does not look for is finding 3 below.

**This is a careful table and it reads well.** The three things I checked
hardest all held.

*It is one table and not two.* `family` has sixteen values and they are names,
which is the structural tell the skill asks about — but it names *what the
number is of*, one order polynomial for each of sixteen families, which is the
good kind, and the value column is headed `$P(q)$`, a symbol true of all
ninety rows, not the word `value` a table of two quantities falls back on.

*The rendering is clean.* No "Math input error", no eaten `<`, no
`argument ()`, no dangling `CITE{}` or `HREF{}`. Two things that looked like
rendering faults were artifacts of my own chunking and are not faults:
`sources: [CITE{Hiss}, CITE{WikiSimple}]` renders as "Sources of data: [1],
[2]" with links, and `CITE{formula-simple-quotients}` inside `rigour details`
renders as a link reading "(5)". The twisted types typeset: `${}^2A_n$`,
`${}^3D_4$` and the rest are well-formed.

*The claims about the checks are true.* "compares 180 specialisations with the
stored finite simple group orders" is exactly right — I counted the
intersection of the generator's `sample_qs` with what T220 actually holds and
got 180, not 179 or 181.

What is left is eleven things. Eight are worth doing, and the first is the one
a reader actually loses something to.

- **1 is the one that costs a reader what they came for**: the definition does
  not say which of the several groups of a given type this is the order of.
- **2 is a visible failure** — the `Programs` snippet does not run; I ran it
  and have the error.
- **3 and 4 are notation and reasons**: a symbol used eight times and never
  defined, and thirteen pairs of byte-identical rows explained as a convention
  where a theorem is the reason.
- **5 to 8 are worth doing while the file is open.**
- **9 is a judgement call** that cannot be made about T258 alone.
- **10 and 11 are noted only because I noticed them**, and both are house
  practice rather than slips.

---

## 1. The definition does not say which group

What a reader sees, as the whole Definition:

> For a Lie type and rank, this table stores the order polynomial $P(q)$ in the
> field-size parameter $q$ for the corresponding finite group of Lie type [1].

Two things are wrong with it, and the second is the expensive one.

It names the object by the table's own title. "the corresponding finite group
of Lie type" restates "finite groups of Lie type", so the sentence says what
the title says and stops.

And there is no such thing as *the* finite group of a given Lie type and rank.
For type $A_1$ over $\mathbb F_q$ there is $SL_2(q)$, there is $PGL_2(q)$, and
there is the simple $PSL_2(q)$; the first two have the same order and the third
does not. The stored $A_1$ row is `q^3 - q`, which is $|SL_2(q)|$ — the
universal (simply connected) group. Nothing in the Definition says so. A reader
who arrived holding `q^28 - q^26 - q^22 + q^18 + q^14 - q^12` learns from the
first screen that they have a ${}^2D_4$ order polynomial and does not learn
whether it counts the simple group or the one above it, which for
${}^2D_4$ differ by a factor of $\gcd(4, q^4+1)$.

The fact is on the page, in the second comment: "The companion table [Orders of
finite simple groups of Lie type] stores the simple central quotients. Where
that quotient has a central factor $d(q)$, its order is $P(q)/d(q)$ rather than
$P(q)$." That is a comment doing the definition's job, and a reader has to read
it backwards to learn what $P(q)$ itself is.

Smallest fix — one sentence, no new section:

> For a Lie type and rank, this table stores the order $P(q)$, as a polynomial
> in the field size $q$, of the universal (simply connected) finite group of
> Lie type of that type over $\mathbb F_q$.

The `central-quotients` comment then reads as the caveat it is.

## 2. The `Programs` snippet fails on its first line

What a reader sees, as (P1), labelled `Sage`:

    from sage.rings.integer_ring import ZZ
    from sage.rings.polynomial.polynomial_ring_constructor import PolynomialRing

    R = PolynomialRing(ZZ, "q")
    q = R.gen()
    n = 3
    polynomial = q ** (n * (n + 1) // 2)
    for i in range(2, n + 2):
        polynomial *= q ** i - 1
    polynomial

Saved verbatim to a file and run under SageMath 10.9, both ways a reader would
run a Sage program:

    $ sage -python p1.py
    $ sage p1.py

each fails identically, on line 1:

    AttributeError: partially initialized module 'sage.rings.integer_ring'
    has no attribute 'ZZ' (most likely due to a circular import)

Replacing the two imports with `from sage.all import ZZ, PolynomialRing` runs
under both and returns
`q^15 - q^13 - q^12 - q^11 + q^10 + q^9 + q^8 - q^6`, which is the stored $A_3$
row. So the arithmetic is right and the imports are wrong for the environment
the `language` field names. (This is the third table this batch with the same
shape; the general lesson is already proposed in
`agents/lessons/proposals/20260916T024304Z-critique.md` and I have added a
measurement to it.)

Two smaller things in the same block. The snippet computes one family of the
sixteen — a reader who wants one more $E_8$ or ${}^2F_4$ value gets nothing
from it, though `Formulas` has every case. And it carries no comment, so
nothing says that `n = 3` reproduces the $A_3$ row rather than being an
arbitrary number.

Smallest fix: the `sage.all` import line, and `# the A_3 row` beside `n = 3`.

## 3. $(a,b)$ is used eight times for $\gcd(a,b)$ and never defined

What a reader sees, in formula (5):

> The finite simple group order in [the companion table] is $P(q)/d(q)$, where
> $d(q)=(n+1,q-1)$ for $A_n$, $d(q)=(n+1,q+1)$ for ${}^2A_n$, $d(q)=(2,q-1)$
> for $B_n$ and $C_n$, $d(q)=(4,q^n-1)$ for $D_n$, $d(q)=(4,q^n+1)$ for
> ${}^2D_n$, $d(q)=(3,q-1)$ for $E_6$, $d(q)=(3,q+1)$ for ${}^2E_6$, and
> $d(q)=(2,q-1)$ for $E_7$.

Eight $(a,b)$ and nothing on the page says the parenthesis is a gcd. The skill
is explicit about this — "If a symbol appears in a formula or a comment, its
definition belongs in the same table" — and the companion table already carries
the sentence, in its own `comment-notation`: "In the formulas, $(a,b)$ denotes
$\gcd(a,b)$."

The audit does not look for undefined notation, so its clean verdict is right
in form and silent here.

Two words in the same neighbourhood are loose. $d(q)$ is called a "central
factor" in the `central-quotients` comment, attributed to the quotient — it is
the order of the centre of the *universal* group, which is what gets quotiented
out. And the notation $d(q)$ reads as a polynomial in $q$, which it is not; it
is a gcd taking a handful of small integer values.

Smallest fix: open `formula-simple-quotients` with "Here $(a,b)$ denotes
$\gcd(a,b)$, and $d(q)$ is the order of the centre of the universal group."

## 4. Thirteen pairs of identical rows, explained as a convention where a theorem is the reason

What a reader sees: the $C_n$ row and the $B_n$ row, for each $n$ from 3 to 15,
are the same string of up to 1100 characters. Thirteen pairs. That looks like a
duplicate until they find the third comment:

> The $B_n$ and $C_n$ rows have the same polynomial for each listed rank. The
> $C_2$ row is not repeated, following the convention used for the finite
> simple groups of Lie type.

Three problems, all in two sentences.

The first sentence says the rows agree and not *why*. The fact worth telling a
reader is that for odd $q$ and $n\geq3$ the groups are genuinely different and
their orders are equal anyway — T220 says this, with a citation to Garge, in
its `comment-equal-orders`. Without it, a reader cannot tell whether they are
looking at a coincidence or at one family entered twice.

The second sentence points at a convention instead of naming a reason. "the
convention used for the finite simple groups of Lie type" makes a reader open
the companion table to find out what convention. The reason is that
$C_2\cong B_2$, and the companion states it in one clause.

And it explains one omission of the two. The `n` parameter says $n\geq4$ for
$D_n$, which quietly drops $D_3$ for exactly the same reason ($D_3\cong A_3$) —
and nothing on the page says so, while the $C_2$ case gets a sentence.

Smallest fix, replacing the comment:

> For $n\geq3$ the groups of types $B_n$ and $C_n$ are not isomorphic when $q$
> is odd, but they have the same order, so those rows carry the same
> polynomial. The types $C_2$ and $D_3$ are not listed separately, being the
> same families as $B_2$ and $A_3$.

## 5. Three keywords name the companion table's subject, not this one

`Keywords` holds `PSL`, `PSU`, `PSp`. Those three words appear nowhere on the
page, and the orders of $\mathrm{PSL}$, $\mathrm{PSU}$ and $\mathrm{PSp}$ are
precisely what this table does *not* store — they are $P(q)/d(q)$, and they are
T220's. What T258 holds is $|SL|$, $|SU|$, $|Sp|$, $|\mathrm{Spin}|$.

Keywords are not printed on the page, so this is invisible to a reader looking
at T258; it is visible to the reader who types "PSL" into the search box, since
`Keywords` goes into `weight_A_text`, the same weight as the title
(`numberdb_app/editing.py:662`). That reader gets two tables, one of which does
not hold what they are holding — and the skill's own reason applies: every hit
in the corpus is worth a little less for it.

The list also doubles: "Chevalley group order" and "Chevalley group",
"Steinberg group order" and "Steinberg group", where "Suzuki group order" and
"Ree group order" have no bare partner. Four keywords do the work of two, and
inconsistently.

Smallest fix: `PSL, PSU, PSp` → `SL, SU, Sp, Spin`, and drop one of each
doubled pair.

## 6. $q$ is never said to be a prime power

What a reader sees, as comment (1):

> The polynomial variable is $q$. For the Suzuki and Ree families, group orders
> are obtained only at $q=2^{2m+1}$ for ${}^2B_2$ and ${}^2F_4$, and at
> $q=3^{2m+1}$ for ${}^2G_2$.

The comment restricts $q$ for three of the sixteen families and never says what
$q$ ranges over for the other thirteen. A reader can guess "field-size
parameter" means a prime power, but the table never asserts it, and $m$ is
never said to be a non-negative integer. The companion states both, in its `q`
parameter.

The fact is on this page, in the one place nobody reads for it: the `Similar
tables` relation ends "at prime-power values of $q$".

Smallest fix: begin the comment "Here $q$ is a prime power", and end it "with
$m\geq0$".

## 7. Hiss is a paper in `Links`, and as a source it carries five of the sixteen formulas

`Links` holds the Hiss survey as a URL to a PDF on a personal homepage; there
is no `References` section. The skill's section table puts "sources outside:
Wikipedia, LMFDB, OEIS, MathWorld" in `Links` and "papers and books ... `bib`,
and the identifiers beside it" in `References`. Hiss, *Finite groups of Lie
type and their representations*, is a survey published in Groups St Andrews
2009 in Bath (LMS Lecture Note Series 387, pp. 1–40) — a paper, at the address
in this pair most likely to rot. The companion table gets this right: Garge is
a `References` entry with `bib` and `arxiv`.

I read the PDF to see what it supports as a *source of data*. It is an
excellent citation for the Definition — §1.1.2 and §1.1.3 define finite groups
of Lie type and name every family this table holds. As a source of the order
formulas it is thin: Example 1.3, on page 3, gives five, namely
$|GL_n(q)|$, $|GU_n(q)|$, $|SO_{2m+1}(q)|$, $|F_4(q)|$ and $|{}^2F_4(q)|$, and
then asks "Is there a systematic way to derive these formulae?" The last three
match this table's $B_m$, $F_4$ and ${}^2F_4$ exactly; the first two are the
$GL$ and $GU$ orders, not the $SL$ and $SU$ orders stored here. The remaining
eleven families are carried by the Wikipedia link alone.

The canonical source for exactly this table is reference [72] of that very
survey: Solomon, *The orders of the finite Chevalley groups*, J. Algebra 3
(1966), 376–393.

Smallest fix: move Hiss into a `References` section with a `bib` line, and add
Solomon beside it.

## 8. Nothing points at T257, whose polynomials these are built out of

T257 (a draft in the same batch) holds $W(t)$, the Poincaré polynomials of the
finite Coxeter groups. For every untwisted type the two tables share,

$$P(q) = q^{N}\,(q-1)^{\ell}\,W(q),$$

with $N$ the number of positive roots and $\ell$ the rank. I checked this
against the stored values of both drafts on all 28 rows they have in common —
$A_1$ to $A_9$, $B_2$ to $B_9$, $D_4$ to $D_9$, $E_6$, $E_7$, $E_8$, $F_4$,
$G_2$ — and all 28 agree.

That is a relation worth more to a reader arriving from the Coxeter side than
the four separate links to T220, and `Similar tables` is where the corpus says
this sort of thing. One line stating the identity.

The caveat is that both tables are drafts, so the link dangles until T257 is
published, and the slug has to be read off T257 rather than guessed from its
title.

## 9. "rank" is not the rank for the twisted families

The `n` parameter is titled **rank**, and its constraint patches the fixed-rank
cases — "the fixed-rank families use the displayed subscript as $n$" — but not
the two twisted families with a running index. For ${}^2A_n$ the group's own
rank is $\lfloor (n+1)/2\rfloor$ and for ${}^2D_n$ it is $n-1$; the stored $n$
is the rank of the underlying root system in both. The rendered rows say this
out loud on the fixed-rank side too: `${}^2B_2$ | 2:`, where the Suzuki group
has rank 1.

Smallest fix: title the parameter "rank of the underlying root system", or add
half a sentence to its constraint.

I am ranking this below the rest because it cannot be decided about T258 alone.
T220's `n` parameter is word for word the same, deliberately; changing one of
the pair and not the other is worse than either.

## 10. The $n$ column repeats the family label on ten rows — noted only

Rendered, the fixed-rank rows read

    $E_7$      7:    q^133 - q^131 - ...
    $G_2$      2:    q^14 - q^12 - q^8 + q^6
    ${}^2F_4$  4:    q^26 - q^25 + ...

and the `$n$` column says nothing the label to its left has not already said —
which is the noise the skill names, "a label that repeats what the block
heading above it already says". Ten of ninety rows.

I am not recommending a change. The alternative is leaving `n` empty on those
rows, which breaks the parameter; T220 renders identically and is published;
and the repetition is at least consistent. Noting it so that the next person
who spots it does not have to re-derive that it was considered.

## 11. The completeness note says what and not why — noted only

> Table is complete: no (it holds $A_n$ for $1\leq n\leq15$, $B_n$ and
> ${}^2A_n$ for $2\leq n\leq15$, ... and all fixed-rank exceptional, Suzuki and
> Ree families listed in the family parameter)

The skill asks the completeness note to carry the argument for the range, not
just its description. The range here is well chosen — the largest entries,
$D_{15}$ and ${}^2D_{15}$ at 1133 characters and 128 terms, land just under the
point where the skill's own measurement says an entry stops being something
anybody reads ($F_{100}$ at 1107 characters, fine; $F_{150}$ at 2248, not) —
but the note does not say that, so the next person extending the table has no
reason on the page to stop at 15 either.

T220's note has the same shape, so this is house practice rather than a slip,
and it would be a clause: "…, a bound set by entry size: $D_{15}$ is 1133
characters".

## How it was read

* Document: `GET /api/table?id=T258` with the zeta3 key. 90 entries across 16
  families, 30 827 characters of polynomial in all; largest entry 1133
  characters ($D_{15}$ and ${}^2D_{15}$), smallest 7 (`q^3 - q`, $A_1$).
* Audit: `GET /api/table/T258/audit` → `{"findings": [], "clean": true}`.
  `manage.py audit_table --links` could not be run: this campaign runs on the
  AWS builder, which has no Django, no database and no `numberdb/web` image
  (`docker: pull access denied for numberdb/web`) — both already recorded in
  `docs/agent-environment.md`. I checked the two external URLs by hand instead:
  the Hiss PDF answers 200 with 337 KB of `application/pdf`, and the Wikipedia
  article answers 200.
* Rendering: nineteen `/preview?table=` requests, each a subset of the document
  under the 4094-byte request line limit, plus one carrying both parameters,
  `Display properties` and thirteen short entries to see the numbers block laid
  out. Header row reads `family | $n$ | $P(q)$`; the section is titled
  "Polynomials", from `type: Z[]`.
* The `Programs` snippet: run verbatim under SageMath 10.9 through
  `agents/sage.sh`, as `sage -python p1.py` and as `sage p1.py`; both fail on
  line 1. `from sage.all import ZZ, PolynomialRing` in place of the two stored
  imports returns the stored $A_3$ row.
* The "180 specialisations" claim: recomputed from the generator's `sample_qs`
  against T220's stored rows. 180, distributed
  `A` 49, `2A` 32, `C` 24, `B` 23, `D` 17, `2D` 17, and one or two each for the
  fixed-rank families.
* The T257 identity: `P(q) == q^N (q-1)^rank * W(q)` on the 28 rows the two
  drafts share, checked with integer polynomial arithmetic on the stored
  strings of both. 28 agree, 0 disagree.
* The Hiss survey: 40 pages, read for order formulas. Example 1.3 on page 3 is
  the only place they appear, and it gives five.
