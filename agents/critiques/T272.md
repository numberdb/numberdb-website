## What I checked hardest, and found right

* *It is one table, and the columns say so.* One integer parameter $k$, which
  is an argument and not a name. The parameter reads "$k$ — number of variables
  in each equation ($k\geq3$)". That describes the family, not the run, and the
  range is left to `complete-note`. The value column is headed $\alpha_k$, not
  `value`, and each row is labelled by its bare $k$.
* *The formulas say what they claim.* In Sage's mpmath at 60 digits, for every
  $k$ from 3 to 12, I solved `formula-root` and evaluated `formula-threshold`,
  which gives the stored value to within $3\cdot10^{-61}$. I took the largest
  root $q$ of $q=1-e^{-k\alpha q^{k-1}}$ at the stored $\alpha_k$, and
  `formula-core`'s equation $\alpha q^k=1-e^{-x}-xe^{-x}$ holds there to
  $3\cdot10^{-61}$. The program under `Programs`, run as printed, prints
  `0.91793527665808601351544122823302412955664628137867`, which agrees with
  the $k=3$ row. Each $\xi_k$ in the entry comments is the root correctly
  rounded to 12 significant digits. Each ten-digit value credited to
  Dietzfelbinger et al. is the stored value correctly rounded.
* *A reader who arrives with 0.9179352767 is served.* It is best known as the
  threshold for 3-ary cuckoo hashing. The title says XORSAT, `Keywords` carries
  "cuckoo hashing", and the first comment says that cuckoo hashing gives the
  same number.

## Findings, most worth doing first

### 1. Five entry comments repeat a check against the literature (worth doing)

Rows 3 to 7 read:

> The root is $\xi_{3}=2.14912579991$; Dietzfelbinger, Goerdt, Mitzenmacher,
> Montanari, Pagh and Rink tabulate this threshold as $0.9179352767$ to ten
> decimal places [2].

The second half is the row's own value rounded to ten places, with six
surnames in front of it, repeated down five rows. It tells a reader nothing
the row does not. It is a record of what the build compared, and that record
is already in `rigour details` ("the values for $3\leq k\leq7$ were compared
with the ten-digit table of Dietzfelbinger, ..."). Reference [2] is already
listed under `sources`. The skill says an entry comment is worth having "when
it says something the row cannot", and worth leaving out when it repeats what
the document already says.

**Fix:** cut each of the five comments down to its first clause, so every row
reads the same way: "The root is $\xi_{k}=\dots$."

That leaves the $\xi_k$ clause. It is a second number sitting in a comment,
the pattern the skill warns about, but nobody arrives holding $\xi_3$. It is
the intermediate value that `formula-root` defines, and it saves a reader
checking a row one root-finding step. I would keep it. If it stays, write it
as "$\xi_3=2.14912579991$, the root in CITE{formula-root}" so that it names
its formula instead of relying on "The root".

### 2. The definition says "sharp satisfiability transition" but not what that means, and comment (2) relies on it (worth doing)

> The threshold $\alpha_k$ is its sharp satisfiability transition in the
> density $\alpha$.

Comment (2) then says that for $k=2$ "no positive density has the almost-sure
satisfiability required in this definition". The definition requires nothing
of the kind in words. It uses a term and leaves the reader to know what the
term means, so a reader reaches comment (2) and has to go back and guess what
"required" referred to. The first sentence also attaches "For $k\geq3$" to
random $k$-XORSAT itself. Random 2-XORSAT exists; what fails at $k=2$ is the
threshold.

**Fix:** "Random $k$-XORSAT CITE{WikiXORSAT} is a system of
$m=\lfloor\alpha n\rfloor$ equations over $\mathbb{F}_2$ in $n$ Boolean
variables, each using $k$ distinct variables and a uniform right-hand side.
For $k\geq3$ its threshold $\alpha_k$ is the density such that, as
$n\to\infty$, the system is satisfiable with probability tending to $1$ when
$\alpha<\alpha_k$ and to $0$ when $\alpha>\alpha_k$ CITE{PittelSorkin}."
Comment (2) can then say "so no density has the property that defines
$\alpha_k$", which points at a sentence that is actually there.

### 3. The cuckoo-hashing sentence says "one key per bucket" and "keys per bucket" in one clause (worth doing)

> ... and cuckoo hashing with one key per bucket quotes the same number as the
> load, keys per bucket [2].

This is the sentence the cuckoo-hashing reader came for, and it reads as
though the load were one. The first "per bucket" is a capacity and the second
is a ratio. The sentence also never says that $k$ is the number of hash
functions, which is how that reader knows $k$. The Wikipedia article on cuckoo
hashing is declared under `Links` and cited nowhere, and this is its first
mention.

**Fix:** "In cuckoo hashing CITE{WikiCuckoo} with $k$ hash functions and
buckets that hold one key each, $\alpha_k$ is the threshold for the load, the
number of keys per bucket CITE{DGMMPR}."

### 4. "$k$-core" in a table whose $k$ is the length of an equation (small, worth doing in the comment)

Comment (3) talks about the $2$-core of the constraint hypergraph and then
links "HREF{...}[$k$-core thresholds of the Erdős-Rényi random graph]". On
this page $k$ already means the number of variables in an equation, and the
previous sentence was about a core. A reader naturally takes "$k$-core" to
mean a core of order $k$ of this hypergraph, and that is a different object.
The batch conventions in issue #148 already use $r$ for the order of a core
and keep $k$ for the size of a constraint.

**Fix:** in the comment, caption the link without the letter:
"HREF{k-core_thresholds_of_the_Erdős_Rényi_random_graph}[the core thresholds
of the Erdős-Rényi random graph]". In `Similar tables` the caption is T156's
own title and should stay. The relation beside it ("thresholds for graph
cores, using the same Poisson-tail machinery in the graph case") says "graph"
twice and describes a method rather than a relation. "The same Poisson-tail
calculation for the cores of a random graph; here it is applied to the
$2$-core of a random $k$-uniform hypergraph" says what the two tables share.

### 5. Noted only because I noticed

* Comment (2) switches from density to "below average degree $1$", after
  comment (1) set density as the convention. "below density $\alpha=1/2$,
  average degree $1$" keeps the reader in the table's own units.
* `complete-note` states the range, $3\leq k\leq12$, but not why it stops at
  12. The skill asks for that sentence. The reason is the batch convention
  (T156's range, and the published table stops at $k=7$). From $k=8$ onwards
  the values all begin $0.999$, so a reason would help a reader wondering
  whether a larger $k$ would be here.
* Not for this table, but for whoever builds the next one in the batch: the
  planned "Cuckoo hashing thresholds" table will hold these same numbers at
  capacity one. That is two tables whose values agree because of a theorem,
  which is the case where both should answer. It should not use `repeats`.

Nothing else. The title, keywords, tags, parameter, formulas, program and
references read well, and the page renders.
