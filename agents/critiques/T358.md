# T358 — Sharp Gagliardo-Nirenberg constants of Del Pino and Dolbeault

Read 2026-09-20 as a draft: 145 entries, $3\leq n\leq20$, type `R`, rigour

The table is in good shape. It is one table by every test that matters — both
parameters are arguments rather than names, and the value column heads

## What I checked hardest, and what it said

**The `<` in `$1<a\leq n/(n-2)$`.** This string appears twice, in the
Definition and as the `a` parameter's `constraints`, and it is exactly the
shape that ate the rest of T130's parameter list. It survives. The rendered
parameter row is

    <div class="table-entry"> &mdash;&nbsp;&nbsp; interpolation exponent ($1&lt;a\leq n/(n-2)$)</div>

— escaped, nothing swallowed. `numberdb_app/test_angle_brackets.py` covers this
now; the draft confirms it on the live server.

**Every `$...$` fragment, typeset.** 43 distinct fragments pulled out of the
prose and the entry comments, run through MathJax 3 with `AllPackages`, looking
for `merror` in the output rather than for a thrown exception. Zero errors. The
control `\frac{1}{` *did* report "Missing close brace", so the check bites — an
earlier version of it passed the control too, which would have meant nothing.
No eaten backslash, no "Math input error".

**The completeness note against the data.** The note claims

> it holds every dimension $3\leq n\leq20$, every rational exponent $a$ in the
> open admissible range whose reduced denominator is at most $8$, and the
> Sobolev endpoint $a=n/(n-2)$ in each dimension

I rebuilt that set from the sentence alone and compared it with the stored
keys: they are equal, dimension by dimension, 145 entries, no extra row and no
gap. That is rarer than it should be, and it is worth saying so.

**The `Programs` snippet, run.** Pasted verbatim into Sage it produces

    [0.60829144672079527005486004617232813241845272540591165838642457280251875836805383955675325640113303021765... +/- 3.94e-148]

which is the stored `n=3, a=2` row to all 100 digits, with about 48 digits of
headroom. (See finding 6 for the one-word thing wrong with it.)

**The claims in `rigour details`.** All three are implemented in the attached
generator: `_extremal_ratio` evaluates the three norms on the extremal
$u=(1+|x|^2)^{-1/(a-1)}$, and the endpoint rows are multiplied against T354's
$s=1$ rows and T92's $p=2$ rows with a `contains_zero` test on the product
minus one. The field is not asserting something nothing does. As a spot check
of my own, $1/A_{3,3} = 2.34049227504201172777289925375844058327\ldots$, which
is T92's $(n,p,q)=(3,2,6)$ row to its last digit.

**The ragged range.** $n=3$ holds 44 rows and $n=20$ holds one. That shape is a
warning sign in the skill, where it means two tables sharing a title — here it
is the family: the admissible window is $(1,\,1+2/(n-2)]$ and closes as $n$
grows, so there is genuinely less to hold. Not a fault.

## Findings

### 1. The endpoint identity cannot be read without leaving the page — worth doing

A reader meets $A_{n,a}=1/S_{n,2}$ three times: Comments (2), Formulas (2), and
the comment on each of the 18 endpoint rows ("Sobolev endpoint: this value is
$1/S_{3,2}$."). Each time, $S_{n,2}$ is glossed only as

> where $S_{n,2}$ is the constant in [the Sobolev constant table]

Which direction that table normalises in is the one thing that differs between
sources for this constant. T92 stores $S_{n,p}\|u\|_{L^q}\leq\|\nabla u\|_{L^p}$,
so the reciprocal is right — but a reader who assumes the other, commoner
convention $\|u\|_{L^q}\leq C\|\nabla u\|_{L^p}$ reads the identity as simply
false, and has to click through and re-derive the direction to find out that it
is not. The link makes the check possible; it does not make the sentence true
on its own.

Smallest fix: in whichever of the two survives finding 2, write the inequality
out — "where $S_{n,2}$ is the largest constant with
$S_{n,2}\|u\|_{L^{2n/(n-2)}}\leq\|\nabla u\|_{L^2}$, as
HREF{T92}[the Sobolev constant table] stores it". One clause; the entry
comments can then keep pointing at it.

### 2. Comments (2) and Formulas (2) are the same sentence — worth doing

    Comments.endpoint:   At $a=n/(n-2)$, the inequality becomes the Sobolev
                         inequality and $A_{n,a}=1/S_{n,2}$, where $S_{n,2}$ is
                         the constant in HREF{T92}[the Sobolev constant table].

    Formulas.formula-endpoint:
                         At the Sobolev endpoint, $A_{n,n/(n-2)}=1/S_{n,2}$,
                         where $S_{n,2}$ is the constant in
                         HREF{T92}[the Sobolev constant table].

Rendered, a reader sees the same fact, in the same words, in two sections a
screen apart, with the same link under both. It reads as a table that has been
edited twice rather than written once.

Smallest fix: delete `formula-endpoint` and keep the comment, which is where
"what the values mean at a special point" belongs, and which also carries the
half the formula drops (that the inequality *becomes* Sobolev there). Nothing
cites `formula-endpoint` — `rigour details` cites `formula-constant` and
`formula-extremal`, by key — so removing it renumbers the displayed formulas
and breaks nothing.

### 3. Comment (3) points three times and names nothing — worth doing

> Some sources write this exponent as $p$ or write the left exponent as
> $2\sigma+2$. Here $a$ is the parameter in the displayed inequality.

Comments render as a numbered list, so (3) is read on its own, and on its own
it has no antecedent: "this exponent" — which one? The nearest preceding text
on the page is comment (2), about the Sobolev endpoint. "The left exponent" is
$2a$, the exponent of the norm on the left-hand side, but a reader has to
scroll back to the Definition and count to be sure, and "the displayed
inequality" is in a different section again.

Smallest fix, naming each one:

> Some sources write the exponent $a$ as $p$, and write the left-hand norm's
> exponent $2a$ as $2\sigma+2$. This table's $a$ is the $a$ of the definition.

### 4. The definition never says over what the constant is least — worth doing

> The number $A_{n,a}$ is the least constant in the Del Pino-Dolbeault
> Gagliardo-Nirenberg inequality [2] [1],
> $\|u\|_{L^{2a}(\mathbb{R}^n)}\leq A_{n,a}\|\nabla u\|_{L^2}^{\theta}\|u\|_{L^{a+1}}^{1-\theta}$.

There is no quantifier over $u$ and no function space. Nothing says the
inequality is asserted for *every* admissible $u$ rather than for some
particular one, which is the whole content of "least constant". The sibling
table built in the same batch gets this right and is the model:

> T354: it is the largest constant such that $S_{n,s}\|u\|_{L^{2n/(n-2s)}(\mathbb{R}^n)}\leq\|(-\Delta)^{s/2}u\|_{L^2(\mathbb{R}^n)}$ for $u\in\dot H^s(\mathbb{R}^n)$.

Smallest fix: "is the least constant such that [inequality] holds for every
$u$ in ...", naming the class the cited source takes. I am not asserting which
space that is — the source is CITE{DelPinoDolbeault2002} and whoever repairs
this should read it off the paper rather than off me — but the missing "for
every $u$" needs no source at all.

### 5. The completeness note says what the range is, not why — worth doing

The skill asks the note to carry the argument, and this one carries only the
rule. It matters more than usual here, because the rule looks arbitrary and
is not: of the 145 rows, only **8** have $2a$ an integer (the Lebesgue
exponents anybody names), and **108** have denominator 5 to 8. Read cold, that
is the pattern the skill calls counting rather than choosing.

The defence is real and is simply absent from the page: the admissible window
$(1,\,1+2/(n-2)]$ closes as $n$ grows, so past about $n=9$ the low-denominator
rationals have fallen out of range and a denominator bound of 4 would leave
**43** rows, most dimensions holding nothing but their own endpoint. Denominator
8 is what keeps the table non-trivial where the family is narrow.

Smallest fix: one clause on the end of the existing note, in the shape T354
uses — "a bound of 8 rather than 4 because the admissible window closes as $n$
grows, and below it most dimensions above $n=9$ would hold only their Sobolev
endpoint".

### 6. `Programs` ends with a bare `A` and prints nothing — worth doing

The last line of the snippet is `A`. That prints in the Sage REPL and prints
nothing under `sage -python`, which is how the file at the top of the
generator tells a reader to run Sage here. Both siblings end in `print(...)`
(T354 `print(reciprocal_square.rsqrt())`, T355 `print(C)`).

Smallest fix: `print(A)`. I ran the snippet with that one change and it gives
the stored value, so nothing else about it needs touching.

### 7. The definition's citations render backwards — noting only

    ... Gagliardo-Nirenberg inequality [2] [1], $\|u\|_{L^{2a}...

`CITE{WikiGN} CITE{DelPinoDolbeault2002}`, and the page numbers References
before Links, so the Wikipedia article is [2] and the paper is [1] and they
appear in that order. Harmless, slightly untidy. Fix: swap the two `CITE`s.

### 8. Two `Similar tables` relations do not state a relation — noting only

> T356 — another sharp constant table in this family of classical inequalities
> T357 — another upper-bound sharp constant table in this family of classical inequalities

Those sentences are true of most of the corpus, and the skill's point about
this section is that the relation is the valuable part — the T92 line ("the
endpoint $a=n/(n-2)$ is the reciprocal of the $p=2$ row") and the T355 line
both show what it looks like when it works. Fix: name something shared, or drop
the two rows; the tags already say these tables are about the same subject.

### 9. Not a fault: the rendered entry comments read `comment: ...`

Worth recording so the next reader does not file it. Each endpoint row renders

    <div class="number-extra-info">comment: Sobolev endpoint: this value is $1/S_{3,2}$. <br></div>

The `comment:` prefix is the site's own label for an entry's extra info, not
anything this table wrote.

## The audit, and why I disagree with both of its findings

    {"tid": "T358", "clean": false, "findings": [
      "Tags: \"functional analysis\" reaches only this table; a tag that leads nowhere else leads nowhere",
      "Tags: \"inequality\" reaches only this table; a tag that leads nowhere else leads nowhere"]}

**Overrule both.** This is the off-by-one already written up on 2026-09-20
after the T355 read: `Tag.table_count` counts published tables, so a draft is
missing from its own tags' counts, and the `reach <= 1` threshold is one too
high for every table at the moment it is audited. `/tags/inequality` and
`/tags/functional%20analysis` each list T92 today, which is published and
carries both. T354, T355, T356 and T357 are drafts in this same batch and carry
the same two tags, so on the day this batch is published both tags reach six
tables.

A repair run has already deleted a correct tag to silence this finding (T218).
Do not do it again here.

Nothing else was flagged, and that is right: the CITE and HREF targets all
resolve, and `HREF{T92}`, `HREF{T354}`, `HREF{T355}`, `HREF{T356}`,
`HREF{T357}` are all real. One thing the audit cannot see and somebody should
hold in mind at review time: T354 through T357 are drafts, so if T358 is
published ahead of them, four of its five `Similar tables` links become dead
for every visitor. The audit's published-links check will catch it at that
moment; publishing the batch together avoids it.
