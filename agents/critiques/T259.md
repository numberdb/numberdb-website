# T259 critique: Kostka–Foulkes polynomials $K_{\lambda\mu}(t)$

Read 2026-09-16. T259 is a private draft — `/T259` answers 404 — so it was read
through `GET /api/table?id=T259` and rendered in eleven `/preview?table=`
pieces. It holds 901 entries, one integer polynomial in $t$ for each pair of
partitions $(\lambda,\mu)$ of the same size $n\leq9$ with $\lambda$ dominating
$\mu$, grouped under 96 values of $\lambda$; type `Z[]`, rigour `exact`,
`complete: no` with a note giving the range. `GET /api/table/T259/audit`
reports `{"findings": [], "clean": true}`, and I agree with it; nothing it
looks for is wrong here, and none of the eight findings below is a rule it
has.

**This is a good table and it reads well.** The three things I checked hardest
all held.

*The values are right, checked against something that is not Sage.* I
implemented the Lascoux–Schützenberger charge statistic and a semistandard
tableau enumeration in plain Python and recomputed every stored polynomial.
All 901 agree, exactly, as strings. The entry set is also exactly the
dominance set: 1, 3, 6, 15, 28, 64, 116, 238, 430 pairs at sizes 1 to 9, which
is every $(\lambda,\mu)$ the `complete-note` promises and no others.

*It is one table and not two.* Two parameters, both partitions, and neither
names a second quantity: $\lambda$ and $\mu$ together say *what the number is
of*, one coefficient of one transition matrix. The value column is headed
`$K_{\lambda\mu}(t)$`, a symbol true of all 901 rows, not the word `value`.
Neither parameter uses `param-latex`, which is right, because both their
values are shown as themselves.

*The rendering is clean.* No "Math input error", no eaten `<`, no
`argument ()`, no dangling `CITE{}` or `HREF{}`. All five declared sources
render as numbered links and all three URLs answer 200; both `HREF{}` slugs,
`Schur_polynomials` and `Monomial_symmetric_polynomials`, resolve. One thing
that looked like a rendering fault is not one: `CITE{formula-charge}` inside
`rigour details` prints as the bare word `formula-charge` in a preview chunk
that omits `Formulas`, and as the link "(2)" when `Formulas` is present.

Eight things are left. Seven are worth doing; the eighth is a judgement call.
Three more are noted only because I noticed them.

- **1 is a statement on the page that is false**, and I have the Sage output.
- **2 is the one that costs a reader something**: the table's central formula
  uses a statistic the table never defines.
- **3 is a rigour claim that is not one**: one of the four checks is the
  generator checking itself, and I read the Sage source to be sure.
- **4 to 7 are worth doing while the file is open.**
- **8 is a search judgement**, with a measurement behind half of it.
- **9, 10 and 11 are noted only.**

## 1. The `Programs` snippet computes a value the table already holds, and says it does not

What a reader sees, as (P1), labelled `Sage`:

    from sage.combinat.sf.kfpoly import KostkaFoulkesPolynomial

    KostkaFoulkesPolynomial([4], [2, 1, 1])    # t^3, past this table's diagonal

Run verbatim through `agents/sage.sh` under SageMath 10.9, the import works and
the call returns `t^3`. That value is row four of the very first block of
numbers a reader sees:

    $\lambda$   $\mu$        $K_{\lambda\mu}(t)$
    4           2, 1, 1:     t^3

So the comment tells a reader the example is outside the table, and it is
inside it — $\lambda=(4)$ and $\mu=(2,1,1)$ are partitions of 4, and the table
runs to 9.

The phrase came from somewhere. The two sibling tables this one links to write
the same line and mean it:

    schur(4, [3, 2])                 # a partition of 5, past this table
    monomial_symmetric(5, [3, 2])    # a partition of 5, past this table

"past this table" there names an example the table does not hold, which is what
the skill asks a `Programs` block for: "the standard incantation for a reader
who wants one more value". Here "past this table" grew a qualifier, "past this
table's diagonal", and the example stopped being past anything. A reader can
read "diagonal" as the $\lambda=\mu$ row and be told something true and
useless, or as the table's edge and be told something false; neither reading
gives them a value they did not have.

Smallest fix: a pair of partitions of 10. I ran one:

    KostkaFoulkesPolynomial([5, 3, 2], [2, 2, 2, 2, 2])   # a partition of 10, past this table

returns `t^13 + 2*t^12 + 4*t^11 + 5*t^10 + 6*t^9 + 5*t^8 + 4*t^7 + 2*t^6 + t^5`.

(The import itself is fine. This is not the `sage.all` fault that T256, T257
and T258 all had: `from sage.combinat.sf.kfpoly import ...` works in a script,
where `from sage.rings.integer_ring import ZZ` does not.)

## 2. `charge` is the whole content of formula (2) and the table never says what it is

What a reader sees, as formula (2):

> $K_{\lambda\mu}(t)=\sum_T t^{\operatorname{charge}(T)}$, summed over
> semistandard Young tableaux $T$ of shape $\lambda$ and weight $\mu$ [2]

Nothing on the page says what $\operatorname{charge}$ is. It is not a standard
symbol like $\gcd$; it is a specific combinatorial statistic with a specific
construction, and a reader who wants to check one of these polynomials by hand
— which is the only thing formula (2) is for — cannot start. The skill is
explicit: "If a symbol appears in a formula or a comment, its definition
belongs in the same table."

There is a second, sharper half to it. Charge is a statistic on *words*, not on
tableaux, and the formula writes $\operatorname{charge}(T)$ for a tableau
without saying which word. Sage's own documentation for the function this table
is built from does say:

> where $\operatorname{charge}(T)$ denotes the charge of the reading word of
> $T$

Reproducing the 901 values took exactly that missing sentence: I had to supply
"the reading word, read left to right along each row from the bottom row
upwards", and that choice is not recoverable from what the page prints.

`CITE{LS}` sits beside the formula, and it is the right reference, but it is a
two-page *Comptes Rendus* note from 1978 with no DOI or arXiv identifier in
this table — it is the attribution, not a definition a reader can reach.

Smallest fix, one clause in `formula-charge` and one sentence in `Comments`:

> $\operatorname{charge}(T)$ is the charge of the reading word of $T$, the word
> obtained by reading each row left to right, from the bottom row upwards. The
> charge of a word is computed by decomposing it into standard subwords, as in
> CITE{LS}; CITE{Sage} gives the algorithm.

## 3. The first of the four checks in `rigour details` is the generator checking itself

What a reader sees, folded under "more" in `Data properties`:

> Before the values were written, they were checked against Sage's
> Schur-to-Hall-Littlewood transition dictionary, against an independent
> enumeration of semistandard tableaux using the charge statistic, against the
> dominance zero condition, and against the specialization $K_{\lambda\mu}(1)$
> to the ordinary Kostka number.

Four checks, and the first one is not a check. The generator computes every
value with `KostkaFoulkesPolynomial`. In `sage.combinat.sf.kfpoly`, that
function's whole body is a delegation to `kfpoly`, and `kfpoly` and
`schur_to_hl` are the same loop:

    # kfpoly(mu, nu, t)
    nuc = _Partitions(nu).conjugate()
    f = lambda x: weight(x, t) if x[0] == nuc else 0
    return sum(f(rg) for rg in riggings(mu))

    # schur_to_hl(mu, t)
    for rg in riggings(mu):
        res[rg[0]] = res.get(rg[0], 0) + weight(rg, t)

Same `riggings`, same `weight`, same module. Comparing one against the other
can only detect a transcription slip between the generator and the table; an
error in `riggings` or `weight` would pass it silently. The skill's rule is
exactly this: "Check new values against something independent. **Not the code
that produced them.**"

The other three are real, and the strongest of them is the one I reproduced:
an independent Python enumeration of semistandard tableaux with the charge
statistic gives all 901 stored polynomials. So the sentence does not need
propping up — it needs its weakest clause removed, so that a reader counting
the evidence counts three things rather than four.

Smallest fix: drop "against Sage's Schur-to-Hall-Littlewood transition
dictionary, " and begin the list at the tableau enumeration.

## 4. The Definition names the Schur polynomials and does not link the table of them

What a reader sees, as the whole Definition:

> The Kostka-Foulkes polynomial $K_{\lambda\mu}(t)$ is the coefficient of
> $P_\mu(x;t)$ in the Hall-Littlewood expansion [5] of the Schur polynomial
> $s_\lambda$ [4].

`Schur_polynomials` is a published table in this corpus, and it is already in
this document's `Similar tables`. The skill: "Link the first mention of a
thing to what explains it. A table if the corpus holds one". First mention is
here, in the Definition, and it is plain text; a reader meeting $s_\lambda$ is
one click from 33 of them and is not given the click. The corpus holds
no Hall–Littlewood table, so `CITE{WikiHallLittlewood}` is right where it is.

The two citations are also attached to the wrong nouns. Rendered, "[5]" sits
after "Hall-Littlewood expansion", which is correct, and "[4]" sits after "the
Schur polynomial $s_\lambda$" — but [4] is *Wikipedia: Kostka polynomial*,
which is the source for the object the sentence defines, not for Schur
polynomials. A reader following it to learn about $s_\lambda$ lands somewhere
else.

Smallest fix:

> The Kostka-Foulkes polynomial $K_{\lambda\mu}(t)$ CITE{WikiKostka} is the
> coefficient of $P_\mu(x;t)$ in the Hall-Littlewood expansion
> CITE{WikiHallLittlewood} of HREF{Schur_polynomials}[the Schur polynomial]
> $s_\lambda$.

## 5. The one comment is said three times elsewhere, and the two things a comment is needed for are missing

What a reader sees, as the only comment:

> (1) The Hall-Littlewood polynomial $P_\mu(x;t)$ is taken in Macdonald's $P$
> normalisation. If $\lambda$ does not dominate $\mu$, then
> $K_{\lambda\mu}(t)=0$; such pairs are not entries in this table.

Both sentences are already on the page. The first repeats formula (1), which
says "with $P_\mu(x;t)$ in Macdonald's Hall-Littlewood $P$ normalisation". The
second repeats formula (4), "$K_{\lambda\mu}(t)=0$ unless $\lambda$ dominates
$\mu$", and the $\mu$ parameter's own constraint, "a partition of $|\lambda|$
dominated by $\lambda$". It is also a formula written into `Comments`, which
the skill's section table puts on the "not" side. The one clause that is
nowhere else is "such pairs are not entries in this table", eight words.

Meanwhile the two things a reader does need a comment for are absent, and both
of the sibling tables carry the first of them verbatim:

* **How a partition is written.** The $\lambda$ and $\mu$ columns print `3, 1`
  and `2, 1, 1` with no statement anywhere that these are partitions written
  as their parts, largest first. `Schur_polynomials` and
  `Monomial_symmetric_polynomials` both say it, in identical words:
  "The partition is written as its parts, largest first, separated by commas:
  $2,1,1$ is the partition $(2,1,1)$ of $4$."
* **What charge is**, which is finding 2.

Smallest fix: replace comment (1) with those two sentences and keep the
surviving clause as a third, "Pairs where $\lambda$ does not dominate $\mu$
have $K_{\lambda\mu}(t)=0$ and are not entries here."

## 6. The completeness note says what and not why, and the argument is already measured

What a reader sees:

> Table is complete: no (it holds every nonzero $K_{\lambda\mu}(t)$ with
> $|\lambda|=|\mu|\leq9$)

Accurate — I checked the entry set against an independent enumeration of the
dominance order and it is exactly that set. But the skill asks this note to
carry the argument for the range, because it is "what a reader checking whether
their own number belongs here actually reads", and the next person extending
the table has nothing on the page telling them why it stops at 9.

The argument exists. It is a comment in `generators/kostka-foulkes-polynomials/generate.py`:

> up to size 9 gives 901 entries, the longest value is 182 characters, and the
> entries block is 75.1 KB. Size 10 would be 1719 entries, over the soft entry
> limit and at 160.8 KB.

Both figures I can check are right: 901 entries, and the longest is 182
characters ($\lambda=(4,3,1,1)$, $\mu=(1^9)$). This is a better reason than
most tables have, and it is the one sentence a reader of the page does not get.

Smallest fix, a clause inside the existing parenthesis: "…, a bound set by the
entry count: size 10 would be 1719 entries, past the soft limit of 1200."

## 7. The `Sage` link is declared and never cited

`Links` holds three entries and the prose cites two of them. `Sage`, the
SageMath reference page for `kfpoly`, is pointed at by nothing — a listing
rather than a citation, which the skill calls furniture.

It has an obvious home. `rigour details` already writes "The generator computes
the coefficients with Sage's `KostkaFoulkesPolynomial`, whose documentation
defines them by (2)" — a sentence about a document, with no link to it.

Smallest fix: `CITE{Sage}` after "`KostkaFoulkesPolynomial`". It also gives
finding 2 somewhere to point at for the charge algorithm.

## 8. Nothing here says "Lusztig", and two keywords buy nothing

`Keywords` holds `Kostka-Foulkes`, `Kostka Foulkes`, `Hall-Littlewood`,
`tableaux charge`, `t-analogue of Kostka numbers`.

Two of those five are already reached by the title. The title writes
Kostka–Foulkes with an en dash and the keywords add the hyphen and the space
forms, which looks like insurance against the site's index — the skill warns
about exactly this for accents, "the index has no `unaccent`". Dashes are not
accents, and I measured it on published tables: searching `Hardy-Littlewood`
and `Hardy–Littlewood` returns the same tables in the same order, and so does
`Gauss-Laguerre` against `Nodes and weights of Gauss–Laguerre quadrature`,
whose title carries the en dash. The search is indifferent to the dash on both
sides. So `Kostka-Foulkes` and `Kostka Foulkes` cost two slots for nothing.

What is not reachable is the other name of this object. In type $A$ these
polynomials are Lusztig's $q$-analogue of weight multiplicity, and somebody
arriving with one of them from an affine Lie algebra or a Hall algebra
computation types "Lusztig", not "Kostka". The skill's test — "what would
somebody type who is holding one of these numbers and wants to know what it
is?" — has an answer here that the table does not carry.

Smallest fix: drop the two dash variants and add `Lusztig q-analogue` and
`q-analogue of weight multiplicity`.

I rank this below the rest because the dash measurement is about this site's
index today and the naming judgement is a judgement.

## 9. The Definition does not fix the alphabet — noted only

"the Schur polynomial $s_\lambda$" and "$P_\mu(x;t)$" are written with no
statement of how many variables $x$ runs over, and $x$ is never introduced. It
does not change any stored value: the coefficients are the same in any
$n\geq\ell(\mu)$ and in the ring of symmetric functions. It matters slightly
because the table a reader is sent to, `Schur_polynomials`, defines
$s_\lambda(x_1,\dots,x_n)$ with an explicit $n\leq4$, so following the link
lands them on an object whose variable count this table never fixed.

Half a sentence would settle it — "as symmetric functions", or "in $n$
variables with $n\geq\ell(\mu)$" — but the two sibling tables handle the
alphabet by making $n$ a parameter, which is not open to this table, so this
is not a change I would make without a view on all three.

## 10. The $\lambda$ column repeats on every row — noted only, and not this table's doing

Rendered, the block for $\lambda=(4)$ reads

    4    4:           1
    4    3, 1:        t
    4    2, 2:        t^2
    4    2, 1, 1:     t^3
    4    1, 1, 1, 1:  t^6

with `4` printed five times. The site's numbers block is a flat grid —
`div.table-block` per entry, one `div.table-param-group` per parameter, no
grouping or row span — so this is how every two-parameter table renders and
T258 renders identically. Noting it so the next person does not spend an
afternoon deciding whether T259 could have avoided it. It cannot.

One thing that could have gone wrong here and did not: the entry anchors are
`$\lambda$,$\mu$` concatenated, so $\lambda=(4)$, $\mu=(3,1)$ is `#4,3,1`,
which looks ambiguous. It is not. Every entry has $|\lambda|=|\mu|$, and the
partial sums of a concatenated pair are strictly increasing, so the split point
— the unique prefix summing to half the total — is recoverable from the string.
No two of the 901 entries collide.

## 11. `CITE{LS}` has no identifier beside it — noted only

`References` has two entries. Macdonald carries `mr`, and renders with an "(MR)"
link. The Lascoux–Schützenberger note carries `bib` alone, so a reader who wants
the paper that finding 2 says is the definition of charge gets a citation
string and no address. The skill lists `arxiv`, `doi`, `zbl`, `mr` as the
identifiers that render as links. I did not look up a number for it and am not
going to guess one; somebody with MathSciNet or zbMATH open can add it in a
minute.
