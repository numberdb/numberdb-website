# T260 critique: Macdonald–Kostka polynomials $\tilde K_{\lambda\mu}(q,t)$

Read 2026-09-16. T260 is a private draft — `/T260` answers 404 — so it was
read through `GET /api/table?id=T260` and rendered in eight `/preview?table=`
pieces, which is the only rendering of it available from outside. It holds 787
entries, one polynomial in $\mathbb{Z}[q,t]$ for each pair of partitions
$(\lambda,\mu)$ of the same size $3\leq n\leq 8$ with $\lambda$ neither a
single row nor a single column, grouped under 51 values of $\lambda$; type
`Z[]`, rigour `exact`, `complete: no` with a note giving the range.

`GET /api/table/T260/audit` reports `{"findings": [], "clean": true}`. I agree
with the verdict as far as it goes: nothing it looks for is wrong here. Six of
the seven findings below are not rules it has; one (finding 6) is a rule it
has and misses, because the phrase in the prose is singular where the title it
would match is plural.

**This is a good table and it reads well.** The things I checked hardest all
held.

*The rendering is clean.* No "Math input error" waiting to happen, no eaten
`<`, no `argument ()`, no dangling `CITE{}` or `HREF{}`. Rendered with
`Formulas`, `References` and `Links` all present, every `CITE{}` resolves to a
number: `CITE{HHL}` to `[1]`, `CITE{SageMacdonald}` to `[4]`,
`CITE{formula-duality}` to `(6)`, `CITE{formula-edges}` to `(7)`. All five
external URLs render as links. The whole document contains exactly one
non-ASCII character, the en dash in the title, and no `--` anywhere. Both
parameters render with their titles rather than falling back to
`Symbolic (Unknown type)`, which is what the same parameter does on T122.

*The entry addresses survive both parameters holding commas.* An entry anchor
is its parameter values comma-joined, and here both values are partitions
written with commas, so `#2,1,3` is $\lambda=(2,1)$, $\mu=(3)$ with nothing
marking the join. It is still unambiguous, because $|\lambda|=|\mu|$ forces
the split at the prefix summing to half the total, and all 787 anchors are in
fact distinct. Worth saying because it looked like a collision waiting to
happen and is not one.

*The `Programs` incantation runs and agrees.* I ran the stored block verbatim
through Sage's preparser: it returns
`q^3*t^2 + q^2*t^3 + q^4 + 3*q^3*t + 4*q^2*t^2 + 3*q*t^3 + t^4 + q^2*t + q*t^2`
for $\lambda=\mu=(3,2,1)$, which is the stored row character for character.

*The entry set is exactly the rule the table states.* Sizes 3 to 8 hold 3, 15,
35, 99, 195 and 440 rows, which is $(p(n)-2)\,p(n)$ for each $n$ — every
$\lambda$ but the row and the column, against every $\mu$, and no others. No
single-row or single-column $\lambda$ is stored. All 787 values satisfy
$\tilde K_{\lambda\mu}(1,1)=f^\lambda$, and none has a negative coefficient.

*It is one table and not two.* Two parameters, both partitions, and neither
names a second quantity: $\lambda$ and $\mu$ together say what the number is
of, one coefficient of one transition matrix. The value column is headed
`$\tilde K_{\lambda\mu}(q,t)$`, a symbol true of all 787 rows, not the word
`value`. Neither parameter uses `param-latex`, which is right, because both
their values are shown as themselves.

Seven things are left. Five are worth doing; two are rule-following that costs
nothing. Three more are noted only because I noticed them.

---

## 1. `formula-hook` uses plethystic brackets and does not say so

A reader sees, as formula (5):

> For a hook shape $\lambda=(n-k,1^k)$, $\tilde K_{\lambda\mu}(q,t)=e_k[B_\mu-1]$,
> with $B_\mu=\sum_{(i,j)\in\mu}q^jt^i$ and zero-based row and column indices.

The square brackets are plethystic substitution. Nothing on the page says so,
and $e_k$ is not defined here either — the elementary symmetric polynomials
are linked from `Similar tables`, two sections away, and the reader who is
looking at formula (5) has no reason to go there.

Read the way the notation invites, as $e_k$ evaluated at the single quantity
$B_\mu-1$, the formula gives $0$ for every $k\geq2$. That is 222 of the 285
hook rows in the table, and not one of them is zero. So this is not a piece of
harmless shorthand: a reader who trusts it and reads it the ordinary way gets
a wrong answer and no warning. Read plethystically it is right — I checked all
285 hook rows and all 285 agree.

Smallest fix, and it introduces no new notation: say what the right-hand side
is in words. "$e_k[B_\mu-1]$, the elementary symmetric polynomial of degree
$k$ in the monomials $q^jt^i$ of the cells of $\mu$ other than the corner."
A reader can then compute it. Alternatively keep the bracket and add "where
$[\,\cdot\,]$ is plethystic substitution".

**Worth doing.** The highest-ranked finding here, because it is the only one
where a reader can leave the page with a wrong number.

## 2. $\mu'$ is used three times and never defined

`$\mu'$` appears in the `swapped-variables` comment ("sends the row with
Macdonald shape $\mu$ to the row with Macdonald shape $\mu'$"), in
`formula-duality`, and in `formula-edges` as $q^{n(\mu')}$. It is the
conjugate partition, and the table never says so. Every other symbol in the
table is glossed where it is used — $n(\mu)$ in `formula-macdonald-kostka`,
$f^\lambda$ in `formula-one-one`, $B_\mu$ in `formula-hook` — so this is the
one gap, and the `swapped-variables` comment is where a reader meets it: they
are told a whole convention hinges on a symbol they have not been given.

Smallest fix: one clause in the `convention` comment, which already explains
how a partition is written. "…is the partition $(3,2,1)$ of $6$, and $\mu'$
denotes the conjugate partition."

**Worth doing.**

## 3. `complete-note` promises size 2 and the table starts at size 3

The rendered line reads:

> Table is complete: no (it holds every nontrivial coefficient with
> $2\leq|\lambda|=|\mu|\leq8$; …)

There are no rows with $|\lambda|=2$. Both partitions of $2$ are a single row
or a single column, so the $\lambda$ constraint excludes both, and the
smallest stored size is $3$. The sentence is true if you read "nontrivial" as
doing that work, and a reader who arrived holding a size-2 case will not read
it that way: they will read a promise, look, and find nothing.

Smallest fix: write $3\leq|\lambda|=|\mu|\leq8$. (The generator's docstring in
`generators/macdonald-kostka-polynomials/generate.py` says `2 <=` too and
would want the same.)

**Worth doing.** Small, and it is the one sentence a reader checks their own
number against.

## 4. `HREF{T259}` without a caption prints the bare string "T259"

Formula (3) renders as:

> $\tilde K_{\lambda\mu}(0,t)=t^{n(\mu)}K_{\lambda\mu}(t^{-1})$, where
> $K_{\lambda\mu}(t)$ is the Kostka-Foulkes polynomial T259.

The sentence ends in a T-number. Every other link in the table carries a
caption — `HREF{T122}[Schur polynomials]`, `HREF{T118}[elementary symmetric
polynomials]`, `HREF{T259}[the Kostka-Foulkes polynomials]` in the rigour
note — and this one does not, so the link text falls back to the address.

Smallest fix: `is HREF{T259}[the Kostka-Foulkes polynomial]`, dropping the
plain phrase that now precedes it.

**Worth doing.**

## 5. `omitted-rows` does not say which index is the single row

> The single-row and single-column Schur coefficients are not stored as
> entries. They are the closed forms in (7).

Both $\lambda$ and $\mu$ are partitions, and both take single-row and
single-column values. The rows with $\mu=(n)$ and $\mu=(1^n)$ *are* stored —
they are the two ends of every group. So a reader has to work out from formula
(7), which writes $\tilde K_{(n),\mu}$ and $\tilde K_{(1^n),\mu}$, that the
comment meant $\lambda$. "Schur coefficients" is the hint, since $\lambda$ is
the Schur index, but it is a hint rather than a statement.

Smallest fix: "The coefficients with $\lambda=(n)$ or $\lambda=(1^n)$ are not
stored as entries", which is what formula (7) says anyway.

**Worth doing.**

## 6. The Definition names the Schur polynomial and does not link it

The first sentence a reader gets is:

> The Macdonald-Kostka polynomial $\tilde K_{\lambda\mu}(q,t)$ is the
> coefficient of the Schur polynomial $s_\lambda$ in the expansion … of the
> modified Macdonald polynomial $\tilde H_\mu$ [1].

The Macdonald side gets a pointer, `CITE{HHL}`, at its first mention. The
Schur side does not, though this corpus holds it: T122, `Schur_polynomials`,
public, and linked from `Similar tables` further down. First mention, once per
section, is the rule, and `Definition` is a section.

Smallest fix: `the coefficient of HREF{Schur_polynomials}[the Schur
polynomial] $s_\lambda$`. The slug answers 200; I checked.

The audit did not catch this, and I do not think it could: it matches a phrase
against a title, and the phrase here is singular ("Schur polynomial") where
the title is plural ("Schur polynomials $s_\lambda$").

**Worth doing**, and it costs one edit.

## 7. Two of the three references are cited from nowhere

`HHL` is cited four times. `Haiman` and `Macdonald` are declared, render as
[2] and [3] with their arXiv, doi and MR links, and nothing in the table
points at either. A bibliography nobody points at is furniture.

One of the two has an obvious home going begging. `formula-macdonald-kostka`
reads "…and $K_{\lambda\mu}(q,t)$ is Macdonald's two-variable Kostka
coefficient CITE{SageMacdonald}" — citing the SageMath documentation for a
definition due to Macdonald, whose book is sitting in `References`. Cite
`Macdonald` there, beside or instead of the Sage link.

`Haiman` has no home in the table as written, and the fact it would support is
one the table never states: every $\tilde K_{\lambda\mu}(q,t)$ has nonnegative
integer coefficients, which is the Macdonald positivity conjecture and
Haiman's theorem, and which holds for all 787 stored rows (I checked). The
table's own `Keywords` already carry "Garsia-Haiman modules" and "Hilbert
scheme of points", which are that theorem's context — so the keywords point at
a fact the prose does not make. A one-sentence comment would state it and give
[2] its citation. Failing that, drop the reference.

**Worth doing**, the `Macdonald` half certainly; the `Haiman` half is a
judgement call about whether to add the positivity sentence, and I would.

## Noted only because I noticed

**$\lambda$'s parameter title is "shape", beside $\mu$'s "Macdonald shape".**
The rendered list reads "$\lambda$ — shape" and "$\mu$ — Macdonald shape",
and a reader meeting two shapes, one of them called "shape", has to guess
which is which from the constraint. "Schur shape" would pair with "Macdonald
shape" and match the way the rest of the table talks ("the Schur coefficients
are…"). I am not proposing it, because T259 titles its $\lambda$ "shape" too
and the two tables should read alike; it is worth changing only if both change.

**The `Programs` block returns an element of the fraction field of
$\mathbb{Q}[q,t]$**, not of $\mathbb{Z}[q,t]$, because `K.subs({t: 1/t})`
coerces. It prints identically to the stored entry, so a reader comparing the
two sees agreement, and the `rigour details` note is about the generator
rather than this block. Nothing to fix. (The block also binds `q` and never
uses it.)

**`complete-note` ends "past the soft entry limit of $1200$"**, which is
NumberDB's own ingest limit inside a field a reader reads as mathematics.
T259's note says "past the soft limit of 1200" in the same place, so this is
the batch's usage rather than a slip in T260, and it is not worth splitting
the two apart for.
