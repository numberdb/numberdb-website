# T316: Maximal cusp volumes of the hyperbolic prime knots with at most ten crossings

Read on 2026-09-18, against the skill fetched the same day from
<https://numberdb.org/skill> (47,534 bytes; fetched directly, since `ALL_PROXY`
is empty on this machine and the SOCKS proxy at `127.0.0.1:1080` refuses
every connection). T316 is a draft of 243 real entries at 100 digits, one per
hyperbolic prime knot $n_k$ with at most ten crossings: the volume of the
maximal cusp of $S^3\setminus n_k$. `rigour: proven`, `complete: yes`. It is
the seventh knot table in the corpus and is built to the pattern of T138,
T139, T140, T141, T312, T313 and T315 -- closest to T141, whose two parameters
and whose 243 knots it shares exactly.

**How I read it.** The HTML routes authenticate by session, so `GET /T316`
answers 404 to the zeta3 key. I rebuilt the page the way the T315 critique
did: the site's own code and templates, the document as `/api/table?id=T316`
serves it, and a throwaway sqlite database inside the `agents/sage.sh`
container. One new obstacle, since T315 was a polynomial table and this one
holds reals: `Number.value_range` and `Number.frac_range` are
`DecimalRangeField`s, and `RangeField.get_placeholder` emits `%s::numrange`
whatever the value is, so every insert died on sqlite's `unrecognized token:
":"`. Patching that placeholder to `%s` and nulling the two columns -- they
are the search projection, and nothing on the page reads them -- gave the
whole page: status 200, 188,528 bytes, all 243 rows with their comments, the
column headers, the prose, the reference numbering. Every quotation below is
from that page. The obstacle is written up in `docs/agent-environment.md`.

`audit_table` cannot run here (no database); `GET /api/table/T316/audit`
answers `{"findings": [], "clean": true}`. I agree with it as far as it goes.
Three of the findings below are outside what it checks: it verifies that every
`CITE` names something, never that everything named is cited
(`audit_table.py:323`), it reads a `Similar tables` caption not at all, and it
does not open a link to see whether the page is the one the title promises.

**The table is in good shape.** The page renders whole, the family is exactly
the one the Definition describes, the values are right where I could check
them independently, and no two of them collide at the precision a reader will
type. The findings are about six rows whose names differ from the source a
reader is most likely to be holding, and about four places where the page
points at something without naming it.

## What I checked hardest, and found nothing wrong with

* **The `Programs` block runs as written and gives the page's numbers.** It
  builds the exterior from Sage's `small_knots_table`, which is *not* where
  the generator got its braid words (`generate.py` carries its own copy of
  KnotInfo's), so this is also a check that the two sources name the same
  knot by $n_k$. For $4_1$, $5_2$, $8_{18}$, $10_{161}$, $10_{162}$,
  $10_{163}$ and $10_{165}$ the snippet reproduces the stored value to every
  digit I compared. It exercises comment (6) by accident, too: Sage's braid
  word for $5_2$ is $\sigma_1^{-3}\sigma_2^{-1}\sigma_1\sigma_2^{-1}$, the
  mirror of the generator's $\sigma_1^3\sigma_2\sigma_1^{-1}\sigma_2$, and
  the two give the same cusp volume.
* **$4_1$ is $\sqrt3$ to all hundred digits.** Formula (2) says
  $\operatorname{cv}(S^3\setminus 4_1)=\sqrt3$; the stored entry agrees with
  `Decimal(3).sqrt()` at 120 working digits, correctly rounded in its last
  place. That is an exact closed form matched against the stored digits, not
  against the code that made them.
* **The family is the one the prose claims.** $1+1+2+3+7+21+49+165=249$ prime
  knots through ten crossings, six torus knots, 243 rows. Every $k$ from 1 to
  $N(n)$ is present for each $n$ except the five torus indices the parameter
  constraint excludes, with no gaps and nothing extra.
* **A reader with a handful of digits gets one answer.** No two rows hold the
  same value, no two agree to nine significant digits, and the closest pair in
  the table ($9_2$ and $10_1$) differ by $8.7\times10^{-5}$. So the five or six
  digits somebody is likely to paste into the search box identify the knot.
* **The page does not break.** Balanced `$` in every field, no raw `<` or `>`,
  no `--`, no stray control characters outside the `Programs` code, and
  nothing in the rendered HTML that reads as a MathJax input error or an
  `(Unknown key)`.
* **Everything the page points at exists.** All four `HREF` slugs and all four
  `Links` answer 200.
* **It is one table.** Two integer parameters that index one quantity of one
  family, and a value column headed $\operatorname{cv}(S^3\setminus n_k)$,
  which is a symbol true of every row rather than the word `value`.

## Findings, in the order I would fix them

### 1. Comment (5) says SnapPy's names differ, and never says how. Six of the 243 rows are affected

Comment (5), the whole of what the page tells a reader about the clash:

> The knot $n_k$ is numbered as in Rolfsen's table [1] after Perko's
> correction [2]. KnotInfo [4] uses this numbering. SnapPy's built-in Rolfsen
> names do not, so calculations build the exterior from the braid word in this
> numbering.

A reader arriving with a cusp volume most likely got it from SnapPy -- it is
the program the rigour note, the `Programs` block and `Links[6]` all name --
and will have got it by asking for a knot *by name*. For six knots the name
SnapPy uses and the name this table uses are different knots. I ran both:

    snappy Manifold('10_83')  -> 8.8017833452...  = this table's 10_86
    snappy Manifold('10_86')  -> 8.5277861646...  = this table's 10_83
    snappy Manifold('10_162') -> 3.4389117634...  = this table's 10_161 again
    snappy Manifold('10_163') -> 6.8943668866...  = this table's 10_162
    snappy Manifold('10_164') -> 7.8870243433...  = this table's 10_163
    snappy Manifold('10_165') -> 7.7685810671...  = this table's 10_164
    snappy Manifold('10_166') -> 6.5660986292...  = this table's 10_165

The shift is what "after Perko's correction" *does*, and the page never says
it. Worse, the page contradicts itself without it. The entry comment on
$10_{161}$ reads

> $10_{161}$; the Perko pair, listed twice by Rolfsen as $10_{161}$ and
> $10_{162}$; non-alternating

and four rows below it sits a row labelled $10_{162}$ holding a different
number. Both statements are true -- Rolfsen's $10_{162}$ was the duplicate,
and this table's $10_{162}$ is Rolfsen's $10_{163}$ -- but a reader has no way
to reconcile them from anything on the page.

The corpus already has the sentence. T141, the table of the volumes of these
same 243 complements, says it in its own comment (5):

> The numbering is Rolfsen's after Perko's correction [2]: the knots Rolfsen
> listed as $10_{161}$ and $10_{162}$ are one knot, so there are $165$ prime
> knots with ten crossings rather than $166$, and Rolfsen's $10_{163}$ to
> $10_{166}$ are $10_{162}$ to $10_{165}$ here. KnotInfo, the Knot Atlas and
> Sage's knot table use this numbering. SnapPy's own table of Rolfsen knots,
> Manifold('n_k'), does not: it keeps Rolfsen's 166 ...

T139 says the same. T316 copied the shorter version from T313, which is the
one sibling that also leaves it out.

**Smallest fix:** replace the first two sentences of comment (5) with T141's,
and add the second discrepancy, which T141 and T313 both put in their
`Programs` block and which I confirmed above: SnapPy's $10_{83}$ and
$10_{86}$ are interchanged relative to this numbering. That is six rows a
reader can otherwise get wrong, told in two clauses.

### 2. Reference [3] is cited nowhere

`References` holds Adams, Hildebrand and Weeks, *Hyperbolic invariants of
knots and links* -- the paper that computed these invariants for this table of
knots in the first place -- and no prose anywhere in the document contains
`CITE{AdamsHildebrandWeeks}`. The only `CITE` keys used are `KnotInfo`,
`Rolfsen` and `Perko`. It renders as a numbered reference [3] that nothing on
the page refers to, which is the skill's "bibliography nobody points at is
furniture", and it is the same fault the T315 critique found with Rolfsen
there.

**Smallest fix:** cite it where it belongs, in comment (4) beside the
statement of what the maximal cusp is -- it is the source for the cusp
invariants of exactly these knots -- or drop it. The audit will not tell you
either way; it checks that a `CITE` resolves, not that a reference is cited.

### 3. The Definition names the quantity and leaves the defining word to a comment

> The maximal cusp volume $\operatorname{cv}(S^3\setminus K)$ of the complete
> hyperbolic metric on the complement of a hyperbolic knot $K$ [4], for every
> hyperbolic prime knot $n_k$ with at most ten crossings, numbered as in
> Rolfsen's table [1] after Perko's correction [2].

The word doing the work is "maximal", and nothing in the Definition says
maximal under what. A reader who does not already know the term learns it two
sections later, in comment (4), and there it is framed as somebody else's
convention rather than as the definition:

> KnotInfo defines the maximal cusp volume as the volume of the maximal cusp
> split off by a maximal flat peripheral torus.

The Definition is reproducible, in the sense that two people following [4]
would build the same table; but they have to follow [4], and the page has the
sentence already. Compare T141, where the parallel Definition needs no such
help because "the volume of the complete hyperbolic metric on the complement"
is self-contained.

**Smallest fix:** one clause, so the first sentence carries its own meaning:
"the volume of the maximal cusp of $S^3\setminus K$, the largest embedded
horoball neighbourhood of the cusp, whose boundary torus is flat". Comment
(4) then says the shorter thing it is for, that KnotInfo's
`maximum_cusp_volume` column is this quantity.

### 4. The Chern-Simons caption is an old slug, not the table's title, and it promises a wider table

`Similar tables` reads

> Chern-Simons invariants of hyperbolic knot complements — the same
> hyperbolic knot complements

The slug behind it resolves to T313, whose title is "Chern–Simons invariants
of the hyperbolic prime knots with at most ten crossings" -- the caption is
the wording frozen into the slug when that table was created, not what the
table is called now. A reader is told there is a table of the Chern-Simons
invariants of hyperbolic knot complements, and lands on the same 243 knots
this page holds. The other three captions on this page are their tables'
titles exactly, which is the house style throughout T139, T141 and T312.

**Smallest fix:** caption it "Chern–Simons invariants of the hyperbolic prime
knots with at most ten crossings". The slug stays as it is; only the text in
the brackets changes.

### 5. `Links[6]` names a method and points at a front page

> SnapPy documentation: cusp_areas — https://snappy.computop.org/

The title promises the documentation of `cusp_areas`, which is the one thing a
reader following this link wants (it is the call the rigour note and the
`Programs` block both depend on, and the reason for the factor of two). The
URL is the SnapPy home page. `https://snappy.computop.org/manifold.html#snappy.Manifold.cusp_areas`
answers 200 and is the method's own entry.

**Smallest fix:** use that URL.

### 6. The `Programs` block does not say how to install what it imports

    from snappy import Link
    from sage.knots.knot_table import small_knots_table

`snappy` is not part of Sage, and a reader running the block without it gets
an `ImportError` on the first line. T141 and T313 both write the same import
as

    from snappy import Link, Manifold       # sage -pip install snappy

**Smallest fix:** the same comment on the same line. (The audit's install
check looks only at the attached `generate.py`, which does carry its
commands.)

### 7. Two relations name a difference and miss the one a reader will notice first

> Jones polynomials ... — the same knot names, with the unknot and the torus
> knots included there and excluded here

T139 and T138 also list each chiral knot twice, once for $K$ and once for
$\bar K$: 479 entries against these 243. A reader following the link to look
up the same knot meets a third parameter that this table does not have, and
the relation has already spent a clause on the smaller differences. The reason
is on this page -- comment (6), that the cusp volume does not distinguish a
knot from its mirror image -- so the relation can say it in five words.

**Smallest fix:** "... included there and excluded here, and each chiral knot
listed there with its mirror image as well".

## Noted only because I noticed

* **One tag.** `volume`, where T141 carries `volume` and `period`, and T313
  carries `period`. Sideways browsing works -- `volume` reaches T141 from
  here -- so this is not a hole, but the skill asks for two and the obvious
  second is the one the neighbour uses.
* **The rigour note does not say how far the source check reaches.** "the
  values are checked against KnotInfo's `maximum_cusp_volume` column" is true
  of the first ten significant digits: that is what the column holds, and what
  `generate.py` compares. The other ninety digits rest on the verified
  interval alone, which the sentence before it does say.
* **"so calculations build the exterior from the braid word in this
  numbering"** (comment (5)) has no subject a reader can attach: whose
  calculations, and which braid word? It is also a fact about the build rather
  than about the mathematics. The `Programs` block in fact builds from Sage's
  `small_knots_table` rather than from KnotInfo's word -- I checked that they
  agree, above, but the sentence does not name either.
* **Formula (2) singles out $4_1$ and does not say why.** $\sqrt3$ is the
  smallest value in the table (I checked all 243), and the row for the
  figure-eight knot is where somebody holding a small cusp volume will land.
  T141 uses the entry comment for exactly this: "the smallest volume of any
  hyperbolic knot complement". A clause naming what is special about $\sqrt3$
  would do more there than the formula does in a section of its own.
* **Entry comments punctuate the name with a semicolon** -- "$4_1$; the
  figure-eight knot; alternating" -- where T139, T141 and T313 all write
  "$4_1$, the figure-eight knot; ...". Trivial, and worth a `sed` only if
  something else brings the block back.
