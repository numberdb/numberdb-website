# Critique of T279, "Known solutions of the Fermat-Catalan equation $x^p+y^q=z^r$"

Read on 2026-09-16. The table is a private draft owned by zeta3.

## How it was read

- **Document:** `GET /api/table?id=T279` with the key returned 200. There are
  nine solutions, and each has four parts: `x`, `y`, `z` and `sum`.
- **Audit:** `GET /api/table/T279/audit` returned one finding, with
  `clean: false`. It says the parameter `part` takes 4 names (sum, x, y, z)
  "so this reads as 4 tables sharing one title and one value column". I did
  not run `manage.py audit_table`, because this runner has no Django.
- **Rendering:** nothing was listening on the SOCKS proxy at 127.0.0.1:1080
  (connection refused), but numberdb.org answered directly. `/T279` returns
  404 without a session, so I rendered the draft through `/preview?table=`.
  The request line is limited to about 4 KB, so I rendered it in pieces. Every
  piece carried `Links` and `References`, and every piece returned 200. Each
  prose section went with one solution, and the entries went two solutions at
  a time. No piece contained `Math input error`, `HREF-broken` or
  `CITE-broken`. When I first split without `References`, some pieces showed
  `CITE-broken`, but those came from the splitting, not from the table.
- **Source:** I read Sikora's §2 in the arXiv HTML version (2410.21552v1). It
  lists **ten** solutions, starting with $1+2^3=3^2$. The completeness range

- **Corpus:** `api/lookup` for Catalan, Beal, Pillai, Tijdeman, Mihailescu,

## The audit's finding

I agree with the form of the finding and disagree that the table should be
split. $x$, $y$, $z$ and $z^r$ are parts of one solution, which is the skill's
first good answer, the same as $a$, $b$, $c$ in the $abc$-triples. A reader
holding 30042907 wants $43$, $96222$ and the equation next to it. The
definition already says this in its last sentence. Nothing needs to change.

## Findings, ranked

### 1. The condition $xyz>1$ excludes nothing, so the definition admits a solution the table leaves out. Worth doing.

The definition, the constraint on the `sum` parameter and `complete-note` all
restrict to solutions "with $xyz>1$". A reader will take that to be the
condition that removes $1^p+2^3=3^2$, because comment (3) says that family is
not stored. It does not remove it: for that solution $xyz=1\cdot2\cdot3=6$. In
fact $xyz>1$ holds for every solution. $x=y=z=1$ would need $1+1=1$, so the
condition is empty. The same empty test is in the generator
(`if x * y * z <= 1`). As written, the definition describes ten solutions,
the table stores nine, and two people following the definition would not
build the same table.

`complete-note` also says the table "holds the nine known solutions with
$xyz>1$ listed in CITE{Sikora2024}". Sikora lists ten and never uses that
condition, so a reader who opens the paper will count ten and find a mismatch.

The smallest fix is to write the condition that is actually meant, with the
same wording in all three places: "with $x,y,z>1$" (or "with none of $x$,
$y$, $z$ equal to $1$"). `complete-note` should then read something like "it
holds the nine solutions with $x,y,z>1$ among the ten known solutions listed in
CITE{Sikora2024}; ...". Comment (3) can stay, since it gives the reason for
the exclusion.

### 2. The Darmon–Granville reference is never cited. Worth doing; it is one sentence.

Reference [2], Darmon and Granville 1995, appears in the bibliography, but no
`CITE{DarmonGranville}` points to it. A reader cannot tell why it is listed;
the skill calls this "furniture". The fact it supports is the one Sikora quotes
it for, and it belongs in the table: for each fixed $(p,q,r)$ with
$\frac1p+\frac1q+\frac1r<1$ there are only finitely many coprime solutions.
Add that as a comment ending in `CITE{DarmonGranville}`, or remove the
reference.

### 3. Comment (2) talks about search, and the 36 entry comments repeat the row label. Worth doing if the table is touched for #1.

Comment (2) says: "The exponents $p$, $q$ and $r$ are shown in the displayed
solution label and in each entry comment, rather than stored as rows. They
are small integers and would not identify this family in a number search."
The first sentence describes how the table was built. The second is a remark
about how search works, and the skill's rule is that "How strong a search hit
would be ... [is a remark] about the website".

The decision itself is sound. The exponents are not hidden: they are printed
on every row, in the label $2^5+7^2=3^4$. But that makes the entry comments
redundant. On the page, every row reads

    $2^5+7^2=3^4$   $x$:  2
    comment: In this solution, $x$ has exponent $p=5$.

and the comment repeats what the label on that row already shows. The skill's
guidance on per-entry comments applies: leave them out "when it repeats what
... the document already says for every row". The fix is to delete the 36
entry comments and cut comment (2) to "The exponents $p$, $q$ and $r$ of each
solution are shown in its label." Or delete comment (2) entirely, since the
label shows the exponents without being told to.

### 4. The formula restates the definition. Noted; low value.

Under Formulas the reader sees "For every stored solution, $x^p+y^q=z^r$,
$\gcd(x,y,z)=1$ and $\frac1p+\frac1q+\frac1r<1$." That is the definition again,
phrased as a check on the stored data. It is not an identity, and the table
has no real formula to state. Removing the `Formulas` section loses nothing.

### 5. The solution column is headed $z^r$. Noted only.

The first column of the entries is headed $z^r$ (the `display` of `sum`), and
its cells are whole equations, $2^5+7^2=3^4$. Inside the block, the last part
is also labelled $z^r$. The parameter list reads "$z^r$ — sum (a perfect
power $z^r$ from a coprime solution ...)". It is readable, because the reader
can see that the solutions are indexed by their sum. But the heading claims
the column holds $z^r$ when it holds equations. `display: solution` would say
what the column holds. The key `sum` can stay.

## What reads well

- **The page renders cleanly.** Every `$...$` in the labels, the long
  `complete-note` with $M_{\min(p,q,r)}$, and the fractions all set without
  error, and the one `<` in `Links` titles that bit T278 does not occur here.
- **A reader holding a number is served.** Arriving with 21063928 or
  443689062789184, the first thing on the row is the equation it belongs to.
  The order convention $x^p<y^q$ is explained where a reader comparing with
  Sikora's $7^3+13^2=2^9$ will look for it.
- **The parameters describe the family, not the run.** The range that was
  searched sits in `complete-note`, where it belongs, and it quotes the source
  exactly.

Findings 1 and 2 are the ones worth a repair. Finding 3 is cheap to fix at the
same time. Findings 4 and 5 are noted only because I saw them.
