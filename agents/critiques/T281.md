# Critique of T281, "Davenport-Stothers polynomial triples"

Read on 2026-09-16. The table is a private draft owned by zeta3. It holds five
triples ($M=1,\dots,5$) with three parts each, so 15 exact polynomials over
$\mathbb Q$.

## How it was read

- **Document:** `GET /api/table?id=T281` with the key.
- **Audit:** `GET /api/table/T281/audit` with the key. It returned two
  findings and `clean: false`. This runner has no Django, so I did not run
  `manage.py audit_table`.
- **Rendering:** `/T281` answers 404 without a session, because it is a draft.
  I rendered it through `/preview?table=` in four pieces: every entry, the
  prose sections, the lists, and the data properties. All four returned 200.
  `/preview` and the table page share `table_context` in
  `numberdb_app/views.py`, so what the preview printed is what the page will
  print. No piece contained `Math input error` or `argument ()`. The one
  `CITE-broken` came from my piece with the entries, which had no
  `References` in it; the full document has no broken citation.
- **Corpus:** a text search for Belyi, dessin, Stothers, Davenport, Mason,
  "Hall conjecture" and abc found T278, T279 and T280, which the table already
  names under Similar tables, and T62, T63 and T87 on abc triples and Szpiro
  ratios. There are no Belyi or dessin tables. All four tags exist.
- I did not recheck the values. Each part satisfies $h=f^3-g^2$, and the
  degrees match $2M$, $3M$ and $M+1$ at sight for $M=1,2,5$. The build checked
  the rest.

## The audit

The audit makes two findings, and I disagree with both about this table.

- **`part` (f, g, h)** is the good kind. The three polynomials are parts of
  one object, and a reader holding $h$ wants $f$ and $g$ beside it. The
  definition already says so: "the part is one of its three polynomials". The
  rule did not recognise that wording. Leave the table together.
- **`tree` (unique, Birch)** is not two tables either. Each $M$ has exactly
  one tree value, so the parameter picks one equivalence class within a given
  $M$. It does not name two quantities. The audit is right that something is
  wrong with this parameter, but the fault is its labels, not a need to split
  (finding 3).

The audit missed the most visible fault on the page (finding 1).

## Findings, ranked

### 1. Both formulas print as Python dictionaries. Worth doing, and first.

A reader sees this under Formulas:

    (1) {'name': 'defining relation', 'text': '$h(t)=f(t)^3-g(t)^2$.'}
    (2) {'name': 'Belyi map', 'text': '$f(t)^3/h(t)=1+g(t)^2/h(t)$ is the Belyi map attached to the Hall dessin of the triple [2] .'}

Each entry under `Formulas` is stored as a record `{name, text}`. The renderer
expects a string for a label and passes the dict straight to `render_text`, so
it prints the Python repr, braces and quotes included. MathJax may still
typeset the `$...$` inside it, but the line still reads as a dump. Nothing
checks for this: the API accepted it, and the audit is silent.

Fix: make each formula a plain string under its label, for example
`formula-defining-relation: "$h(t)=f(t)^3-g(t)^2$."`. The names "defining
relation" and "Belyi map" do not survive as captions, because the page numbers
formulas and does not caption them. Where a name matters, write it into the
sentence.

### 2. "Hall dessin" and "tree" are never explained. Worth doing.

"Hall dessin" appears in the constraint on `tree` and in formula (2). "Tree
label" is the title of a parameter. Nothing on the page says what the dessin
is, why it is a tree, or which tree. Take the constraint "a label for the
equivalence class of the Hall dessin represented by the row": a reader who
does not already know the Belyi-map picture cannot tell what is being
labelled. The skill says to define notation where it is used.

Fix: add one comment. It should say that $f^3/h$ is a Belyi map, and that its
dessin, with the degree-2 vertices removed, is a plane trivalent tree with
$M+1$ leaves (or whatever description Montanus uses, since the tree is his
label). Cite Montanus or Sijsling-Voight for it. Then the constraint on `tree`
can refer to that tree.

### 3. The `tree` labels are not labels. Worth doing before publication, because a key's values are frozen once cited.

The column reads `unique` on twelve rows and `Birch` on three. "Unique" is a
statement about a tree, namely that $M\le4$ has only one class; it does not
name the tree. "Birch" names a person. Neither describes a tree, so two people
adding a second class for $M=5$ would invent unrelated labels. That is
exactly what "two people would build the same table" rules out. Rows are cited
as `T281#4,unique,f`, so the vocabulary is fixed once the table is public.

It also matters which classes the table admits. If I count plane trivalent
trees with six leaves by hand, I get more than one: a symmetric "snowflake",
which fits Birch's $t\mapsto t^3$-symmetric row, and caterpillar shapes. So
$M=5$ probably has classes that the table does not hold. I have not checked
this against a source. The page does not say either way (see finding 5).

Fix: choose labels that name the tree, from a stated scheme. The simplest is
the one Montanus or Stothers uses, if either numbers the trees. Otherwise,
drop `tree` as a parameter while every $M$ holds one row, and keep Birch's
name in the $M=5$ row's comment. The first is better if the $M=5$ classes are
ever to be added.

The column heading is also `$tree$`. The parameter has no `display`, so the
page falls back to `$key$` and typesets the word in math italic as
$t\,r\,e\,e$. Add `display: tree`.

### 4. The `M` column says `$M=1$` under a heading `$M$`. Worth doing, one line each.

The values of `M` display as `$M=1$` … `$M=5$`. The column is already headed
$M$, so every row repeats the symbol. This is the "label that repeats what the
heading already says" case, and `M` is a number, so the display should be `1`
… `5`, or omitted.

### 5. The page does not say why $\deg h=M+1$ matters, or what is missing for $M=5$. Worth doing.

A reader holding one of these polynomials came from a calculation about
$f^3-g^2$. The fact that explains the table is Davenport's bound: $\deg
(f^3-g^2)\ge \tfrac12\deg f+1$ whenever $f^3\ne g^2$. It appears nowhere on
the page. Without it, "$\deg h=M+1$" in the definition looks arbitrary instead
of extremal, and the link to Hall's conjecture is left to a Similar-tables
gloss.

Fix: add a comment stating the bound, that these triples attain it and exist
for every $M$ (Stothers), and that they are the polynomial analogue of
HREF{Good_examples_of_Hall's_conjecture}[Hall's conjecture], with a citation.
The Mason-Stothers link is already in `Links` and can carry the citation.

The complete-note currently reads: "it holds the five examples printed in
[1]; that source states uniqueness up to equivalence for the $M\leq4$ rows,
while the $M=5$ row is Birch's symmetric example". The "while" sets up a
contrast it does not state. A reader cannot tell whether $M=5$ has other
classes. Better: "it holds every class with $M\leq4$, and for $M=5$ only
Birch's symmetric example, one of $N$ classes", with $N$ taken from a source.

### 6. The equivalence comment names only one triple, and "printed here" points. Worth doing, small.

"Two triples are equivalent … when constants … carry $f_1,g_1,h_1$ to $w^2
f_1(ut+v)$, …" Only one triple is named, and the reader has to guess that the
second one is the image. "The table stores one representative of each class
printed here": *here* could mean this page or Montanus's article. It means the
article.

Fix: "Triples $(f,g,h)$ and $(f_1,g_1,h_1)$ are equivalent … when
$f_1(t)=w^2f(ut+v)$, $g_1(t)=w^3g(ut+v)$ and $h_1(t)=w^6h(ut+v)$ for some …
The table stores, for each class, the representative printed in
CITE{Montanus2006}." It is worth adding one sentence: a triple from another
calculation is usually a different representative, so it matches only after
the substitution. A reader searching by polynomial needs to know that.

### 7. One Similar-tables gloss is false. Worth doing, one line.

The gloss for T279 reads "records another family where perfect powers nearly
coincide". Solutions of the Fermat-Catalan equation are exact equalities
$x^p+y^q=z^r$, so nothing nearly coincides. The T280 gloss, "records exact
integer parts of another perfect-power identity", is hard to parse ("exact
integer parts"?).

Fix, for example: "records coprime perfect powers whose sum is a perfect
power exactly", and "records integer solutions of $\sum a_i^k=b^k$ with fewer
than $k$ terms".

### 8. The definition's two naming conventions differ. Minor.

The definition says "of type $M$", and the parameter's title is
"half-degree". Use one word. The second sentence of the definition is about
how the table is indexed. That is acceptable, since it answers the audit's
question in the place the audit asks for. But it uses "equivalence class"
before the comment that defines it. "Up to the equivalence in (3)" would
point the reader there.

## Noted only

- The keyword "Hall polynomials in Hall conjecture" is not a phrase anybody
  types. "Hall polynomials" are a different object, from Hall algebras, so a
  search for them lands here. "Hall triples" (Montanus's *Halltripels*) would
  serve better.
- The tag `elliptic curves` has no support in the prose. The connection
  (elliptic surfaces, Danilov-Elkies Hall examples) is real but not stated.
- The reference text "Publications mathematiques de Besancon" has lost its
  accents. The Montanus article is in Dutch, and a reader following the
  citation would like to know that beforehand.

## What reads well

The first screen shows the entries grouped by $M$, with $f$, $g$ and $h$ next
to each other. That is what a reader holding one polynomial wants. The
rigour details say plainly what was transcribed and what was derived.
