## What reads well

This is the right table to have beside T284. T284 wrote each minimal
polynomial into an entry comment as text, where no search reaches it. Here each
polynomial is a searchable `Z[]` row with the same index, and each row links to
its root. The title says what the rows are. The number header $m_a(x)$ matches
what is stored. The parameter's constraint describes the family, not the run,
and the range is stated in `complete-note`. `Similar tables` names the relation
in a sentence.

## Findings, ranked

### 1. The Definition does not say what a Salem number is, and "the first half of the reciprocal minimal polynomial" is not precise (worth doing)

A reader sees:

> Let $a=(a_0,\ldots,a_{d/2})$ be the first half of the reciprocal minimal
> polynomial of a Salem number $\tau<1.3$ [n]. The table stores the monic
> minimal polynomial $m_a(x)\in\mathbb{Z}[x]$ of $\tau$.

This has three problems:

- **"Half of a polynomial" is not defined.** It becomes precise only in the
  parameter's constraint and in Formula (1), further down the page.
- **"Reciprocal minimal polynomial" can be misread.** It can mean "the
  reciprocal of the minimal polynomial". What is meant is that the minimal
  polynomial *is* reciprocal.
- **The first sentence describes the index, not the object.** "Salem number"
  itself is left to Wikipedia. Two people could still build the same table,
  but only after reading T284's Definition or the formula.

The smallest fix is to define the object first and the index second, using
T284's own definition sentence:

> A Salem number is an algebraic integer $\tau>1$ whose other conjugates have
> absolute value at most $1$, with at least one on the unit circle. The table
> stores the minimal polynomial $m_a(x)\in\mathbb{Z}[x]$ of each Salem number
> $\tau<1.3$. It is monic and reciprocal of even degree $d$, so it is
> determined by its coefficients $a=(a_0,\ldots,a_{d/2})$ of
> $x^d,\ldots,x^{d/2}$, which index the rows.

Finding 2 covers the link.

### 2. "Salem number" in the Definition should link to T284, not only to Wikipedia (worth doing)

The corpus holds this exact family: T284 is the table of the Salem numbers
$\tau<1.3$ whose minimal polynomials this table stores. The skill prefers a
table here to an encyclopedia link for the same thing, and asks for the first
mention in each section to be linked. The Definition links Wikipedia, and the
table is not linked until the Comments. The audit does not see it because the
phrase differs from the title.

Fix: `HREF{Salem_numbers_less_than_1_3}[Salem number] $\tau<1.3$`. If the
Wikipedia citation is still wanted, it can stay beside the link.

### 3. The Sac-Épée reference is listed but never cited, and its author's name has lost its accent (worth doing)

References [1], "J.-M. Sac-Epee, Salem numbers less than 49/37", is cited
nowhere in T301. It was copied from T284, where `complete-note` cites it for
the later search that found all 47 again. T301's `complete-note` dropped that
clause and kept the reference, so the reference is now uncited. T284 spells
the name "Sac-Épée"; T301 has "Sac-Epee".

Fix: restore the clause in `complete-note` (see finding 4), which gives [1] a
citation, and write the name "Sac-Épée".

### 4. `complete-note` ends with "and the one degree-46 entry is also included" (worth doing, small)

It renders as:

> Table is complete: no (it holds the minimal polynomials of the 47 known
> Salem numbers below 1.3 in Mossinghoff's list [5]; the list is proved
> complete through degree 44 [2], and the one degree-46 entry is also
> included)

"Also included" suggests that the degree-46 polynomial was added on top of
the 47, but it is one of them. What a reader needs is the fact T284 states:
the degree-46 entry lies outside the proven range. Suggested wording, matching
T284:

> it holds the minimal polynomials of the 47 known Salem numbers below $1.3$
> in Mossinghoff's list CITE{Mossinghoff}. The list is proved complete for
> degree at most $44$ CITE{MRW}. The one degree-$46$ entry lies outside that
> range, and a later search by another method found all 47 again and no
> others below $1.3$ CITE{SacEpee}

### 5. Row 1 is Lehmer's polynomial, and nothing on the page says so (worth doing)

Many readers who hold one of these polynomials will be holding
$x^{10}+x^9-x^7-x^6-x^5-x^4-x^3+x+1$. On this page its row looks like the
other 46. The Keywords carry "Lehmer number", so a text search finds the
table, but the row does not tell that reader what they have. T284's first row
does say it.

Fix: row 1's comment could read "This is Lehmer's polynomial; its root
HREF{Salem_numbers_less_than_1_3#1,1,0,-1,-1,-1}[$\tau$] greater than $1$ is
Lehmer's number, the smallest known Salem number." "Lehmer polynomial" could
also go into `Keywords`.

### 6. The two Comments are notes about sources and navigation, and do not say how the rows are ordered (worth doing if the Comments are touched anyway)

> The entries here are the reciprocal monic polynomials determined by those
> half-lists.

> The parameter is the same coefficient half-list used by the Salem-number
> table. Each entry comment links to the matching root there.

- "Half-lists" is the generator's word. The page has not introduced it.
- `comment-source` repeats what `rigour details` already says: the list is
  parsed and the polynomials are rebuilt from it.
- "Each entry comment links to the matching root there" describes the
  website, not the mathematics.
- The caption "the Salem-number table" is not T284's name.
- The one fact the Comments leave out is the ordering. The rows are in
  increasing order of $\tau$, which T301's page cannot show, because it has no
  column of $\tau$.

Smallest fix: replace both comments with one sentence, for example "Rows are
in increasing order of the Salem number $\tau$, and each row has the same
index as its row in HREF{Salem_numbers_less_than_1_3}[Salem numbers less than
$1.3$], which gives $\tau$ to 100 digits." The provenance can stay where it
already is, in `rigour details`.

### 7. The parameter title says "leading coefficients", and the column reads `coefficients` (noted only)

The Parameters line renders as "coefficients — leading coefficients of the
minimal polynomial (the coefficients $a_0,\ldots,a_{d/2}$ of
$x^d,\ldots,x^{d/2}$ …)".

- "Leading coefficient" usually means the single top coefficient, which is
  always 1 here. "The coefficients of $x^d,\ldots,x^{d/2}$" is exact.
- The index column is headed by the word `coefficients`, while the value
  column and the Definition call the tuple $a$. A `display` of `$a$` would tie
  the header $m_a(x)$ to the rows.

Neither misleads, and T284 uses the same parameter block. If this is changed,
change it in both tables.

comments could link to the T301 row instead, and T284's `Similar tables`
could name T301. That is a change to T284, noted here for whoever publishes
