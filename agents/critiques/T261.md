# T261 critique: Hall–Littlewood polynomials $P_\lambda(x_1,\dots,x_n;t)$

Read 2026-09-16. T261 is a private draft — `/T261` answers 404 to anybody,
with a key or without — so it was read through `GET /api/table?id=T261` and
rendered in five `/preview?table=` pieces, which is the only rendering of it
available from outside. It holds 33 entries, one polynomial in
$\mathbb{Z}[x_1,\dots,x_n,t]$ for each $n$ from 1 to 4 and each partition
$\lambda$ with $1\leq|\lambda|\leq4$ and $\ell(\lambda)\leq n$; type `Z[]`,
rigour `exact`, `complete: no` with a note giving the range and the reason for
it.

`GET /api/table/T261/audit` reports `{"findings": [], "clean": true}`. I agree
with the verdict on every rule it has except one: finding 1 below is a rule it
holds (`_prose_faults`, "a link sitting after the name") and misses here,
because the check matches the target's title exactly and the prose writes it
in the singular. That is the same class of miss as finding 6 of the T260
critique. Finding 6 below is also a rule it holds and deliberately skips,
because the rule is gated on the table being published and this one is not.

**The mathematics of this table is in good order and I found nothing wrong
with a value.** What I found is in the prose and in two places that only the
rendered page shows.

The things I checked hardest all held.

*Every stored row is Sage's own Hall–Littlewood $P$, character for character.*
All 33 rows were recomputed from `SymmetricFunctions(QQ(t)).hall_littlewood().P()`
and moved into $\mathbb{Z}[x_1,\dots,x_n,t]$; 33 agree as polynomials and 33
agree as strings, so the stored text is the printed form of the ring the table
says it uses, with no term-order drift.

*The entry set is exactly the rule the table states.* 4, 8, 10 and 11 rows for
$n=1,2,3,4$: every partition of 1 through 4 with at most $n$ parts, and no
others.

*The two character counts in the completeness note are right.* Sage gives
$P_{(4)}$ at $n=5$ as 2493 characters and $P_{(5)}$ at $n=4$ as 2114, exactly
as the note says, against a longest stored entry of 1080 characters
($P_{(4)}$ at $n=4$). A range argument that quotes numbers is worth more than
one that does not, and these are numbers a reader can reproduce.

*The TeX typesets.* All 43 `$...$` fragments in the prose, parameters, header
and completeness note went through MathJax with the `base` and `ams` packages
— what `tex-svg.js`, the file this site loads, carries — with 0 errors; a
control pair (an unclosed brace, an undefined macro) raised 2. No "Math input
error" is waiting on this page, no `<` eats a section, and no parameter
renders as `argument ()`.

*A reader holding one of these polynomials can find it whatever they call
their variables.* All 33 values parse with the site's own
`utils.numbers.polynomial.parse_polynomial`, and its canonical key is blind to
variable names and to which variable is which: `-x1*x2*t + x1^2 + x1*x2 + x2^2`,
`-x*y*z + x^2 + x*y + y^2` and `-a*b*t + a^2 + a*b + b^2` all produce the same
key. So the reader does not have to guess that the indeterminate is called $t$
and the variables $x_1,\dots,x_n$.

*It is one table.* $n$ is an argument, not a name — one family of symmetric
polynomials at four truncations — and $\lambda$ says what the number is of.
The value column is headed `$P_\lambda(x_1,\dots,x_n;t)$`, a symbol true of
all 33 rows, not the word `value`. Neither parameter carries `param-latex`,
which is right, because both their values are shown as themselves.

*The committed `generators/hall-littlewood-polynomials/table.yaml` matches the
live document field for field.*

Eight things are left. Six are worth doing. Two more are noted only because I
noticed them, and a short list at the end is smaller than that.

---

## 1. Formulas (2) and (3) print a slug where they mean a name

This is the one a reader meets first, and it exists only in the rendering.
Formulas (2) and (3) come off the page as

> (2) $P_\lambda(x;0)=s_\lambda(x)$, the Schur polynomial **Schur_polynomials**.
>
> (3) $P_\lambda(x;1)=m_\lambda(x)$, the monomial symmetric polynomial
> **Monomial_symmetric_polynomials**.

The bold words are the link text. The stored prose is
`the Schur polynomial HREF{Schur_polynomials}.`, an `HREF` with no `[caption]`,
and the renderer uses the target as the caption when none is given
(`caption = ref`). So an address with an underscore in it is set in running
English, twice, in the two formulas most likely to be read.

The smallest fix is to move the link onto the name it belongs to, which is
also what the skill asks for:

    formula-schur:    $P_\lambda(x;0)=s_\lambda(x)$, HREF{Schur_polynomials}[the Schur polynomial].
    formula-monomial: $P_\lambda(x;1)=m_\lambda(x)$, HREF{Monomial_symmetric_polynomials}[the monomial symmetric polynomial].

Why the audit passed it: its check looks for the target's bare title
immediately before the `HREF`, and the titles are "Schur polynomials" and
"Monomial symmetric polynomials" while the prose writes "the Schur polynomial"
and "the monomial symmetric polynomial", singular. Written in the plural, both
would have been caught.

## 2. The $\lambda$ parameter has no title, so the page says "Unknown type"

The parameter list renders

> $n$  —  number of variables (a positive integer)
>
> $\lambda$  —  **Symbolic (Unknown type)** (a partition with at most $n$ parts)

The second line has an internal type name and an apology where the first line
has a description. The document's `Parameters.lambda` has `type`, `display`
and `constraints` but no `title`, and the page falls back to the type when
there is none.

The fix is one line, and its two sibling tables already say what to write:
T259 and T260 both give their partition parameter `title: shape`. With that,
the line reads "$\lambda$ — shape (a partition with at most $n$ parts)".

## 3. The definition names the object rather than defining it

> The Hall–Littlewood polynomial $P_\lambda(x_1,\dots,x_n;t)$ [2] is
> Macdonald's $P$-normalised Hall–Littlewood symmetric polynomial [1] for a
> partition $\lambda$ with at most $n$ parts.

A reader who does not already know what a Hall–Littlewood polynomial is
learns, from the definition, that it is a Hall–Littlewood polynomial. The
`convention` comment closes the same circle a second time: "This is the
$P_\lambda$ normalisation of Macdonald." Two people could not build this table
from its definition; they could from formula (1), but nothing sends them
there.

There are two fixes and they are not exclusive. The minimal one is to point at
the formula that does the defining, `given by CITE{formula-symmetrization}`,
which renders as "(1)" and costs four words. The better one is to say what the
$P$ normalisation *is*, in the one clause that distinguishes it from $Q$ and
$Q'$: $P_\lambda$ is the one that is monic in dominance order,

> $P_\lambda = m_\lambda + \sum_{\mu<\lambda} u_{\lambda\mu}(t)\,m_\mu$,
> the sum over partitions strictly below $\lambda$ in dominance order

which has the advantage that a reader can check it against any row on the
page. I checked it against all 33: every stored value is $m_\lambda$ plus a
$t$-combination of strictly lower $m_\mu$, with no exceptions. Since formula
(3) already names $m_\lambda$ and links the monomial symmetric polynomials,
the notation is on the page already.

## 4. The `convention` comment says something false about $Q'_\lambda$

> The $Q_\lambda$ and $Q'_\lambda$ normalisations multiply these polynomials
> by factors depending on $\lambda$ and $t$.

True of $Q_\lambda$, which is $b_\lambda(t)P_\lambda$ with
$b_\lambda(t)=\prod_{r\geq1}\prod_{j=1}^{m_r(\lambda)}(1-t^j)$. Not true of
$Q'_\lambda$, which is not a multiple of $P_\lambda$ at all. Expressed in the
$P$ basis by Sage:

    lambda = [1,1]   Q  = (t^3-t^2-t+1) P[1,1]                one term
                     Q' = (t^2+1) P[1,1] + t P[2]             two terms
    lambda = [2,2]   Q  = (t^3-t^2-t+1) P[2,2]                one term
                     Q' = (t^8+t^6+t^5+2t^4+t^2) P[1,1,1,1]
                          + (t^5+t^3+t^2+t) P[2,1,1]
                          + (t^4+t^2+1) P[2,2]
                          + (t^3+t) P[3,1] + t^2 P[4]         five terms

A reader who believes the sentence and wants $Q'_{(2,2)}$ from the row in
front of them gets the wrong symmetric function, and the table gives them no
way to notice.

The smallest honest fix is to split the sentence and let $Q'$ be what it is:

> $Q_\lambda=b_\lambda(t)P_\lambda$ is the same polynomial up to a factor
> depending on $\lambda$ and $t$. $Q'_\lambda$ is not: it is the plethystic
> transform $Q'_\lambda(x;t)=Q_\lambda[x/(1-t);t]$, and its expansion
> $Q'_\mu=\sum_\lambda K_{\lambda\mu}(t)s_\lambda$ has the same
> HREF{T259}[Kostka-Foulkes polynomials] as CITE{formula-transition}.

(That last expansion is what Sage returns as well: $Q'_{(2,2)} = s_{22} + t\,s_{31} + t^2 s_4$.)
If a shorter sentence is wanted, dropping $Q'_\lambda$ from the comment
altogether is better than the present claim.

While in that comment: it opens "The parameter $t$ is an indeterminate", and
$t$ is the one symbol in the title that is *not* a parameter of this table.
The Parameters section lists $n$ and $\lambda$, so a reader sent looking for
$t$ there finds nothing. "$t$ is an indeterminate" says the same thing without
sending them.

## 5. Formula (1) uses $m_r(\lambda)$ and $\ell(\lambda)$ without defining them

> $v_\lambda(t)=\prod_{r\geq0}\prod_{j=1}^{m_r(\lambda)}(1-t^j)/(1-t)$ and
> $m_0(\lambda)=n-\ell(\lambda)$.

The formula defines $m_0$ and leaves $m_r$ and $\ell$ to be guessed. The guess
is available — $m_r(\lambda)$ has to be the number of parts equal to $r$ for
$m_0(\lambda)=n-\ell(\lambda)$ to make sense — but a reader has to make it,
and the letter is working against them: $m$ is the monomial symmetric
polynomial two formulas later, in formula (3), and $m_\lambda$ is the title of
the table that formula links to.

One clause fixes it: "where $m_r(\lambda)$ is the number of parts of $\lambda$
equal to $r$, $\ell(\lambda)$ is the number of nonzero parts, and
$m_0(\lambda)=n-\ell(\lambda)$ counts the zeros added by the padding". The
collision with $m_\lambda(x)$ is then visible rather than latent, and if it is
thought worth avoiding, Macdonald's other letter for the multiplicity is
available.

## 6. Three links point at T259, which is a private draft

`formula-transition`, `Similar tables` and `rigour details` each link
`HREF{T259}`, the Kostka–Foulkes polynomials. `/T259` answers 404 to
everybody. If T261 is published before T259, a reader following any of the
three lands on a not-found page, and the page they are sent from is the one
that tells them what the coefficients in formula (4) are.

Nothing in the table needs changing; this is a note for whoever reviews it.
The audit has exactly this check —

    HREF{%s} points at a draft, which answers 404 to everybody;
    a published table must not link to one

— and skips it here because it is gated on `table.published`, which is false
for a draft. It will fire the moment T261 goes public, which is after the
decision it should inform. Publish T259 first, or publish the two together.

## 7. The `Programs` block opens with an import that looks like a mistake and is not

    import sage.rings.polynomial.laurent_polynomial_ring
    from sage.combinat.sf.sf import SymmetricFunctions
    ...

The first line imports a module the block never uses. A reader tidying it away
gets `ImportError: cannot import name Category` from a line that has nothing to
do with Laurent polynomials — I removed it and that is what happened. It is
load-bearing: importing Sage submodules into a fresh interpreter starts the
Sage import graph part-way through, and this line pushes it past the point
where it breaks.

It is also avoidable. `from sage.all import SymmetricFunctions, QQ, PolynomialRing`
replaces all four import lines, needs no workaround, and runs both in a Sage
session and under `sage -python`; I ran that form and it returns the expected
expansion. This is a second instance of the pending lesson "A `Programs`
snippet that imports from `sage.*` submodules runs in a Sage session and not
in a Sage script" (`agents/lessons/proposals/20260916T024304Z-critique.md`),
with the wrinkle that here somebody met the failure and worked around it
rather than moving the import.

One more thing about that block, worth a clause wherever it fits. What it
prints is not what the table prints. For $\lambda=(2,1)$ at $n=3$ the
incantation returns

    x1^2*x2 + x1*x2^2 + x1^2*x3 + (-t^2 - t + 2)*x1*x2*x3 + x2^2*x3 + x1*x3^2 + x2*x3^2

and the row directly above reads

    -x1*x2*x3*t^2 - x1*x2*x3*t + x1^2*x2 + x1*x2^2 + x1^2*x3 + 2*x1*x2*x3 + x2^2*x3 + x1*x3^2 + x2*x3^2

The same polynomial: Sage expands over the fraction field of $\mathbb{Q}(t)$
and groups the coefficients in $t$, while the table stores the expansion in
$\mathbb{Z}[x_1,\dots,x_n,t]$. A reader who runs the program to check a row
has to see that for themselves. "Sage groups the coefficients in $t$; the
table writes the same polynomial expanded in $\mathbb{Z}[x_1,\dots,x_n,t]$"
would save them the minute.

## 8. The completeness note promises the empty partition

> it holds every $P_\lambda$ with $1\leq n\leq4$, $|\lambda|\leq4$, and
> $\ell(\lambda)\leq n$

$\lambda=\varnothing$ satisfies all three conditions, $P_\varnothing=1$, and
the table does not hold it — the generator enumerates $|\lambda|$ from 1. The
sentence is the one a reader checks their own case against, so it should be
true of it: `$1\leq|\lambda|\leq4$`.

Nobody arrives holding the polynomial 1 and wants to know what it is, so the
fix is the sentence and not the entry.

## Noted only because I noticed

**The spelling is inconsistent.** The Definition and the `convention` comment
write "normalised" and "normalisation"; `Similar tables` writes
"specialization" twice. Both are correct English and the page uses one of each.

**`Keywords` carries "Macdonald Hall polynomials".** Nobody types that: it
reads like the title of Macdonald's book with "Symmetric Functions and"
removed. Keywords weigh as heavily as the title, so it also puts this table in
front of somebody searching for Macdonald polynomials, which it does not hold —
T260 does. "Macdonald Hall-Littlewood polynomials" would answer the search the
phrase was reaching for.

**Formula (4) drops an argument and a range.** `$s_\lambda=\sum_\mu
K_{\lambda\mu}(t)P_\mu(x;t)$` writes the left side without its $x$ and the
right side with it, and does not say that $\mu$ runs over the partitions of
$|\lambda|$ with at most $n$ parts. `$s_\lambda(x)=\sum_{\mu}...$, the sum
over partitions $\mu$ of $|\lambda|$ with at most $n$ parts` fixes both.

**The $\lambda$ column prints "2, 1" and the notation comment writes
"$2,1,1$".** The space is the site's, not the author's, and the entry key — the
thing a citation resolves on, `HREF{slug#3,2,1}` — has no space in it. Nothing
to do unless somebody wants the comment to match the column it explains.
