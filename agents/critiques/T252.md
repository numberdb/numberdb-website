# T252 critique: Clebsch-Gordan coefficients and Wigner $3j$ symbols

Read 2026-09-15. T252 is a private draft. It holds 586 real values at 293
parameter tuples $(j_1,j_2,j_3,m_1,m_2,m)$ with every $j\leq2$: each tuple
carries both the Clebsch-Gordan coefficient and the Wigner $3j$ symbol,
selected by a parameter `normalisation`. Rigour `proven`, 100 significant
digits, exact rationals written exactly. No entry has a comment.

**The numbers are right and the page renders.** The three things I checked
hardest all held: the row set is *exactly* the nonzero set in range (293 of the
303 tuples the stated rules admit — see finding 1, which is about the prose
that describes this, not about the rows); all 44 TeX fragments typeset under
MathJax 3; and every `CITE` and `HREF` resolves, with both `Similar tables`
slugs answering 200 on the live site.

What is wrong is prose about the mathematics, and one snippet that tells a
reader the opposite sign of what the table holds.

- **1 and 2 are worth doing and are the reason to open the file.** One
  comment states something that is false of this table, and the `Programs`
  snippet contradicts the table's own row.
- **3 to 5 are worth doing**: the definition does not define, the row label is
  a 2×3 matrix printed 293 times, and the selection rule is written in symbols
  the table does not use.
- **6 to 9 are small** and worth doing while the file is open.
- **The notes at the end are there only because I noticed them.**
- **On the audit's one finding I agree with the rule and disagree with
  splitting.** See "What `audit_table` says" below.

## What `audit_table` says

One finding, and it is this:

> parameter normalisation takes 2 names (clebsch-gordan, wigner-3j) and every
> other parameter repeats under each of them, so this reads as 2 tables sharing
> one title and one value column. If those are 2 named quantities, make 2
> tables and relate them in Similar tables; if they are one object in several
> parts, or one number in several conventions, say so in the definition and
> leave them together.

The structural description is exactly right: all 293 tuples carry both names,
none carries one. So the rule fired correctly.

**I do not think it should be split, and I think the answer the audit asks for
is already on the page.** The skill names this case: "Where two entries are one
object in two conventions, one table", with $\beta$ and $e^\beta$ for Lévy's
constant as the example. Here the two values at a row differ by the single
nonzero factor $(-1)^{j_1-j_2+m}\sqrt{2j_3+1}$, which the table states in
`formula-cg` — one number rescaled, not two quantities. A physicist holding
$0.8660254\ldots$ may have got it from either convention and should land in the
same place, and on the rendered page they do: the two rows sit one above the
other under the same six parameters. And the first sentence of the Definition
already says "two normalisations of the same angular-momentum coupling
coefficient", which is the sentence the audit asks for.

The one thing that does point the other way is the value-column header, which
falls back on "or" — the skill's tell for a column with no symbol true of every
row. But here every row carries its own symbol in the `normalisation` column,
so the header is restating what the rows already say. That is finding 4, and it
is a wording problem rather than evidence of two tables.

## 1. `comment-zeros` says the selection rules determine which rows are absent. They do not — ten rows in range vanish that those rules allow

What a reader sees, in Comments:

> Rows whose coefficient is zero are omitted. The selection rules in (1)
> determine those values.

So a reader who wants to know whether a missing row is missing or zero reads
`formula-selection`, applies it, and expects the rows it admits to be present.

Why it is wrong. The rules written in `formula-selection` are necessary and not
sufficient, and the gap is not small. Enumerating every tuple with
$j_1,j_2,j_3\leq2$ that satisfies every condition that formula states:

    tuples satisfying every rule in formula-selection: 303
    of those, zero anyway: 10
    of those, nonzero (should be rows): 293
       zero: ('1', '1', '1', '0', '0', '0')  J = 3
       zero: ('1', '2', '2', '0', '0', '0')  J = 5
       zero: ('3/2', '3/2', '2', '-1/2', '-1/2', '-1')  J = 5
       zero: ('3/2', '3/2', '2', '1/2', '1/2', '1')  J = 5
       zero: ('3/2', '2', '3/2', '-1/2', '1', '1/2')  J = 5
       zero: ('3/2', '2', '3/2', '1/2', '-1', '-1/2')  J = 5
       zero: ('2', '1', '2', '0', '0', '0')  J = 5
       zero: ('2', '3/2', '3/2', '-1', '1/2', '-1/2')  J = 5
       zero: ('2', '3/2', '3/2', '1', '-1/2', '1/2')  J = 5
       zero: ('2', '2', '1', '0', '0', '0')  J = 5

(`agents/sage.sh`, `wigner_3j` on all 303.) The table holds exactly the 293
nonzero ones — I checked set equality against the document, not just the count
— so **the rows are right and only the sentence describing them is wrong**.

The ten split into two kinds, and neither is covered:

- Four have $m_1=m_2=m=0$ with $j_1+j_2+j_3$ odd. That vanishing is a standard
  rule and it is in the section the table already links: DLMF 34.3.5 says the
  symbol is $0$ when $J=j_1+j_2+j_3$ is odd. `formula-selection` omits it.
- Six are non-trivial zeros with $m\neq0$, such as
  $\begin{pmatrix}3/2&3/2&2\\-1/2&-1/2&1\end{pmatrix}=0$. No selection rule
  predicts these. Adding one more rule cannot fix the sentence.

DLMF 34.2 is careful about this and says only one direction: "If either of the
conditions (34.2.1) or (34.2.3) is not satisfied, then the 3j symbol is zero."
The comment turns that into an "if and only if" the source does not claim.

Smallest change: rewrite `comment-zeros` to say what is true, which is also
more useful than what it says now —

> Rows whose coefficient is zero are omitted. The selection rules in (1) are
> necessary and not sufficient: of the 303 parameter tuples in range that
> satisfy them, 293 are here and ten vanish anyway — four because
> $m_1=m_2=m=0$ with $j_1+j_2+j_3$ odd, and six as non-trivial zeros of the
> $3j$ symbol, the smallest being
> $\begin{pmatrix}3/2&3/2&2\\-1/2&-1/2&1\end{pmatrix}$.

Worth doing. It is the one sentence on the page that would send a careful
reader to a wrong conclusion about the data.

## 2. The `Programs` snippet's two answers both have the wrong sign, and contradict the table's own row

What a reader sees, in Programs:

    from sage.functions.wigner import clebsch_gordan, wigner_3j

    clebsch_gordan(1, 1, 1, 1, 0, 1)     # -sqrt(1/2)
    wigner_3j(1, 1, 1, 1, 0, -1)         # sqrt(1/6)

Why it is wrong. Run under `agents/sage.sh`, Sage answers:

    clebsch_gordan(1,1,1,1,0,1) = sqrt(3)*sqrt(1/6) = 0.70710678118654752440
    wigner_3j(1,1,1,1,0,-1)     = -sqrt(1/6)        = -0.40824829046386301637

Both comments are the negative of the truth. And the table itself agrees with
Sage, not with the snippet: at $(j_1,j_2,j_3,m_1,m_2,m)=(1,1,1,1,0,1)$ the
document stores

    clebsch-gordan: 0.70710678118654752440...
    wigner-3j:     -0.40824829046386301637...

So a reader who runs the two lines the table gives them, to get "one more
value", sees a number whose sign disagrees with the comment beside it, and
whose sign agrees with the table. The two comments are consistent with each
other — they are related by `formula-cg` — which is how a single wrong sign at
the $3j$ propagated into both without looking wrong.

Smallest change: fix the two comments.

    clebsch_gordan(1, 1, 1, 1, 0, 1)     # sqrt(1/2)
    wigner_3j(1, 1, 1, 1, 0, -1)         # -sqrt(1/6)

Worth doing, and it is the finding I would fix first if only one were fixed:
`rigour details` says every row was checked against Sage, and this is the one
place on the page where a reader can check that claim themselves.

## 3. The Definition says how the two are related. It never says what either one is

What a reader sees:

> Clebsch-Gordan coefficients and Wigner $3j$ symbols are two normalisations of
> the same angular-momentum coupling coefficient. This table uses the DLMF
> Wigner convention [1] and the Condon-Shortley phase convention, with the row
> relation in (2).

Why it is wrong. The skill's table of sections gives Definition "one or two
sentences saying what the object *is*", and Comments the conventions. Here the
first sentence states a *relation* between the two names, and names the thing
by a longer name — "angular-momentum coupling coefficient" — without saying
what it is a coefficient *of*. The second sentence is two conventions, which
have a home in Comments. A reader who arrives holding $0.8660254\ldots$ from a
calculation learns from the whole page that their number is indexed by six
angular momenta, and never learns what quantity it is.

Nor is it recoverable from `Formulas`: `formula-selection` says when the symbol
is zero, `formula-cg` converts one normalisation to the other, and
`formula-orthogonality` and `formula-legendre` are properties. Nothing on the
page evaluates anything. `rigour details` names "the Racah finite sum", which
is DLMF 34.2.4 and is the closed form a reader would want, and never gives it.

Smallest change: one sentence saying what the coefficient is, keeping the
sentence the audit wants —

> The Clebsch-Gordan coefficient $\langle j_1m_1,j_2m_2\mid j_3m\rangle$ is the
> coefficient of $|j_1m_1\rangle|j_2m_2\rangle$ in the coupled state
> $|j_3m\rangle$ of two angular momenta $j_1$ and $j_2$; the Wigner $3j$ symbol
> is the same coefficient in a symmetric normalisation (2).

and move "This table uses ... Condon-Shortley phase convention" to a comment,
where it sits beside `comment-indexing`, which is already about conventions.
Adding DLMF 34.2.4 as a `formula-racah` would let a reader recompute a row;
that is worth doing too, and is the formula `rigour details` already leans on.

## 4. The label on every `wigner-3j` row is a 2×3 matrix of letters, printed 293 times beside the letters' values

What a reader sees, in the seventh column of the numbers table:

    1/2  3/2  2  -1/2  -1/2  -1   ⎛j₁ j₂ j₃⎞:   0.38729833462074168851...
                                  ⎝m₁ m₂ -m⎠

The row's six numbers are in the six columns to the left; the label repeats
their names. It also restates the value-column header, which reads
`$\langle j_1m_1,j_2m_2\mid j_3m\rangle$ or
$\begin{pmatrix}j_1&j_2&j_3\\m_1&m_2&-m\end{pmatrix}$` — both symbols, again.

Why it is wrong. The mechanism is right: the skill says a parameter whose
values are words should show a symbol, and gives `normalisation: relative`
shown as `$\operatorname{vol}_{\mathrm{rel}}(B_5)$`. What is wrong is the size.
Typeset with MathJax:

| label | width | height |
|---|---|---|
| `$\langle j_1m_1,j_2m_2\mid j_3m\rangle$` | 18.3 ex | 2.26 ex |
| `$\begin{pmatrix}j_1&j_2&j_3\\m_1&m_2&-m\end{pmatrix}$` | 17.6 ex | 5.43 ex |
| `$j_1$` | 1.9 ex | 1.96 ex |
| `-1/2` | 5.2 ex | 2.26 ex |

The site's own CSS carries a comment about exactly this: a named parameter
value "could not break, so it set the width of the whole column and pushed the
digits out of the half of the page the numbers get". MathJax typesets each of
these into one unbreakable element three times the width of the widest
parameter column, in a numbers panel that is `calc(50% + 1.5rem)` on a wide
screen, beside values that are 100 characters long. The matrix additionally
makes each of its 293 rows 5.43 ex tall, about two and a half times a normal
row.

Smallest change: shorten the two labels, keeping the full symbols in the
Definition and `formula-cg` where a reader reads them once.
`$\langle\,\cdot\,\rangle$` is 3.1 ex × 2.26 ex and
`$\bigl(\begin{smallmatrix}\cdot&\cdot&\cdot\\\cdot&\cdot&\cdot\end{smallmatrix}\bigr)$`
is 4.9 ex × 2.71 ex; both typeset under `base` and `ams` alone, which the page
already loads. Dropping the `values:` map altogether is smaller still and
leaves the column reading `clebsch-gordan:` and `wigner-3j:` — short wrapping
words the document already uses in the Definition, the constraint and the
snippet.

Worth doing. The reading cost is on every row of the table.

## 5. `formula-selection` is three chained "unless"es, in symbols the table does not have

What a reader sees:

> The Wigner symbol is zero unless $|j_r-j_s|\leq j_t\leq j_r+j_s$ for every
> permutation of $1,2,3$, unless $m_1+m_2+m_3=0$, and unless $|m_i|\leq j_i$
> with $j_i-m_i\in\mathbb{Z}$ for each $i$ [1].

Two things a reader has to guess.

**The grammar.** "zero unless A, unless B, and unless C" does not say whether
the symbol is zero when only one of them fails. It is: all three must hold. The
skill asks that a field read as English, and this one reads as a list of three
exceptions to a claim, joined in a way that leaves the quantifier open.

**The symbols.** The table's six parameters are $j_1,j_2,j_3,m_1,m_2,m$. This
formula uses $j_r,j_s,j_t$, $m_1+m_2+m_3$, and $m_i$/$j_i$ "for each $i$".
$m_3$ is never defined anywhere on the page. It is $-m$ — `comment-indexing`
explains that the lower row of the symbol holds $-m$, but never writes
$m_3=-m$, so a reader checking a row against this condition computes
$m_1+m_2+m$ and finds it is $2m$, not $0$. The symbols come from DLMF 34.2,
which is where the citation points, but the table's own parameters are the ones
the reader has in front of them.

Smallest change: write it as a list in the table's symbols, and add the rule
finding 1 needs:

> The Wigner $3j$ symbol is zero unless all of the following hold:
> $|j_1-j_2|\leq j_3\leq j_1+j_2$; $m=m_1+m_2$; $|m_1|\leq j_1$,
> $|m_2|\leq j_2$ and $|m|\leq j_3$, with $j_1-m_1$, $j_2-m_2$ and $j_3-m$ all
> integers; and, when $m_1=m_2=m=0$, $j_1+j_2+j_3$ even [1], [2].

Worth doing. Findings 1 and 5 are the same field read twice and should be
fixed together.

## 6. The parameter list reads "normalisation — normalisation"

What a reader sees, under Parameters:

    $j_1$          —  first angular momentum (...)
    ...
    normalisation  —  normalisation (either clebsch-gordan or wigner-3j)

Why it is wrong. Every other row is a symbol, then what it means. This one
prints the same word twice with a dash between, because `display` and `title`
are both `normalisation`. The skill's rule about a label that repeats the
heading above it is the same shape: the second copy carries nothing.

Smallest change: give the `title` something to say — `which of the two
normalisations the row gives` — and leave `display` as it is, since it is the
column heading and is right there.

Small, and worth doing while the file is open.

## 7. The triangle inequality is stated three times, once under each of $j_1$, $j_2$, $j_3$

What a reader sees: three consecutive parameter lines each ending "and
$j_1,j_2,j_3$ satisfy the triangle inequalities". It is one joint condition on
three parameters, and it is not a constraint on $j_1$ separately at all.

Smallest change: leave $j_1$ and $j_2$ reading "$j_1$ is a nonnegative integer
or half-integer", and state the triangle condition once — under $j_3$, which is
the coupled momentum it constrains, or in `formula-selection`, which already
states it.

Small.

## 8. The title given for DLMF 34.3(vii) describes a different section

What a reader sees, in Links:

> [2] DLMF 34.3(vii): Wigner 3j symbol product formulas

Why it is wrong. §34.3(vii) is headed "Relations to Legendre Polynomials and
Spherical Harmonics", which is what the table cites it for in
`formula-legendre`. "Product formulas" would be §34.3(vi), "Sums". A reader who
follows the link to look for a product formula finds Legendre polynomials.

Smallest change: `DLMF 34.3(vii): relations to Legendre polynomials and
spherical harmonics`.

Small.

What a reader sees:

Small.

## Noted only because I noticed

- **"the Wigner symbol"** appears in `formula-selection` and `comment-indexing`
  without the $3j$. DLMF chapter 34 is "3j, 6j, 9j Symbols", so a bare "Wigner
  symbol" is three things. The title gets it right.
- **Four notations for the same six indices.** `formula-selection` uses
  $j_r,j_s,j_t,m_i,m_3$; `formula-orthogonality` uses $j,m,j',m'$;
  `formula-legendre` uses $l_1,l_2,l_3$ and $m_i$; the parameters are
  $j_1,j_2,j_3,m_1,m_2,m$. Each is defensible on its own — $l_i$ is right for
  orbital angular momentum, and a primed $j'$ is needed in an orthogonality
  sum — but a reader checking a row against the four formulas translates four
  times. The $m_3$ in finding 5 is the case where the translation is not
  guessable.
- **`comment-indexing` names a value by its key**: "The `wigner-3j` rows use
  $-m$ ...". The skill's rule is about parameter keys, and this is a value key,
  but the same reasoning applies — `wigner-3j` is how the document addresses
  those rows and "the Wigner $3j$ rows" is what a reader would say.
- **`complete-note` gives the range without its reason.** "every nonzero
  Clebsch-Gordan coefficient ... with $j_1,j_2,j_3\leq2$" is exactly true — I
  checked it by enumeration — but nothing says why 2. If the reason is that
  $j\leq2$ is the range the standard printed tables cover, that is a sentence
  a reader would use.
- **`comment-algebraic` understates what it knows.** "a rational multiple of a
  square root of a rational" is true, and so is the sharper statement: every
  value is $\pm\sqrt{q}$ for a rational $q$, so a reader holding one of these
  numbers can square it and get a rational. That is the most useful thing the
  page could tell somebody who arrived from a calculation.
- **The first screen is the trivial coupling.** Entries render in document
  order, so the table opens on the $j_1=0$ rows, where the Clebsch-Gordan
  coefficient is $1$ on every one of them. That is the smallest case, which is
  the rule the skill gives, so I would not change it; but the first thing a
  reader sees is a column of ones.
- **Keywords** could carry "vector coupling coefficient" and "Wigner
  coefficient", both common names for the same number, neither a substring of
  anything already there.
- **`formula-cg` cites Sage's documentation** for a standard identity that is
  also in DLMF. Not wrong — the generator did take it from there — but [1] is
  the better citation for a reader.
