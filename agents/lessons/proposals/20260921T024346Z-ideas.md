# Lessons from the ideas run of 2026-09-21T02:43Z

Proposing root numbers, Satake angles and finite-field Gauss sums
(`BATCH-2026-09-21T0243.md`). Four things the skill does not say, each of
which a contributor with a laptop and Sage would hit.

## A `ComplexBall` has no `.str(digits=...)`; a `RealBall` does

What happened: a checking script printed balls with
`value.str(digits=12)`, which is what the skill's own examples suggest for
real balls, and every complex value raised

    AttributeError: 'sage.rings.complex_arb.ComplexBall' object has no
    attribute 'str'

on a full SageMath, not only on a modular passagemath. The fix is `str(x)`,
or `x.real().str(digits=n)` on the parts. It cost a whole container run,
because the script had already done the expensive part before printing.

What the skill says now: that a modular passagemath does not bring
`RealBall.str`. It does not say that `ComplexBall` has no `str` at all, and
a table of complex values -- 4 of the corpus's types are complex -- is where
this bites.

What it should say: print balls with `str(x)`; `str(digits=)` is a
`RealBall` method, and on a `ComplexBall` you must take `.real()` and
`.imag()` first.

Evidence: 2026-09-21 run, `agents/sage.sh` on a script computing
$\varepsilon(\chi)$ in `ComplexBallField(200)`.

## `table(...)['Numbers']` is nested one level per parameter, not keyed by the citation string

What happened: a script read T217 and looked for entries under the key
`'23.2.a.a,2'` -- the comma-joined form a citation uses, and the form
`HREF{slug#entry}` takes. There is no such key. `Numbers` is a dict of dicts,
one level per parameter in the table's parameter order:

    numberdb.table('T217')['Numbers']['23.2.a.a']['2']  ->  'x^2 + x - 1'

and the inner keys are strings, so `sub[2]` raises and `sub['2']` works. The
failure is a `KeyError` on a plausible key, which reads like the entry is
missing rather than like the shape is different.

What the skill says now: that `Numbers` is every entry and that printing it
is megabytes. Nothing about its shape.

What it should say: `Numbers` nests one dict level per parameter, in the
declared parameter order, with string keys; the comma-joined form is the
*citation* address, not a key of this dict.

Evidence: same run, cross-checking Satake angles against T217's stored Hecke
polynomials.

## `source_names_it` matches plurals literally, and a challenge page can pass it

What happened: two things, and the second is the one that matters.

Plurals: the name "Satake angles of weight 2 newforms" failed against a page
that writes "angle" and "newform" in the singular, because the check asks
whether each distinguishing word is a substring of the page -- "angles" is
not a substring of "angle". A proposal can be correctly named and still fail.

Worse: a source that answers with a bot-challenge page can *pass*. A
`lmfdb.org/knowledge/...` fetch returned a Google reCAPTCHA page, and the
challenge echoes the requested URL, so the slug `cmf.satake_angles` put both
"satake" and "angles" into the text the check reads. The first call reported
only "the source does not mention newforms", which reads exactly like a
source that was read. Three further calls, after the same page had been
served again with different wording, reported "does not mention satake,
angles" -- and the difference between those two answers is the only signal
that the page was never the knowl.

What the skill says now: nothing; `source_names_it` is the batch screen, not
the skill, but the failure mode is general -- any check that greps a fetched
page can be satisfied by an error page that quotes the URL.

What it should say: when a source check passes, look at the length and the
first line of what was fetched before believing it; a check that reads a page
should refuse a page that contains "recaptcha", "enable javascript" or the
requested URL and little else.

Evidence: same run; `source_names_it('Satake angles of weight 2 newforms',
'https://www.lmfdb.org/knowledge/show/cmf.satake_angles')` answered two
different ways within ten minutes, and a direct fetch of the same URL shows
an 11 kB reCAPTCHA page.

## A root number can be checked against the functional equation itself, in ball arithmetic

What happened: the obvious check on $\varepsilon(\chi)=\tau(\chi)/(i^\delta
\sqrt q)$ is $\lvert\varepsilon\rvert=1$, which is weak: it holds for every
misnormalisation that multiplies by a root of unity, which is exactly the
error to fear. The strong check is to compute the same number a second way,
from the equation it exists to satisfy:

    L(s, chi)      = q^-s * sum_a chi(a) * zeta(s, a/q)     # Hurwitz zeta
    Lambda(s, chi) = (q/pi)^((s+delta)/2) * Gamma((s+delta)/2) * L(s, chi)
    eps            = Lambda(s, chi) / Lambda(1-s, conj(chi))

with `CBF(s).zeta(CBF(a)/q)` supplying the Hurwitz zeta as a ball and $s$
taken off the real axis, $s=2+i/3$, so no trivial zero is landed on. The two
balls have to overlap. It caught nothing on 22 characters -- which is the
point: it is a check that *would* have caught a wrong $i^\delta$, and
$\lvert\varepsilon\rvert=1$ would not.

The same shape works elsewhere: anything defined as the constant in a
functional equation can be recomputed as a ratio of the two sides at one
point, and PARI offers `lfuncheckfeq(L)`, which returns the number of bits to
which that equation holds ($-254$ at `realprecision 60` for the newform
tried).

What the skill says now: "check new values against something independent --
not the code that produced them", with identities among Fibonacci and Lucas
polynomials as the example. It does not point out that a defining equation is
itself the independent check when the quantity is a constant in one.

What it should say: for a constant that appears in an identity -- a root
number, a residue, a functional equation's factor -- recompute it as the
ratio the identity gives and require the balls to overlap; a modulus or a
sign check is not that.

Evidence: same run, 22 primitive characters of conductor $q\leq13$, every one
agreeing at 200 bits.
