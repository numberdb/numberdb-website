## Parse rational strings yourself before passing them to `QQ`

What happened: the Runge-Kutta tableaux generator first stored its transcribed
coefficients as strings and converted them with `QQ(value)`. Under the named
imports used by `agents/sage.sh`, `QQ('1/2')` failed before any computation:
`AttributeError: module 'sage.rings' has no attribute 'real_mpfr'`. The fix
was to split strings at `/` and build `QQ(int(numerator)) / QQ(int(denominator))`,
or `QQ(int(value))` for integers. The dry run then computed all 219 rational
entries exactly.

What the skill says now: `QQ('1.25')` is named as a missing-machinery trap,
and it says to build a rational from a decimal string by hand.

What it should say: do not rely on `QQ` parsing strings at all in a portable
generator. Parse integer and fraction strings yourself and pass Sage integers
to `QQ`; this avoids both decimal strings and fraction strings reaching Sage
modules that named imports did not initialise.

Evidence: `agents/sage.sh /tmp/dry_run_wrapper.py agents/table-build/dry_run.py
agents/table-build/check.py generators/butcher-tableaux-explicit-runge-kutta-methods/generate.py`,
2026-09-17, first failed at `QQ('1/2')`; after the parser change it reported
`219 entries computed` and `every value is exact`.
