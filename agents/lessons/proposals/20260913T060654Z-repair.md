## Use TeX, not Sage strings, for polynomials inside `$...$`

What happened: T222 put Sage's `str()` of a polynomial into an entry comment inside `$...$`. MathJax reads `t^10` as `t^1` followed by a full-size `0`, and reads `*` as an asterisk operator. The stored values were right, but 288 entry comments rendered a different polynomial from the one the generator had computed.

What the skill says now: it says to use `$...$` for mathematics, and a pending lesson covers the `*` part of this problem, but it does not say that Sage's polynomial text is not TeX.

What it should say: when a generator writes a polynomial into prose that will be rendered as TeX, use `latex(P)` or otherwise brace exponents and remove programming operators. This matters even for exact polynomials: `x^10` is valid Sage text and wrong TeX.

Evidence: `agents/critiques/T222.md` finding 1; `/tmp/t222_print_comments.py` after the repair prints `$x^{10} + x^{9} - x^{7} - ... + 1$`, and the live API re-read has zero entry comments matching raw `t^\d{2}` or `*`.
