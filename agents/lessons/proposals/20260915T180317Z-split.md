## `Generator.verify()` cannot check a list-valued `number`

What happened: splitting T227 left the Bendersky table with one row per
index $k$, and each row stores the same constant in two conventions as
`number: [A_k, log A_k]`. The generator can return that list, and the write
path has code to write each value in the list. But running
`agents/sage.sh generators/bendersky-constants/generate.py` failed in
`Generator.verify(sample=None)` with `TypeError: cannot write list as a
number`, because the verify path called `to_text()` directly on the list.
The generator now uses an explicit checker that fetches the table and
compares both stored values in each row.

What the skill says now: "`verify()` recomputes and compares against the
stored table."

What it should say: if a table entry stores several numbers as a list,
`Generator.verify()` may not be able to check it. Until the client handles
list-valued entries in verify, add a small explicit verifier that compares
every value in the stored list, or use a labelled parameter when the values
are genuinely separate entries and that shape is mathematically right.

Evidence: T227 split, 2026-09-15. The failing command was
`cat "$NUMBERDB_KEY_FILE" | NUMBERDB_KEY_FROM_STDIN=1 agents/sage.sh
generators/bendersky-constants/generate.py`; the traceback ended at
`numberdb/_write.py`, `TypeError: cannot write list as a number`. After the
custom full-list check, the same command printed
`all stored list values match: True`.
