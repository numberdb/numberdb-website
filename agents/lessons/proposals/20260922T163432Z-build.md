## Check an `(answers #N)` issue before putting it in a table link
What happened: the family checklist for numberdb-data#185 marked the quartic
double-well eigenvalue proposal as `(answers #128)`, but
`python3 agents/queue.py show 128` and the GitHub API both showed
numberdb-data#128 as the closed issue "Monomials". The issue body did not ask
for the double-well table. Treating the checklist number alone as provenance
would have put a false "Requested in numberdb-data#128" link in the draft.

What the skill says now: when a checklist line says `(answers #N)`, put
*"Requested in numberdb-data#N"* in Links and let `queue.py built` close it.
It does not say to read that issue before using the number.

What it should say: before adding a requested-in link, read the named issue
and confirm it asks for this table. If the family checklist names an unrelated
issue, record the mismatch in the run report or a lesson and do not put a
false request link in the table.

Evidence: 2026-09-22, `python3 agents/queue.py show 128` printed `#128
Monomials` with the body `Trivial but maybe should be included? (Subset of
#102, so perhaps not needed.)`; `https://api.github.com/repos/numberdb/numberdb-data/issues/128`
returned the same title and closed state.
