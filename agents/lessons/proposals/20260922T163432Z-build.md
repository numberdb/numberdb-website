## Check an `(answers #N)` issue before putting it in a table link
What happened: the family checklist for numberdb-data#185 marked the quartic
double-well eigenvalue proposal as `(answers #128)`, but
`python3 agents/queue.py show 128` and the GitHub API both showed
numberdb-data#128 as the closed issue "Monomials". The issue body did not ask
for the double-well table. Treating the checklist number alone as provenance
would have put a false "Requested in numberdb-data#128" link in the draft.

What the skill says now: when a checklist line says `(answers #N)`, put
*"Requested in numberdb-data#N"* in Links and let `queue.py built` close it.
It does not say to read that issue before using the number.

What it should say: before adding a requested-in link, read the named issue
and confirm it asks for this table. If the family checklist names an unrelated
issue, record the mismatch in the run report or a lesson and do not put a
false request link in the table.

Evidence: 2026-09-22, `python3 agents/queue.py show 128` printed `#128
Monomials` with the body `Trivial but maybe should be included? (Subset of
#102, so perhaps not needed.)`; `https://api.github.com/repos/numberdb/numberdb-data/issues/128`
returned the same title and closed state.

## A claimed draft needs its parameters before an entries-only fill
What happened: T411 was claimed with only `Title` and `Numbers: {}`. The
generator then sent 60 entries with parameters `a` and `n` through the
entries endpoint. Because the draft document had no `Parameters` section yet,
reading the draft back through `/api/table?id=T411` showed `Numbers` as a
single bare list entry rather than the 60 keyed rows. Replacing the full draft
document with record-form `Numbers` repaired it.

What the skill says now: create the draft first, "Title first, prose if you
have it, no numbers", and fill it later with the generator. It does not say
that the parameter section has to exist before an entries-only fill.

What it should say: when the claim draft will be filled through
`/api/table/<tid>/entries` or `Generator.publish()`, include the final
`Parameters` section in the claim document. A title-only claim is safe only if
the later write replaces the whole document with record-form entries.

Evidence: 2026-09-22, after `Generator.publish()` reported
`<PublishOutcome T411: 60 added, 0 updated, ...>`, `/api/table?id=T411`
returned `Numbers` as `["50.067264782081289963476363294634406718482077923591"]`.
The full-document replacement with `params: {a: ..., n: ...}` records returned
T411 to 60 entries, and `verify()` then reported `60/60 matched`.
