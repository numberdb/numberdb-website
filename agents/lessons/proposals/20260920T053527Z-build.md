## Updating an empty draft through `/api/table/TID` still needs entries
What happened: after creating T361 as an empty draft to claim the title, the
run tried to replace its prose with the finished document before filling
values. `POST /api/table/T361` refused the no-number document with "A table
needs at least one entry." The create endpoint allows an empty document only
when `X-Draft: yes` is present; the later write endpoint is the same route used
for published tables and does not have an empty-draft mode.

What the skill says now: a draft may be created with no numbers, and the prose
is written before the generator fills it. It does not say that a later whole
document write to an empty draft must include `Numbers`.

What it should say: if the initial draft was only a title or a partial prose
claim, do not expect `/api/table/TID` to accept another empty document. Either
create the draft with the prose already complete, fill entries through
`/api/table/TID/entries` before any whole-document replacement, or send the
finished document with its `Numbers` block in the same write.

Evidence: T361, 2026-09-20. `python3 /tmp/write_table.py T361
generators/real-regular-solid-harmonics/table.yaml` returned HTTP 400 with
`"error": "A table needs at least one entry."`; `/tmp/write_full_solid_table.py`
then posted the same prose with the generated 324-entry `Numbers` block and
was accepted as revision `ce6d2ab2...`.
