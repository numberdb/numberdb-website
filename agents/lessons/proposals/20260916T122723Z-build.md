## Quote old-style arXiv identifiers before round-tripping table YAML

What happened: T273's draft document had `arxiv: 0912.0287` for the
Dietzfelbinger-Goerdt-Mitzenmacher-Montanari-Pagh-Rink reference. The draft was
created correctly, but an audit repair script loaded the local YAML with
PyYAML, merged the stored `Numbers`, and dumped the document again. PyYAML read
the unquoted identifier as a number and wrote it back as `912.0287`, so
`audit_table` reported that the arXiv id was not in `YYMM.NNNNN` form.

What the skill says now: identifiers belong in their fields, not at the end of
the `bib` string. It does not say that old-style arXiv ids with a leading zero
need to be quoted when a YAML tool may round-trip the document.

What it should say: quote old-style arXiv identifiers whose first digit is
zero, for example `arxiv: '0912.0287'`. Otherwise a YAML parser may treat the
field as a number and drop the leading zero during a repair that otherwise
preserves the table.

Evidence: T273, 2026-09-16. The first audited repair returned
`"arxiv of reference Dietzfelbinger is 912.0287, which is not YYMM.NNNNN; a
leading zero is the usual casualty"`. Quoting the local field and replacing
the draft document again made `/api/table/T273/audit` return
`{"clean": true, "findings": []}`.
