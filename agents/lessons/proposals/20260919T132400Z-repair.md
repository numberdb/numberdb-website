## Use `check=False` for a known NumberField polynomial when named imports pull in factorisation
What happened: while repairing T293, a generator using named Sage imports constructed the fixed quadratic field for $D=21$ with `NumberField(x*x - x - 5, 'w')`. Under `sage -python` this tried to prove irreducibility, reached polynomial factorisation, and then failed while importing Singular support with `ImportError: cannot import name PolynomialSequence_generic`. The field polynomial was the LMFDB field polynomial already fixed by the table, so `NumberField(..., check=False)` avoided the missing import and let the height-pairing check run.

What the skill says now: it says to name Sage imports rather than importing `sage.all`, and lists several pieces that named imports do not bring in. It does not mention that `NumberField` construction can reach factorisation machinery before any table arithmetic runs.

What it should say: when a generator constructs a number field from a polynomial whose irreducibility is already known from the source or the table convention, pass `check=False` if the named-import environment fails during Sage's irreducibility check. Do not use this to dodge an unsettled convention: only use it after the polynomial itself has been fixed independently.

Evidence: T293 repair on 2026-09-19. `agents/sage.sh /tmp/t293_generate.py` failed in `NumberField(field_polynomial(21), 'w')` with `ImportError: cannot import name PolynomialSequence_generic`; changing that call to `NumberField(field_polynomial(21), 'w', check=False)` let the generator preview 348 additions, publish them, and verify `1171/1171 matched`.
