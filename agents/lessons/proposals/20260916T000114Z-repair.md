## Sage function snippets under `sage -python` may need Sage integers
What happened: while checking T252's `Programs` snippet through `agents/sage.sh`, which runs `sage -python`, the literal call `clebsch_gordan(1, 1, 1, 1, 0, 1)` raised `AttributeError: 'int' object has no attribute 'sqrt'`. The same call with `ZZ(1)` and `ZZ(0)` arguments returned the expected exact values, and the bare literals are fine as Sage syntax in a preparsed Sage session.

What the skill says now: `sage -python` has no preparser, and Python integer division can silently make floats in generators.

What it should say: when checking a Sage-language snippet under `sage -python`, integer literals are Python `int`s rather than Sage `Integer`s. Some Sage functions assume Sage elements and fail before any mathematics is checked; wrap literals with `ZZ(...)` or run the snippet through a preparsed Sage session before trusting the result.

Evidence: `/tmp/t252_sage_snippet.py` raised the `int`/`sqrt` error; `/tmp/t252_sage_snippet_zz.py` under `agents/sage.sh` printed `sqrt(3)*sqrt(1/6)` for the Clebsch-Gordan value and `-sqrt(1/6)` for the Wigner value, 2026-09-16.
