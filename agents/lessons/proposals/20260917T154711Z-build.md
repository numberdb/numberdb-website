## Parse quoted rationals explicitly instead of passing strings to `QQ`
What happened: the BDF live-check script used `QQ(value)` on sample strings
such as `"1"` and `"-4/3"`. In the Sage image used by `agents/sage.sh`, after
named imports and `import numberdb.sage`, `QQ("1")` raised
`AttributeError: module 'sage.rings' has no attribute 'real_mpfr'`. Splitting
the string and building `QQ(int(numerator)) / QQ(int(denominator))` worked.

What the skill says now: it warns that `QQ('1.25')` does not work under named
imports and says to build rationals from decimal digits by hand. It does not
say that even exact rational strings can reach missing parser machinery in a
modular Sage environment.

What it should say: do not parse source data or quoted check rows with
`QQ(text)`, even when `text` is an exact integer or `a/b` rational. Parse the
small grammar yourself and pass integers to `QQ`; that uses only the rational
field and avoids lazy imports that a modular Sage or passagemath install may
not have initialised.

Evidence: 2026-09-17, BDF build for T307. `/tmp/live_bdf_checks.py` failed at
`QQ(value)` with `AttributeError: module 'sage.rings' has no attribute
'real_mpfr'`; after changing the helper to split on `/` and call `QQ(int(...))`,
the same lookup script completed.
