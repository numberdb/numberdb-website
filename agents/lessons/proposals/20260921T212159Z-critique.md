# Lessons proposed by the T390 critique, 2026-09-21

Format as in `agents/lessons/PROPOSALS.md`. Nothing here is in force.

## `Programs` is a mapping with `language` and `code`; a bare string takes the page down

What happened: draft T390 stored

```yaml
Programs:
  sage: >
    In SageMath, use `bessel_J(nu, x)` and root isolation for the Bessel
    zero formulas, and use the formulas above for the separable polygons.
```

The renderer reads `program['language']` and `program['code']`, so a string
value raises `TypeError: string indices must be integers`, which
`table_context` re-raises as `ValueError: Error while Parse program sage:
...`. On `/preview` that is caught and the whole table is replaced by a red
message; on a table page nothing catches it and the reader gets a server
error. Not one section missing -- no page. The fault is invisible in the
document: every field reads as sensible prose.

`audit_table` passes it clean. Its only Programs check is

```python
code = (program.get('code') or '') if isinstance(program, dict) else ''
```

so a string yields no code, no range and no finding. Nothing in the pipeline
between writing the YAML and publishing it says a word.

What the skill says now: what `Programs` is *for* -- "the standard incantation
in Sage, PARI or mpmath for a reader who wants one more value", as against
`generate.py` -- and it lists `Programs` in the sections table. It never gives
the shape. A contributor reading the skill and writing `Programs:` with a
string under a label has followed every sentence in it.

What it should say: `Programs` is a mapping of label to `{language, code}`,
and `code` is code, not instructions for writing code:

```yaml
Programs:
  program-sage:
    language: Sage
    code: |-
      from sage.all import bessel_J
      ...
```

`language` picks the syntax highlighting (`Sage` -> python); any other value
renders unhighlighted. A string where the mapping is expected is not a
degraded rendering, it is an HTTP 500 on the table's own page, and neither
`audit_table` nor `verify` will tell you. Preview the table before offering
it -- the preview shows this fault as a message where the numbers should be,
which is the only place it is visible before publication.

Evidence: 2026-09-21, T390 critique. `GET /api/table?id=T390` and
`generators/dirichlet-eigenvalues-classical-planar-domains/table.yaml:110`
hold the string form. The same document sent to `/preview?table=...`
answered 200 with "Error while Parse program sage: string indices must be
integers, not 'str'" and no rendered table; with
`Programs: {sage: {language: Sage, code: "print(1)"}}` substituted it
rendered. `GET /api/table/T390/audit` answered
`{"findings": [], "clean": true}`. T329, T380, T388 and T389 all use the
mapping form.

## A parameter whose values are names should carry a `values:` map, or the page prints the dictionary keys

What happened: T390's `domain` parameter is `type: Symbolic` and its values
are seventeen slugs -- `unit-square`, `rectangle-1x2`, `annulus-1-2`,
`sector-60`, `l-shape`, `gww-drum-1`. The rendered number table prints those
slugs verbatim in the leftmost column, under the heading $\Omega$. A reader
meets `rectangle-1x2`, which is neither mathematics nor English; it is what
somebody typed to make a dictionary key.

T329 has the same shape and carries

```yaml
  family:
    type: Symbolic
    display: $A_n$
    values:
      hilbert: Hilbert matrix
      lehmer: Lehmer matrix
```

and its published page prints "Hilbert matrix" in that column.

What the skill says now: nothing about `values:`. It covers `param-latex`,
`display`, `title` and `constraints`, and it says a name-valued parameter is
the shape that often means two tables -- but not how to render one when it
legitimately is one table.

What it should say: a parameter whose values are names needs a `values:`
mapping from each key to the name a reader should see, or the page shows the
keys. Keep the keys slug-shaped for citation (`HREF{slug#unit-square,1}`
needs them stable) and let `values:` carry the English. It is also the place
to say what a key means when the key abbreviates: `sector-60: circular sector
of angle $\pi/3$` earns its line, because "60" alone does not say degrees and
the table's own formula is written in radians.

Evidence: 2026-09-21, T390 critique. T390 has no `values:` and renders
`unit-square`; T329's rendered page at `https://numberdb.org/T329` shows
"Hilbert matrix" in the same column position.
