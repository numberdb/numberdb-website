## PyYAML writes `OrderedDict` as Python tags unless the document is converted back to plain mappings

What happened: while repairing T368, the API document was loaded with `object_pairs_hook=OrderedDict` so the outgoing whole-document edit would preserve the table order. The pre-send print showed `Comments: !!python/object/apply:collections.OrderedDict`, and the same tags would have gone to `/api/table/T368` if the body had been sent as generated. Regenerating the document with ordinary Python `dict` objects kept the order on Python 3 and produced plain YAML.

What the skill says now: it warns that `yaml.dump` must use `sort_keys=False`, because the order of `Parameters`, formulas and entries is part of what the page shows.

What it should say: do not hand `OrderedDict` objects to PyYAML's default dumper for an API document unless a plain representer is registered. Use ordinary dicts, or otherwise inspect the outgoing YAML and reject any `!!python` tag before sending it.

Evidence: T368 repair on 2026-09-20. `/tmp/T368_changes.txt` first printed `!!python/object/apply:collections.OrderedDict`; the regenerated `/tmp/T368_repaired.yaml` reported `contains python tags: False`, and `POST /api/table/T368` accepted revision `d48311b81d54e3759990c86072fc68f8ecaca5ce26353993ba0268903f70f768`.
