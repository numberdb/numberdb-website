## A prose-only draft still wants `Numbers: []` before a generator fills it

What happened: T228 was created as a draft with the prose document only and
no `Numbers` section. The generator had passed `dry_run.py`, but
`generator.publish()` failed before computing values. Its first act is
`check_writable()`, which posts an empty upsert to `/api/table/228/entries`;
on this draft the server tried to merge that empty entry list into a missing
section and answered `A value in these entries cannot be read as a number.
'str' object has no attribute 'items'`. Sending the real, nonempty entries
worked once that empty probe was bypassed.

What the skill says now: create the draft with "Title first, prose if you
have it, no numbers", then fill it once with the generator. It does not say
whether the empty entries section should be present.

What it should say: when creating a draft through the API for a generator to
fill, include an empty `Numbers: []` section. That is still no numbers, but
it gives the client's empty writability probe an entries section to merge
into. If `publish()` fails with this exact parser error before computing the
first value, the values have not been sent; add the empty section or use the
entries endpoint with a nonempty replacement, then rerun.

Evidence: `cat "$NUMBERDB_KEY_FILE" | NUMBERDB_KEY_FROM_STDIN=1
NUMBERDB_PUBLISH=1 NUMBERDB_ASSISTED_BY=codex-cli agents/sage.sh
generators/zeta-derivative-rational-values/generate.py`, 2026-09-13,
failed with the quoted message before any entries were computed. The same
generator filled T228 with 470 entries when `/tmp/fill_zeta_derivative.py`
skipped only the empty `check_writable()` probe and called
`generator.publish()` for the actual nonempty submission.
