## An empty draft can be created but not rewritten through the full-document endpoint

What happened: T234 was claimed correctly as an empty draft with
`POST /api/tables`, `X-Draft: yes`, and `Numbers: []`. Before filling it, the
table document needed a one-line prose repair in `Programs`. Sending the full
document back to `POST /api/table/234` with the draft's base revision was
refused with "A table needs at least one entry. A published table with no
numbers holds a permanent T-number ... Send X-Draft: yes to propose it
instead." After the generator filled the draft, the same full-document route
accepted the prose repair while preserving the numbers.

What the skill says now: create the draft first with title and prose, no
numbers, then fill it once. A proposed lesson from an earlier run says to
include `Numbers: []` when claiming the draft so the entries endpoint's empty
preflight has the shape it expects.

What it should say: if an empty draft's prose has to be changed before the
first fill, the full-document write route may still refuse it as an empty
table. Either make the correction before creating the draft, or fill the
draft and then rewrite the full document read back from the API, preserving
its `Numbers` section. Do not send the original `Numbers: []` document after
the fill, or it would delete the entries.

Evidence: T234, 2026-09-13. `cat "$NUMBERDB_KEY_FILE" |
NUMBERDB_KEY_FROM_STDIN=1 agents/sage.sh /tmp/update_t234_doc.py
generators/hypersimplex-ehrhart-polynomials/table.yaml` was refused with the
quoted message. After `generate.py` filled 162 entries, `/tmp/patch_t234_program.py`
read the live draft through `numberdb.table("T234")`, inserted the missing
program import, and `POST /api/table/234` returned revision
`3edc570ac8ef820f94287961e6fd9f9544d9b7042d20dfceaeacde1d32aea5fe`.
