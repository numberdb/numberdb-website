## A new draft should carry `Numbers: []` before a generator fills it
What happened: T305 was created as a draft with full prose but no `Numbers`
section, which the creation API allows for drafts. The first generator fill
failed before computing entries, in the client's writable preflight:
`NumberDBError: A value in these entries cannot be read as a number. 'str'
object has no attribute 'items'`. The preflight sends an empty upsert; with no
existing entries block, the server merged that into `Numbers: null` and then
tried to validate it as entries. Sending `[]` once through
`/api/table/305/entries` initialized the block, and the same generator fill
then added all 78 entries.

What the skill says now: a draft may have no numbers in it yet, and a run
should create the draft before building. It does not say whether the draft
document should include an empty entries section.

What it should say: when creating a draft through the API for a generator to
fill, include `Numbers: []` in the draft document, or initialize the entries
block with an empty replace before running `publish()`. A missing entries
section and an empty entries section are not equivalent to the current
generator preflight.

Evidence: on 2026-09-17, `NUMBERDB_PUBLISH=1 agents/sage.sh
generators/adams-bashforth-coefficients/generate.py` failed on T305 with the
preflight error above. `POST /api/table/305/entries` with body `[]` returned
`"entries": 0`, and rerunning the same generator reported
`<PublishOutcome T305: 78 added, 0 updated, 0 unchanged, 0 agreed, 0 left
alone, 0 removed>`.
