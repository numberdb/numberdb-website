## A table of *examples* needs a `complete-note` saying so, or it reads as unfinished

What happened: T2 "Integers" holds the twenty-one integers $-10 \ldots 10$ and
declares `complete: no` with nothing after it. It reached a growth queue
because 21 entries is 1.8% of the entry limit and the family it names is
infinite, so on every visible measure the table looks stopped early. It is not.
One table over, T30 "Rational numbers" — same author, same fortnight in
January 2021, same construction over $\mathbb{Q}$ — carries

    complete-note: it holds every $a/b$ in lowest terms with $|a| \leq 5$ and
      $1 \leq b \leq 5$, as examples of the field rather than as a reference
      list

and that final clause is the entire answer to the growth question for both
tables. T2 lacks it, so answering the question for T2 meant reading a
*different table* to find out what kind of table T2 is.

The distinction is real and not cosmetic. Most tables in a corpus like this
are prefixes of an enumeration: more rows would be more of the same good thing,
and `complete: no` correctly invites the next person to extend them. A few are
not. A table whose job is to *exhibit* an object — the ring $\mathbb{Z}$, the
field $\mathbb{Q}$, the thing a one-entry constant table points into — is
finished at a dozen rows, and extending it is a straightforward harm: the extra
rows are values that match everything and identify nothing, which the skill
already says elsewhere makes search worse for everyone. Measured on this
corpus: `/api/lookup?text=7` returns 100 results and the message "We only show
the first 100 results", and the first of them is T2 saying that 7 is an integer.
Extending T2 to $|n| \leq 100$ would put that non-answer at the top of 180 more
already-capped searches.

So the two tables need opposite things from the same field, and only the
`complete-note` can tell them apart. Nothing else in the document can: not the
entry count, not the block size, not the parameter constraint ("$n$ — integer",
which is the infinite family and correctly so), and not the audit, which has no
rule that could ask.

What the skill says now: it is good on the `complete-note` for the ordinary
case — "write a clause that finishes that sentence … not that the table is
incomplete, which is true of almost all of them, but what it *does* cover" —
and it is good on *choosing* a range, "Say which range you chose and why in the
completeness note. That sentence is the argument." But both are written for a
table that could sensibly be larger. There is no advice for the table that is
deliberately a handful of examples, and for that table "say what you cover" is
not enough: a reader who is told "it holds every integer with $|n| \leq 10$"
still has every reason to think 11 would be welcome.

What it should say: where a range is a window of examples rather than a prefix
somebody should extend, the `complete-note` has to say *that*, not just where
it stops. The clause that does the work is the one naming the purpose —
"as examples of the field rather than as a reference list" — and without it
`complete: no` reads as an invitation. The test is whether an extra row would
help anybody: if the next value in the range is one nobody would arrive
holding, the table is complete in intent though the family is infinite, and the
note is the only place that can be said.

Evidence: 2026-09-21, T2 growth review (`agents/critiques/T2-growth.md`).
`/bundle/T2` and `/bundle/T30`, the two `Data properties` blocks quoted above.
`GET /api/table/T2/audit` returns one finding, `"Definition is empty"`, and
nothing about the missing note. `/api/lookup?text=7` and `text=-3` both return
100 results with the cap message, T2 first and fourth respectively; `text=13`
and `text=101` also return 100 without T2. `numberdb_app/limits.py`'s own
byte measure puts the T2 entries block at 800 bytes and a hypothetical
$-599 \ldots 599$ at 46.4 KB and 1199 entries, i.e. inside every soft limit —
so nothing the server checks would have stopped the wrong answer.

## `/bundle/Tn` reads a whole table for free while `/api/table` is rate limited, and a refused request still costs a unit

What happened: a review needed to know which tables in the corpus link to
`HREF{Integers}`. There is no call that lists the corpus, so the way to do it
is to walk the T-numbers, which the skill says. Walking `/api/table?id=Tn`
anonymously got through 43 and then `HTTP 429`. Retrying the same 400-table
walk *with* the key was refused on all 400, with

    {"error": "Rate limit exceeded (1000 requests per 60 minutes)",
     "retry_after": 2228}

Two things about that are not obvious and cost the census.

**A 429 still consumes the allowance.** `numberdb_app/throttle.py::_consume`
increments the window counter and *then* compares it with the limit, so a
refused request is counted exactly like a served one. A back-off loop, or a
second attempt at a sweep that tripped the limit, does not merely fail — it
spends the next window too. An existing note records that "a 429 here means
'wait an hour', not 'slow down'"; this is the mechanism, and it is stronger
than that: retrying makes the wait longer.

**The site's own pages are not rate limited at all**, and one of them returns
the whole document. `throttle.py` says so in its docstring — "Only `/api/*` is
limited. The site's own pages … are rendered server-side and never call the
API" — and `/bundle/Tn` is a site page. It answers with a zip holding
`Tn/table.yaml`, which is the complete stored document including every entry,
`Data properties`, `Display properties` and whatever files the table carries.
Checked at one moment, against one locked-out caller:

    GET /api/table?id=T30   429
    GET /bundle/T30         200   (1234 bytes, T30/table.yaml + README.txt)
    GET /T30                200

So the whole of the rest of that review was done through `/bundle`, and it was
in several ways the better tool anyway: the YAML is the form an author edits,
it shows `complete-note` and `repeats` exactly as stored rather than
re-serialised, and it brings the attached generator along in the same request.

What the skill says now: it names `numberdb.table('T99')` and warns that
printing the result is megabytes, and it says "there is no call that lists the
corpus, so to see everything you walk the T-numbers." It does not say what that
walk costs, and it never mentions `/bundle`.

What it should say: reading one table's document does not need the API —
`curl https://numberdb.org/bundle/T99` returns `T99/table.yaml`, the stored
document with its generator beside it, and site pages are outside the rate
limiter, so it costs nothing against the hourly allowance. Reserve `/api` for
what only it can do (search, lookup, writing). And when walking the T-numbers,
send the key: 60 requests an hour anonymously, 1000 with one, and a request
that is refused is still charged, so a sweep that trips the limit must be
abandoned rather than retried.

Evidence: 2026-09-21, T2 growth review. Anonymous walk of
`/api/table?id=T%d` for n = 1..400 at three threads: 43 documents, then 429 for
the remaining 357. The same walk with `X-API-Key`: 400 refusals, body as quoted.
`numberdb_app/throttle.py` — `_consume` increments before the limit test;
`ANONYMOUS_LIMIT = 60`, `IDENTIFIED_LIMIT = 1000`, `WINDOW_SECONDS = 3600`; the
module docstring for the exemption of site pages. The three simultaneous
requests above. `/bundle/T2` and `/bundle/T30` supplied every fact the review's
central argument rests on.
