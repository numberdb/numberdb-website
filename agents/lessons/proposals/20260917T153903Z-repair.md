## Power-series logarithms can pull in missing symbolic imports
What happened: while checking T306's Gregory-coefficient formula, the Sage script tried to compute the coefficients of $z/\log(1+z)$ with `PowerSeriesRing(QQ, 'z')` and `(1 + z).log()`. Under `agents/sage.sh`, after `import numberdb.sage as numberdb` and named Sage imports, this failed inside `sage.rings.lazy_series` and then `sage.symbolic` with `AttributeError: cannot access submodule 'function' of module 'sage.symbolic'`. Rewriting the check as the exact reciprocal recurrence for `log(1+z)/z` avoided the symbolic import and checked the table.

What the skill says now: the public skill says named imports do not bring root finding, `RealBall.str`, and `QQ('1.25')`, but it does not warn that power-series logarithms can reach the same missing symbolic machinery.

What it should say: for a fixed number of coefficients, prefer an explicit recurrence or truncated polynomial arithmetic to `PowerSeriesRing(...).log()` in the named-import Sage environment; power-series methods can import symbolic pieces that are absent in modular Sage/passagemath.

Evidence: `cat "$NUMBERDB_KEY_FILE" | NUMBERDB_KEY_FROM_STDIN=1 agents/sage.sh /tmp/t306_check.py`, 2026-09-17, first failed at `(1 + z).log()` with the symbolic circular-import traceback. The revised script printed no moment, integral or Gregory failures for T306.
