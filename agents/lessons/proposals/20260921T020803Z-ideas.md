## Rigorous integration in Sage is on `ComplexBallField`, not `RealBallField`

What happened: the batch needed the mean distance between two random points of
the unit $d$-cube, which has no closed form for $d\ge4$ and has to be
integrated. The obvious call, `RealBallField(300).integral(f, 0, 1)`, raises

    AttributeError: 'RealBallField_with_category' object has no attribute 'integral'

There is no `RealBall` integration in Sage at all: arb's `acb_calc` numerical
integration is exposed only on `ComplexBallField`, and the way to a proven real
value is to integrate in `ComplexBallField(bits)` and take `.real()`. The
integrand is handed `(x, analytic)` and may ignore the second argument when it
is entire.

    C = ComplexBallField(1200)
    I = C.integral(lambda x, _: f(x), 0, 1 - QQ(2)**-400)
    value = RealBallField(1200)(I.real())

What the skill says now: it names `RealBallField` and `ComplexBallField` as the
things to prefer for transcendental values, and gives `elliptic_k` as the
worked example -- a function with a ball method, so integration never comes up.

What it should say: when the value is an integral with no closed form,
`ComplexBallField.integral` is the only proven route; `RealBallField` has no
`integral` method, and the error reads like a version problem rather than like
a design.

Evidence: `agents/sage.sh` on the script above. 120 correct digits of the
Robbins constant (OEIS A073012) in 86 s at 1200 bits; 21 digits in 4.0 s at
300 bits. The `RealBallField` form raises before doing any work.

## An improper integral wants a substitution that makes the integrand bounded, not a bigger cut-off

What happened: $\mathbb{E}\sqrt S = \frac1{2\sqrt\pi}\int_0^\infty
t^{-3/2}(1-\varphi(t)^d)\,\mathrm dt$ has a branch point at $0$ and an infinite
range, and `acb_calc` will not integrate through either. Substituting
$t=u^2$ kills the $t^{-3/2}$, and then $u=x/(1-x)$ maps $[0,\infty)$ to
$[0,1)$ with the integrand tending to a *finite* limit at both ends -- $d/3$ at
$x=0$ and $2$ at $x=1$. The remaining tail past $x=1-\delta$ is then bounded by
$2\delta$ and can simply be added with `add_error`, which is what makes the
result an enclosure rather than an estimate.

The reason it matters is precision, not elegance: with a bounded integrand the
tail cut $\delta$ costs one digit per $\log_{10}(1/\delta)$ and nothing else,
so 120 digits needs $\delta=2^{-400}$ and no further thought. With an
unbounded one the subdivision near the endpoint eats the whole precision
budget.

The other half of the same lesson is cancellation. $1-\varphi(t)^d$ and
$1-\varphi(t)$ both cancel to nothing as $t\to0$. Factoring
$1-\varphi^d=(1-\varphi)\sum_{j<d}\varphi^j$ and evaluating
$h(t)=(1-\varphi(t))/t$ from its Taylor series for $|t|<1$ removes every
cancellation in the problem. In ball arithmetic cancellation is not a silent
loss of digits, it is a ball that grows until the answer says nothing, so this
is the difference between an answer and `[+/- 1e+00]`.

What the skill says now: "State the guard as a constant backed by measurement",
which is about a fixed loss, not about an integrand that has to be reshaped
first.

What it should say: before raising the working precision on an integral, check
that the integrand is bounded on the interval after substitution and that no
subtraction in it cancels; a guard cannot rescue either.

Evidence: same run. The unsubstituted form returns balls of radius $>1$ at
300 bits; the substituted form returns radius `8.5e-22`.

## `sage.functions` and `sage.symbolic` cannot be imported after `numberdb.sage`

What happened: following the skill's instruction to import `numberdb.sage`
before naming the rings, the natural next lines

    from sage.functions.log import log
    from sage.symbolic.constants import pi

raise

    AttributeError: cannot access submodule 'function' of module
    'sage.symbolic' (most likely due to a circular import)

The skill already warns that the named-import style does not bring root
finding, `RealBall.str` or `QQ('1.25')`. The symbolic layer is a fourth thing
it does not bring, and it fails with a message about circular imports rather
than about a missing module, which reads like a broken installation.

There is no need for it: the ball fields carry their own constants and
functions -- `RealBallField(p).pi()`, `x.log()`, `x.sqrt()`, `x.erf()`,
`x.exp()` -- and those are the ones that carry error bounds anyway.

What the skill says now: the list of three things the named imports do not
bring.

What it should say: make it four, and say that the symbolic ones are not a
workaround to reach for, because a symbolic constant would have to be coerced
into a ball to be useful and the ball field already has it.

Evidence: same run, first two attempts.

## `RealBall` has no `.str()` here either, so print with `repr`

What happened: `value.str(digits=20)` raises `AttributeError: 'RealBall' object
has no attribute 'str'`, which the skill already records for the modular
passagemath build. Worth adding what to do instead: `repr(value)` prints the
ball as `[0.66170718226717623516 +/- 5.50e-21]`, which is the form a checking
run wants anyway, since it shows the radius beside the digits.

What the skill says now: that `RealBall.str` is among the things not brought.

What it should say: and that `repr` is the replacement, and is better for a
verification print because it shows the enclosure rather than a chosen number
of digits.

Evidence: same run.

## LMFDB has a JSON API, and it will answer "is this family actually a formula?"

What happened: two open requests (#23, #25) asked for the analytic conductors
of $L$-functions and of classical modular forms. Whether those are a *family*
or a *formula in two integers* decides whether they can be tables at all, and
it was settled in two HTTP requests:

    https://www.lmfdb.org/api/mf_newforms/?_format=json&weight=2&_limit=100
        &_fields=label,level,weight,analytic_conductor
    https://www.lmfdb.org/api/lfunc_lfunctions/?_format=json&degree=1&_limit=8
        &_fields=conductor,analytic_conductor,root_number,origin

`analytic_conductor / level` came back as a single value per weight across 100
newforms each at weights 1, 2, 3, 4, to all 14 digits compared. The request is
a formula, and can be closed.

What the skill says now: LMFDB is named as a durable link target.

What it should say: that it is also queryable as `\
https://www.lmfdb.org/api/<table>/?_format=json&_fields=a,b&_limit=n`, and that
it is the cheapest way to answer the distinctiveness question about an
arithmetic family -- pull the column and look at whether the values are spread
or are one constant times an index. That question decides more proposals than
any search does.

Evidence: the two queries above, run today.

## `source_names_it` catches a plausible URL for a real family

What happened: four sources were cited from memory and three were **404**:
`mathworld.wolfram.com/PolygonLinePicking.html`,
`mathworld.wolfram.com/RectangleLinePicking.html`, and
`en.wikipedia.org/wiki/Sylvester's_four-point_problem` under either apostrophe
encoding. All three name real, well-studied families -- MathWorld does carry
*Square line picking* and *Sylvester's four-point problem*, at different
addresses -- so the failure is not "this family is invented" but "this address
is". A fifth, `HyperspherePointPicking.html`, exists and returns 200, and the
check still complained, correctly: the page is about *point* picking, not
*line* picking, and does not discuss the distance between two points at all.

The consequence was a dropped table: a proposed *mean distance in the regular
$n$-gon* had no source of that name and was cut rather than cited loosely.

What the skill says now: nothing about this stage; the check lives in the
ideation prompt rather than in the skill.

What it should say (in the prompt, if anywhere): run `source_names_it` on the
**family's own name** rather than on the table's title. A title like "Mean
distance between two uniform random points in the cube, the ball and the
sphere" has ten distinguishing words and no page will contain all of them, so
the check fails on every good proposal and passes on none. The name to screen
is "Hypercube line picking".

Evidence: the thirteen checks tabulated in
`agents/table-ideas/BATCH-2026-09-21T0208.md`.
