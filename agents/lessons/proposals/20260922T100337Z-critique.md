## See the page before publishing: `GET /preview?table=` renders a document from a laptop

What happened: the T404 critique had to read the *rendered* page, because
three faults this year existed only in the rendering and not in the stored
YAML -- a `<` in mathematics eating the rest of a section, a parameter list
showing `argument ()`, and a formula printing "Math input error" where a JSON
escape had eaten a backslash. None of those is visible in a document you are
holding in an editor.

They are all visible in ten seconds through a route the site already serves
to anybody:

    curl -s -G --data-urlencode "table@my-table.yaml" https://numberdb.org/preview

That is the same editor page `/preview` shows, filled from the query string,
and it runs the same rendering code the table page runs, so what comes back
is what a reader will get. It needs no account, no key and no table: a
document that has never been sent anywhere renders. `https://numberdb.org/preview`
in a browser is the same thing with a text box, which is easier for a person
and harder to script.

Two limits are worth knowing before the first attempt. **The request line
caps at 4094 bytes**, and over that the answer is HTTP 400 "Request Line is
too large" rather than a page -- so a table of any size goes through in
pieces, two or three sections at a time, with `Numbers` cut to a couple of
entries and only the `References` that those sections' own `CITE{}`s need.
And `HREF{}` renders as a relative anchor whether or not the target exists,
so a preview does not tell you a cross-reference resolves; `GET
/api/table?id=T390` does, answering 200 for a published table and an `error`
otherwise.

What the skill says now: nothing about seeing the page. Section 10, "Check
the work", is entirely about the numbers -- `verify`, `sweep_arb`,
independent recomputation, controls, enclosures. Nothing in it looks at the
prose as a reader meets it, and `preview()` in section 6 is the generator's
dry run, which computes values and sends nothing: a different thing with the
same name.

What it should say: in section 10, beside `verify`, that the rendered page is
a separate check from the values and is one request away --
`curl -G --data-urlencode "table@table.yaml" https://numberdb.org/preview` --
with the 4094-byte request line named, because the first attempt on a real
table returns 400 and reads like the route being wrong rather than the
document being long. It is the cheapest check in the whole list and it is the
only one that catches a definition that renders as half a sentence.

Evidence: T404 critique, 2026-09-22. Six pieces of the T404 document each
answered 200 with about 20 KB; the whole 9209-byte document answered nothing
and a 4884-byte piece answered `400 Request Line is too large (5892 > 4094)`.
The site's own reason for the route is in `views.build_preview_context`: "an
editor that previews through different code from the page is worse than no
preview, because the author trusts it."
