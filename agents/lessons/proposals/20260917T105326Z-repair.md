## Prefer ring-element square roots in Sage check scripts

What happened: while repairing T298, a Sage verification script imported
`sqrt` with `from sage.functions.other import sqrt` after importing
`numberdb.sage`. Under `agents/sage.sh`, that raised
`AttributeError: cannot access submodule 'function' of module 'sage.symbolic'`
from Sage's symbolic-function import chain. The script did not need symbolic
square roots; removing the import and using `RealBallField` elements'
`.sqrt()` method made the check pass.

What the skill says now: it says to import `numberdb.sage` before direct Sage
ring imports, and it lists a few direct imports or methods that are missing in
the modular Sage/passagemath environment. It does not mention that reaching
for symbolic `sqrt` can trip the symbolic import path in a plain verification
script.

What it should say: in generators and check scripts that are doing ball or
interval arithmetic, prefer methods on elements of the chosen ring, such as
`RBF(5).sqrt()`, over importing symbolic functions such as
`sage.functions.other.sqrt`. If a symbolic function is actually needed, test
that import under the same Sage wrapper before depending on it.

Evidence: T298 repair, 2026-09-17. `agents/sage.sh /tmp/verify_t298.py`
failed at `from sage.functions.other import sqrt` with the traceback above.
After deleting that unused import and computing all radicals as
`RealBallField` element powers or `.sqrt()`, the same script confirmed the
row 4 and row 20 closed forms and printed the expected CM discriminants.
