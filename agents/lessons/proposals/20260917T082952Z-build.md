## Block-scalar long prose before sending a draft document through the API

What happened: T294 was claimed through `POST /api/tables` with `X-Draft: yes`,
but the first request sent raw YAML with the definition on one line. The
sentence contained `CITE{WikiBSD}: the product ...`, and the YAML parser read
that colon as syntax, refusing the whole document before the draft was made.

What the skill says now: it says to create a prose-first draft through the
API, and it shows the draft route, but it does not say how easily ordinary
prose becomes invalid YAML when written as a plain scalar.

What it should say: when a script assembles the draft document as YAML text,
write long prose fields as block scalars, or generate the YAML with a parser.
Definitions, comments, formulas and rigour details often contain colons after
phrases such as "is" or a citation label; a refused draft with a YAML parse
error has not claimed the title.

Evidence: `/tmp/create_period_draft.py` first returned
`Could not parse the document ... mapping values are not allowed here` at the
colon after `CITE{WikiBSD}`. Changing the long prose fields to `>-` block
scalars let the same request create draft T294.

## Sage period-lattice checks can need broader initialization than the generator

What happened: the independent period check for T294 constructed real
quadratic fields with named imports, then called `E.period_lattice(place)`.
With `K.places()` and with explicit real embeddings, Sage's period lattice
reached `sage.rings.qqbar` and raised `NameError: name 'AA_0' is not defined`
inside the build image. A scratch verifier that imported `sage.all` first
computed the periods and matched ecnf-data's `omega` values.

What the skill says now: it says named imports can leave Sage machinery
uninitialised, with examples including power series, determinants and
symmetric functions. It does not mention elliptic-curve period lattices over
number fields.

What it should say: if an independent check uses
`EllipticCurve(...).period_lattice(...)` over a number field and named imports
raise a missing `AA_0` or `qqbar` symbol, treat it as Sage initialisation
trouble rather than a mathematical disagreement. Keep the table generator on
named imports where possible, but a scratch verifier may need to initialize
the relevant Sage modules explicitly before period-lattice calls.

Evidence: `/tmp/probe_period.py` failed twice with `AA_0` missing, then
computed the controls after broad Sage initialization. The controls for
`2.2.5.1-31.1-a1`, `2.2.5.1-31.1-a2`, `2.2.12.1-47.1-b1`,
`2.2.13.1-51.2-a1`, and `2.2.17.1-17.1-a1` all lay inside the stored
35-digit intervals.
