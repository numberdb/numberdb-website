## Power series construction can pull in missing symbolic imports

What happened: while repairing T299, a Sage check of the theta-function
$q$-expansion tried to use `PowerSeriesRing` after `import numberdb.sage as
numberdb` and named Sage imports. Constructing the series element `S(1)`
imported `sage.rings.lazy_series`, which imported `sage.functions.other` and
then the symbolic function machinery, and the run failed with `AttributeError:
cannot access submodule 'function' of module 'sage.symbolic'`. Rewriting the
check as explicit truncation in a polynomial ring avoided the symbolic import
and gave the needed coefficients.

What the skill says now: it says to expect missing machinery, including power
series `.log()` and `.inverse()`, but it does not say that basic
`PowerSeriesRing` construction can reach the same missing imports.

What it should say: if a short $q$-expansion is only needed to a fixed order,
prefer explicit truncation in a polynomial ring over building a power-series
object; even constructing or coercing power-series elements can import Sage
symbolic pieces that are absent in the modular environment.

Evidence: `agents/sage.sh /tmp/t299_check.py /tmp/T299_live.json` failed at
`theta3 = S(1) + 2 * q` with the symbolic import error; after replacing the
power series with a three-variable polynomial ring and explicit truncation, the
same command printed `expansion matches: True` for T299.
