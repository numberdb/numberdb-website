## Use block scalars or JSON for prose sent through the table API

What happened: creating the T261 draft with a hand-written YAML document failed
before any table was created. The definition and comment strings were plain
YAML scalars, and the sentence "separated by commas: $2,1,1$ ..." made the
YAML parser stop with `mapping values are not allowed here`. Sending the same
document as JSON worked, and the later full-document updates used YAML only
after loading structured data and dumping it with a YAML library.

What the skill says now: a draft may be proposed with `POST /api/tables` and
the API accepts YAML or JSON. It does not say how easy it is for visible prose
to stop being YAML when written as an unquoted one-line scalar.

What it should say: when a script sends a whole table document through the API,
build a data structure and serialize it as JSON or with a YAML library. If
writing YAML by hand, put prose fields in quoted strings or block scalars,
because a colon followed by a space in a plain scalar is parsed as a mapping
separator before NumberDB sees the document.

Evidence: `/tmp/create_hall_littlewood_draft.py`, 2026-09-16, first run:
`NumberDBError: Could not parse the document. mapping values are not allowed
here, line 25, column 86`. The retry using `json.dumps` created draft T261.
