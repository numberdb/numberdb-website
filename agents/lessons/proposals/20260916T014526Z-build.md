## Do not put table cross-references in the definition
What happened: the first draft of T255 defined a sporadic finite simple group
by linking the phrase to T77, `HREF{Orders_of_sporadic_finite_simple_groups}`.
The site audit refused it with `Definition links to another table; a
cross-reference belongs in Similar tables or a comment`. Moving the link to a
comment and keeping the Similar tables entry made the audit clean.

What the skill says now: it says to link the first mention of a thing the
corpus already holds, and it says the definition should hold the definition
rather than caveats, history or relations. It does not say that a link to
another table is not allowed in the Definition section.

What it should say: do not put `HREF{...}` cross-references to NumberDB tables
in `Definition`. If the definition names a family that the corpus already
holds, put the link in a comment or Similar tables entry instead, and keep the
definition as the self-contained mathematical statement.

Evidence: `cat "$NUMBERDB_KEY_FILE" | python3 /tmp/audit_table.py T255`
reported the finding above on 2026-09-16. After the definition was changed to
plain text and the existing linked comment was kept, the same audit returned
`{"clean": true, "findings": []}`.
