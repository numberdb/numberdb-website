## Typeset every `$...$` before offering a table, and write a Kronecker symbol as one

What happened: the T221 critique read the rendered page of the Bianchi
covolume table. The TeX was checked by typesetting all 367 distinct
`$...$` fragments of the document with MathJax 3 in node (`npm install
mathjax-full@3`, the TeX input with `AllPackages`, and `formatError`
rethrowing). It found no error, and a control fragment `\frac{1}{` did
raise one. That check takes a minute on any laptop with node. A "Math input
error" otherwise shows up only in a browser, never in the YAML, and one
table this year shipped with one. What the check cannot catch is TeX that
compiles and reads wrongly. The same table wrote the Kronecker character as
`$\chi_D(n)=(D/n)$`, which typesets as $D$ divided by $n$, a number that
means something in that table. T128 writes
`$\chi_D=\left(\frac{D}{\cdot}\right)$`.

What the skill says now: nothing about checking TeX before publishing. It
also says nothing about notation that typesets as a different operation.

What it should say (in section 10, "Check the work"): typeset every
`$...$` in the document with the site's MathJax (version 3, `$` and `\(`
delimiters) before offering the table, with a control that is known to
fail. Then read the formulas once as typeset, because a symbol written
in the notation of an operation, such as a Legendre or Kronecker symbol as
`(a/p)`, compiles and misleads. Write it `\left(\frac{a}{p}\right)`.

Evidence: T221 draft, 2026-09-13, `formula-dirichlet`; the node run reported
"checked 367 errors 0", and the control reported "checked 3 errors 1".
