## Empty draft metadata cannot be replaced through `write_table`
What happened: T270 was claimed as an empty draft with its title and initial
prose. After measuring the Krawtchouk range, the run tried to replace the
draft document with the final prose and no `Numbers` block, planning to fill
the entries in the next call. The API answered 400:

`{"error": "A table needs at least one entry.", "detail": "... Send X-Draft: yes to propose it instead, and fill it before publishing."}`

The table was already an unpublished draft. The refusal is on the
`/api/table/TID` replacement endpoint, which calls the same non-empty document
check used for publishing.

What the skill says now: create the draft first, with title and prose if you
have it, then measure and fill it once. It does not say that an empty draft
cannot have its metadata replaced through the table-write endpoint before the
entries exist.

What it should say: if the final prose depends on the range measurement, either
create only the title and send the final prose together with the first entries
as one full-document write, or fill the entries first and then replace the full
document while preserving them. Do not plan on an empty metadata-only
`POST /api/table/TID` after the draft exists; the endpoint refuses it until the
document has at least one entry.

Evidence: `cat "$NUMBERDB_KEY_FILE" | python3 /tmp/write_numberdb_table.py T270 /tmp/krawtchouk_metadata_final.json`, 2026-09-16, returned the error above. Sending the same final document with the computed `Numbers` block succeeded as revision `4bcb7a9bf4ffde86f0969c52bcad5e39817eac482a0b6a383f72ad8f64609959`.
