## Existing comparison tables may carry older last-digit rounding

What happened: the fractional Sobolev constants were required to match the
`p=2` slice of T92 digit for digit at `s=1`. The formula and the current
`numberdb` serializer agreed with T92 through the first 99 significant digits,
but six stored T92 rows differed by one unit in the 100th digit. Recomputing
T92's own Aubin-Talenti formula with the current serializer gave the new last
digit, not the stored one.

What the skill says now: when a new table repeats an existing one, declare the
repeat or match the existing direction, and check relations before writing
them down. It does not say what to do when an existing table was serialized by
older rounding and only the final uncertain digit differs.

What it should say: when a family convention says a new table must match an
existing table digit for digit, compare through the database serializer before
publishing. If the only disagreement is one unit in the final written digit
and the new computation is a proven interval, do not copy the old value as a
string or bias the new interval to reproduce older rounding. Record the
discrepancy for review and keep the new generator's proven output, unless a
person decides to repair the older table as well.

Evidence: T354 build on 2026-09-20. For dimensions
`n = 5, 8, 12, 14, 16, 18`, the `s=1` fractional Sobolev generator and the
current serialization of T92's own formula ended one unit above T92's stored
`p=2` entry. The special value `S_{2,1/2}=\pi^{1/4}` and the reciprocal-square
formula checked in ball arithmetic, and every T92 comparison differed only in
the final written digit.

## A title-only draft needs parameters before a generator fills it

What happened: T354 was claimed with only a title and `Numbers: {}`. The
generator had parameters `n, s` and reported `<PublishOutcome T354: 610
added>`, but the draft did not yet declare those parameters. Reading the draft
back showed one parameterless number: the entries endpoint had no parameter
schema to merge against, so the stream did not become 610 addressable rows.

What the skill says now: claim a proposal by creating the draft before
building anything, "Title first, prose if you have it, no numbers", and then
fill it once. It does not say that the draft must have the intended parameter
keys before the generator writes entries.

What it should say: a title-only draft is enough to claim a proposal, but do
not run a parameterized generator against it until the draft document declares
the generator's parameter keys in the right order. If the prose is not ready,
add at least `Parameters` and `Data properties: type` before filling, or send
the full parameterized document with entries in one repair edit.

Evidence: T354 build on 2026-09-20. After the first generator publish, keyed
`numberdb.table('T354')` returned `Numbers` as a one-item list and no
`Parameters`, despite the generator reporting 610 added entries.
