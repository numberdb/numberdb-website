## Do not trust an `(answers #N)` marker until the numbered issue is read

What happened: the family issue for the laminar boundary-layer batch marked
the proposal "Constants of the von Kármán rotating-disk flow" as
`(answers #109)`. The build prompt says that such a marker means the table
should link to the request and that `queue.py built` will close it. Reading
`numberdb-data#109` showed a different request, "Heat (caloric) polynomial",
already closed after T419. Linking it from the rotating-disk table would have
put false provenance in the document.

What the skill says now: a checklist line with `(answers #N)` is treated as a
request for this table, and the table should put that request in `Links`.

What it should say: read the numbered issue before adding a request link or
letting a queue helper close it. If the title or body of the issue is not this
table, report the mismatch and do not add the link; the family marker is data
that can be wrong, and false provenance is worse than no provenance.

Evidence: `python3 agents/queue.py show 190` printed
`Constants of the von Kármán rotating-disk flow (answers #109)`, while
`python3 agents/queue.py show 109` printed `#109 Heat (caloric) polynomial`
and the GitHub API returned the same title with state `closed`.
