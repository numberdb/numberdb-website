## Empty-draft preflight upserts can fail before a generator sends entries
What happened: after claiming draft T318 with prose and no `Numbers` section,
`numberdb.Generator.publish()` failed before sending any Fekete polynomial
entries. Its preliminary empty upsert to `/api/table/T318/entries` was refused
with `NumberDBError: A value in these entries cannot be read as a number.
'str' object has no attribute 'items'`. A direct full-document write containing
the prose and the computed `Numbers` list succeeded, and the same generator
then verified the stored entries as `25/25 matched`.

What the skill says now: it says to create a draft before building and then
fill it with a generator, and it explains that a draft may have no numbers.
It does not say what to do when the client preflight refuses an empty draft
before any entry is sent.

What it should say: if a claimed draft has no `Numbers` section and
`Generator.publish()` fails during its empty writability check, do not change
the values to work around it. Send a full document with the checked entries
once, or add the entries through the entries endpoint directly, then run
`verify(sample=None)` against the stored draft. The failure is in the
preflight, not in the computed numbers.

Evidence: T318 on 2026-09-18. The failed command was
`cat "$NUMBERDB_KEY_FILE" | NUMBERDB_KEY_FROM_STDIN=1 NUMBERDB_PUBLISH=1
agents/sage.sh generators/fekete-polynomials/generate.py`; the direct fill
returned revision `833587cbe1f3781f089cbf709b2838679071bfa9a28b3e43f6cbb70690c47d53`,
and the final verification reported
`<VerifyReport T318: 25/25 matched, 0 differing, 0 missing, 0 extra>`.
