## The table you should link may be a draft, and the corpus search cannot see it

What happened: T406 (perturbation coefficients of the quartic anharmonic
oscillator) was read against the corpus and found to name, in a comment, the
operator $-y''+(x^2+\lambda x^4)y$ — which is the whole subject of T404,
drafted by the same account an hour earlier. T406 links nothing and has no
`Similar tables` section, and the search that would have found T404 answers
that there is nothing to link: `search_text('anharmonic')` and
`api/lookup?text=anharmonic` both return an empty `tables` list, *including
when the request carries the API key of the account that owns both drafts*.
The two tables are the clearest `Similar tables` pair in the batch — one holds
the eigenvalues, the other the coefficients of their perturbation expansion —
and the only reason neither points at the other is that neither could be
found.

What the skill says now: "`/drafts` lists what is being made right now and is
invisible from outside, so a table can be half-built and unfindable while you
start it again." That is said about the first question of step 1, whether the
table already exists. Nothing is said about the second question — what the
database already holds that this table should point at — where the same
invisibility does a different kind of damage: the answer comes back "nothing
to link" and looks like a fact about the corpus.

What it should say: beside the existing sentence about `/drafts`, that a
search answers only about *published* tables, so the corpus search settles the
duplication question and does not settle the linking one. Check `/drafts` for
both, especially for the other tables of your own batch, which is where
related drafts actually are. A link to a draft is allowed and expected:
`HREF{slug}` to an unpublished table resolves, and `audit_table --links`
checks a draft-to-draft link. Its slug cannot come from a search result, which
is where the skill otherwise says to read it, so take it from the draft's own
address bar or from the "back to table" link on `/files/T<n>`.

Evidence: 2026-09-22, T406 critique. `curl -sS -H "X-API-Key: ..."
https://numberdb.org/api/lookup --get --data-urlencode text=anharmonic`
returned `{"results": [], "tags": [], "tables": [], ...}` while
`/api/table?id=T404` and `/api/table?id=T406` both returned documents to the
same key; `text=quartic` returned nine published tables and neither draft.
The relation the link would carry was checked numerically:
$\sum_k 2^{1-k}E_0^{(k)}(10^{-3})^k$ from T406 reproduces T404's stored
eigenvalue at $\lambda=10^{-3}$ in all 49 digits.
