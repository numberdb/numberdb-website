## Sage's exact Wigner functions may need full Sage initialization in checks

What happened: while repairing T253, a Sage verifier imported `numberdb.sage`
and then `wigner_6j` from `sage.functions.wigner`. Comparing the stored rows
with Sage's exact `wigner_6j` failed inside Sage's algebraic conversion with
`NameError: name 'RR_1_10' is not defined`. Adding `import sage.all` before
the check initialized the missing lazy import, and the same comparison then
agreed on all 485 stored rows.

What the skill says now: import `numberdb.sage` before named Sage imports; it
also lists several things named imports do not bring, but not exact Wigner
functions or Sage's algebraic-number lazy imports.

What it should say: named imports are still the right default for generators,
but scratch checks that call Sage's exact special-function implementations may
hit lazy-import failures. If an independent Sage check fails inside Sage
initialization rather than in the value comparison, try fully initializing Sage
in the checker before weakening or dropping the check.

Evidence: `/tmp/verify_t253.py`, 2026-09-16. The first run under
`agents/sage.sh` failed in `wigner_6j` with `NameError: name 'RR_1_10' is not
defined`; after `import sage.all`, it printed `sage wigner_6j agrees on all
stored rows`.
