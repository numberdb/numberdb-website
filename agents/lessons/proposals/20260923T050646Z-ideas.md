## Sage's ball arithmetic has the incomplete gamma but not the incomplete beta

What happened: screening a batch of quantile tables meant checking that the
distribution functions being inverted can be evaluated with a certified error,
since that is what decides whether the tables can be `proven` rather than
heuristic. Half of them can be done directly and half cannot, and the
difference is not documented anywhere:

* `RealBall` has `gamma_inc` and `gamma_inc_lower`, so the regularised lower
  incomplete gamma -- and with it the chi-squared and gamma distribution
  functions -- is one call:
  `a.gamma_inc_lower(x) / a.gamma()`.
* `RealBall` and `ComplexBall` have **no incomplete beta at all**, so the
  Student $t$, $F$ and beta distribution functions have nothing to call.
  `ComplexBall` does not even have `beta`; the error suggests `zeta`.

The way through is `ComplexBall.hypergeometric`, which arb does carry:

    def betainc_reg(a, b, x):            # regularised I_x(a,b), certified
        a, b, x = C(a), C(b), C(x)
        beta = a.gamma() * b.gamma() / (a + b).gamma()
        return (x**a * (1 - x)**b / (a * beta)) * \
               x.hypergeometric([a + b, C(1)], [a + 1])

Two traps in those four lines. The Beta function has to be built from three
Gamma calls, because there is no method for it. And the argument of the
${}_2F_1$ is `self`, not a third argument: the natural-looking
`C(1).hypergeometric([a + b, C(1)], [a + 1], x)` is accepted -- the third
positional parameter is `regularized`, and a ball is truthy -- and returns
`nan + nan*I` rather than raising. A wrong call shape that silently returns
`nan` is worse than one that fails, because a generator that assigns it to a
value and never looks will publish nothing and report nothing.

What the skill says now: it names `RealBallField` and `ComplexBallField` as
the right tools for anything transcendental, and lists root finding,
`RealBall.str` and `QQ('1.25')` as things the named imports do not bring. It
says nothing about which special functions the ball classes actually have.

What it should say: before promising `proven` on a value, check that the
function has a ball method at all -- `dir()` on a ball is the whole test, and
it takes a second. Where it does not, the generalised hypergeometric function
of `ComplexBall` covers a great deal (the incomplete beta, and through it the
Student $t$, $F$ and beta distribution functions) and is where to look next.
Check any new ball call against a known value before building on it, because
a malformed one can return `nan` instead of an error.

Evidence: `agents/sage.sh /tmp/qcheck2.py` and `/tmp/qcheck5.py`, 2026-09-23,
SageMath in `numberdb/web:latest`.

* `dir(RealBallField(160)(1))` contains `gamma_inc`, `gamma_inc_lower`,
  `erf`, `erfi`, `log_integral`, `polylog`; it contains no incomplete beta.
* `ComplexBall` has `hypergeometric` and raises
  `AttributeError: 'sage.rings.complex_arb.ComplexBall' object has no
  attribute 'beta'. Did you mean: 'zeta'?`
* The wrong call shape returned `nan + nan*I` for three different inputs
  without raising.
* The corrected `betainc_reg` above, at `RealBallField`/`ComplexBallField`
  precision 160, gives the Student $t$ distribution function at
  $t_{10,0.975}$ as `[0.97499999999999999999999999999999999999999917 +/-
  5.64e-48]` and the $F$ distribution function at $F_{5,10,0.95}$ as
  `[0.95000000000000000000000000000000000000000437 +/- 4.99e-46]`, which is
  the certified evaluation a bisection needs.
