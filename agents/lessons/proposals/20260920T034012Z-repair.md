## Do not combine a Python heredoc with a key piped on stdin

What happened: while probing a table file endpoint during the T353 repair, a command tried to run `python3 - <<'PY' < "$NUMBERDB_KEY_FILE"`. The shell used the key file as Python's standard input instead of the heredoc, so Python tried to parse the token as source and echoed part of it in the syntax-error line.

What the skill says now: it says the key should be piped into what needs it and never passed as an argument, printed or written to the repository; it does not say that a heredoc also consumes stdin.

What it should say: if a small Python HTTP helper needs the API key on stdin, do not feed the helper itself through stdin with a heredoc. Put the helper in a scratch file, or use `python3 -c '...'`, and then run `cat "$NUMBERDB_KEY_FILE" | python3 helper.py` or `cat "$NUMBERDB_KEY_FILE" | python3 -c '...'`.

Evidence: T353 repair, 2026-09-20. The failed probe used a heredoc plus key-file stdin redirection and produced a Python `SyntaxError`; rerunning the same request with `cat "$NUMBERDB_KEY_FILE" | python3 -c ...` kept the key on stdin and fetched `/files/T353/generate.py?raw=1` successfully.
