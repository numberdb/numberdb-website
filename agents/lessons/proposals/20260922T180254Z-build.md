## Parse rational parameter strings by hand in named-import Sage generators

What happened: the Falkner-Skan momentum-thickness generator enumerated the
rational parameter $\beta$ as NumberDB entry text, for example `-19/100`, and
then tried to recover it with `QQ(params["beta"])` inside `value()`. In the
named-import Sage environment used by `agents/sage.sh`, even that fractional
string conversion reached an uninitialised Sage module and failed with
`AttributeError: module 'sage.rings' has no attribute 'real_mpfr'`. Replacing
it with a tiny parser, splitting `a/b` and building `QQ(int(a))/QQ(int(b))`,
fixed the dry-run failure.

What the skill says now: it warns that `QQ('1.25')` fails and says to build a
rational from the decimal string by hand. It does not say that a fractional
string such as `'-19/100'` can hit the same named-import path.

What it should say: in a generator, do not rely on `QQ(text)` for parameter
text read back from NumberDB. If the text is an entry identity, parse the
integer or `a/b` spelling yourself and construct the rational from integers;
use the same hand parser for decimal spellings.

Evidence: T416 build, `agents/sage.sh /tmp/run_numberdb_dry.py ...`, failing
in `generate.py` at `beta = QQ(beta)` with `AttributeError: module
'sage.rings' has no attribute 'real_mpfr'`; commit `d681f89` changes it to
manual parsing.
