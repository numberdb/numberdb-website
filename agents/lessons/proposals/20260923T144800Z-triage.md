## A `429` from this API has two meanings — one clears by waiting and the other never does, and the draft ceiling is the second one

What happened: before deciding whether a stalled campaign had room to create
anything, I needed to know how many drafts this key may hold. Every build
prompt in this project says "may hold up to five drafts"; a previous run had
counted **23** unpublished tables under the key and recorded the discrepancy
as unresolvable from outside, because the API document carries no publication
or review field — its top-level keys are `Comments`, `Data properties`,
`Definition`, `Display properties`, `Formulas`, `Keywords`, `Links`, `Numbers`,
`Parameters`, `References`, `Similar tables`, `Tags`, `Title` — and its advice
was to create a draft and read `drafts_held` out of the answer. That advice
spends a slot to find out how many slots are left, and it is not necessary.

The rule is three functions in `numberdb_app/permissions.py`:

    DRAFTS_IN_FLIGHT      = getattr(settings, 'NUMBERDB_DRAFTS_IN_FLIGHT', 15)
    BULK_DRAFTS_IN_FLIGHT = getattr(settings, 'NUMBERDB_BULK_DRAFTS_IN_FLIGHT', 100)

    def draft_ceiling(user):
        return (BULK_DRAFTS_IN_FLIGHT if is_bulk_drafter(user)
                else DRAFTS_IN_FLIGHT)

    def draft_allowance(user):
        if is_board_member(user):
            return (None, Table.objects.filter(created_by=user, published=False).count())
        held = Table.objects.filter(created_by=user, published=False).count()
        return (max(0, draft_ceiling(user) - held), held)

Two things follow that a caller would not guess.

**The ceiling is not five.** It is 15 by default, 100 for the bulk-drafts
group, and unlimited for a board member — and the site operator sets both from
the environment (`numberdb/settings/base.py:391-399` reads
`NUMBERDB_DRAFTS_IN_FLIGHT` and `NUMBERDB_BULK_DRAFTS_IN_FLIGHT`), so an
instance may serve different numbers. Nothing in the API or the skill says so,
and the number a contributor is most likely to be carrying — five — is three
times too small against the smallest of them.

**Offering a draft for review does not give the slot back.** `draft_allowance`
counts every `published=False` table the account created, in any state. A draft
you finished, offered, and consider done still occupies its slot until a
reviewer publishes it — and publishing is a person's act you cannot perform or
schedule. So an account that works faster than its reviewers fills up and
stays full. The refusal's own `detail` says *"The limit is on drafts in flight
rather than on drafts made"*, which reads as though offering releases one. It
does not; only publication does.

The refusal, from `numberdb_app/api.py`, `create_table`:

    429  {"error": "This account already holds 23 unpublished drafts.",
          "detail": "Publish one, or abandon it, and then this will go
                     through. The limit is on drafts in flight rather than
                     on drafts made: ..."}

**That status code is the trap.** `429` is the one status every HTTP client
library and every retry helper treats as "you are going too fast, back off and
try again" — and this particular 429 will still be there in an hour, in a day,
and after any backoff a program can express, because the thing that clears it
is a human being publishing a table. A `while True: sleep(backoff); retry`
around table creation spins for ever here, quietly, looking exactly like a
slow server.

This site really does have a rate limiter, which really does mean "wait", and
it answers with the same code (`numberdb_app/throttle.py`):

    429  {"error": "Rate limit exceeded (60 requests per 60 minutes). An API
                    key raises this limit; see /help#section-api.",
          "retry_after": 1130}
    Retry-After: 1130

**The two are distinguishable, and only by the body.** The rate limiter sets a
`retry_after` key and a `Retry-After` header; the draft ceiling sets neither.
So: a `429` carrying `Retry-After` is worth sleeping on. A `429` without one is
a standing refusal, and the right response is to stop and tell somebody, not to
retry.

One supporting detail, because it is how you count your own drafts without
creating one: a draft answers only to its author and the board
(`api.table` → `_may_see_draft`). To anybody else,
`GET /api/table?id=T443` returns — at **HTTP 200**, not 404 —
`{"error": "Table with id 'T443' does not exist."}`, and `https://numberdb.org/T443`
answers 404. Fetching your own T-numbers *with your key* and counting the ones
the public cannot see is the read-only way to learn where you stand:

    T442  public 200   keyed: Zarankiewicz numbers $z(m,n;s,t)$            published
    T443  public 404   keyed: Values of the Hastings-McLeod solution q(s)   draft
    T444  public 200   keyed: Cumulants of the Tracy-Widom distributions    published
    T445  public 404   keyed: Skewness and excess kurtosis of Tracy-Widom   draft
    T446  public 404   keyed: does not exist                                free

What the skill says now: nothing about a ceiling. `SKILL.md:753-774` gives the
five acts — propose as a draft with `POST /api/tables` and `X-Draft: yes`, fill
it, offer it with `X-Draft: ready` or the button on `/drafts`, somebody reviews
it, it is public — and tells the reader not to expect to do step 4. It never
says that step 3 leaves the slot occupied, that there is a limit on how many
may be open at once, or what the refusal looks like.

What it should say:

- **There is a ceiling on unpublished drafts per account**, enforced at
  creation: 15 by default, higher for some accounts. Not five.
- **Offering a draft for review does not free its slot.** Only publishing does,
  and publishing is somebody else's act. If you are making tables faster than
  they are being reviewed, you will stop being able to make them.
- The refusal is **`429` with `"This account already holds N unpublished
  drafts."` and no `Retry-After`.** Do not retry it — nothing you can do makes
  it pass. Publish one, abandon one, or stop and say so.
- **Check for `Retry-After` before treating any `429` from this API as
  transient.** With it, sleep and retry; without it, the refusal is standing.
- After a successful create, the answer carries `drafts_held` and
  `drafts_remaining`. Read them, so the next create is not a surprise.
