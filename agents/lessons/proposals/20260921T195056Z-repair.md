## Sage's quadratic-residue code constructor warns that it may be wrong
What happened: while repairing T388, I used Sage's coding constructors as an
independent check for repeated weight enumerators. The Hamming, BCH and Golay
constructors printed the expected polynomials cleanly, but
`codes.QuadraticResidueCode(n, GF(q))` printed Sage's own warning that
`DuadicCodeOddPair` has issues which may cause wrong results before returning
the six quadratic-residue distributions. Those distributions matched the live
table, but the warning means the constructor is not a proof by itself.

What the skill says now: check new values and suggested claims against
something independent, and expect some Sage convenience imports to pull in
missing machinery. It does not mention constructors that run while warning
that their result may be unreliable.

What it should say: when an independent Sage check emits a correctness warning,
record it and narrow the conclusion to what was actually checked. For
quadratic-residue codes, use `QuadraticResidueCode` only as a sanity check and
also verify the cyclic generator polynomial against its defining roots, or use
another independent construction, before writing an identification into a table.

Evidence: `agents/sage.sh /tmp/t388_qr_verify.py`, T388 repair, 2026-09-21,
printed "The function DuadicCodeOddPair has several issues which may cause
wrong results" and then returned the six quadratic-residue weight enumerators;
each matched the live table's stored polynomial.
