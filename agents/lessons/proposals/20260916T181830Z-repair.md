## Check rational inequalities as integer inequalities when possible
What happened: while repairing T279, a Sage check tried to verify
$\frac1p+\frac1q+\frac1r<1$ as `ZZ(1) / p + ZZ(1) / q + ZZ(1) / r < 1`.
In the modular Sage environment this failed inside rational coercion with
`AttributeError: module 'sage.rings' has no attribute 'real_mpfr'`. The same
claim checked cleanly as the exact integer inequality
`p*q + p*r + q*r < p*q*r`, which is also the form the generator used.

What the skill says now: it warns that division in a generator is where
exactness goes, and that named Sage imports need `numberdb.sage` first, but it
does not say to prefer algebraically equivalent integer inequalities when the
claim is rational.

What it should say: when a rational inequality has a positive common
denominator, clear denominators and check it as an integer inequality. It is
exact, avoids accidental Python or Sage coercion paths, and often matches the
guard a generator should use.

Evidence: `agents/sage.sh /tmp/check_t279_repair.py /tmp/t279-repaired.yaml`
failed on `ZZ(1) / sp` with `module 'sage.rings' has no attribute
'real_mpfr'`; after replacing it by `sp*sq + sp*sr + sq*sr < sp*sq*sr`, the
same script printed `checked 9 stored solutions, the excluded x=1 family,
labels, and entry comments`.
