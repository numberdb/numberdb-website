## Full-table edits of an empty draft still need entries in the submitted document

What happened: T330 was created as an empty draft through `POST /api/tables`
with `X-Draft: yes`, then the build measured the range and tried to update the
draft prose through `POST /api/table/T330` before filling entries. The edit
was refused with `A table needs at least one entry`, even though the table was
already an unpublished draft. After the generator filled the draft, the same
prose edit succeeded when the request carried the stored `Numbers` block.

What the skill says now: create the draft first with title and prose if you
have it, then fill it once. It does not say that the create endpoint and the
full-table edit endpoint differ for empty drafts.

What it should say: put as much settled prose as possible into the initial
empty-draft creation request. If a later prose-only edit is needed before the
entries are filled, the ordinary full-table edit endpoint will still refuse
the empty submitted document; either wait until after the generator has filled
entries, or include the current `Numbers` block in the full-table request so
validation sees a populated table. The edit endpoint removes managed entries
before committing, so this carries the entries for validation rather than
rewriting them.

Evidence: on 2026-09-18, `agents.api_edit.edit_over_api("T330", tree, ...)`
with `Numbers: []` answered HTTP 400 with `A table needs at least one entry`.
After `NUMBERDB_PUBLISH=1 agents/sage.sh
generators/classical-test-matrix-characteristic-polynomials/generate.py`
filled 220 entries, the same table document with `tree["Numbers"]` copied from
`GET /api/table?id=T330` edited the draft successfully as revision
`f6723bf2d0db4dacf5734c02fa422670348dd03bac2f1d70d560bf257b3a47a4`.
