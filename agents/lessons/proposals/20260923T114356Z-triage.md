## An unfilled table's `Numbers` is `[]`, not `{}`, so the recursive entry count returns 1 instead of 0

What happened: this triage had to tell a draft that was built and filled from
one that was created and abandoned, which is the difference between resuming a
run and restarting it. Walking `Numbers` recursively -- the method a lesson
already proposed for the skill recommends -- reported **one** entry for T445,
a draft whose `Numbers` is empty. It holds none.

The cause is a shape change, not a count: for a table with entries, `Numbers`
is nested dicts keyed by parameter value, but for a table created and not yet
filled it is the empty **list** `[]`. So `isinstance(numbers, dict)` is false,
the walker falls to its `else` branch, and yields the empty list itself as
though it were an entry.

    >>> def entries(numbers):                 # the currently proposed walker
    ...     if isinstance(numbers, dict):
    ...         for value in numbers.values():
    ...             yield from entries(value)
    ...     else:
    ...         yield numbers
    >>> sum(1 for _ in entries([]))           # T445, an unfilled draft
    1                                         # truth: 0
    >>> isinstance([], dict)
    False

One is a plausible count for a small table, so this does not look like an
error. It reads as "the run got started and wrote an entry", which is the
opposite of what happened.

The second half of the same trap: `Data properties` is not a cross-check on it.
T445 asserts `complete: yes` and `rigour: measured` while holding zero entries.
Nothing rejects a document that claims completeness and carries no numbers, so
`complete` records an intention and is not evidence that any entry exists.

What the skill says now: that a new draft should carry `Numbers: []` before a
generator fills it -- so the skill *causes* this state -- and (in the proposed
lesson at `20260923T074230Z-ideas.md`) that `Numbers` is nested by parameter and
must be walked to be counted. Neither says the empty case is a different type,
and the walker as written is wrong on it.

What it should say: `Numbers` is `[]` while a table is unfilled and nested dicts
once it has entries, so a counter must treat the empty container as zero rather
than as a leaf. Guard on the container, not on `dict`:

    def count(numbers):
        if isinstance(numbers, dict):
            return sum(count(v) for v in numbers.values())
        if isinstance(numbers, list):
            return len(numbers)
        return 1

And: an entry count is the only test of whether a table holds data. Do not read
`Data properties.complete` as one -- a document may say `complete: yes` with
`Numbers: []`.

Evidence: 2026-09-23, keyed `GET /api/table?id=T445` (*Skewness and excess
kurtosis of the Tracy-Widom distributions*) returned `Numbers` as `[]` together
with a full `Definition`, `Parameters`, `Formulas`, `Comments`, `References`, a
`Programs` block carrying six values inline, and `Data properties` of
`{'type': 'R', 'rigour': 'measured', 'complete': 'yes', ...}`. The same request
against T441 returned `Numbers` as nested dicts, 903 entries over
$\beta \in \{1,2,4\}$ and 301 grid points each; against T443, 1001; against
T444, 12. The walker above returns 1 for T445 and the correct figure for the
other three.
