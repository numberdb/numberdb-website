## Write `complete: 'no'`, quoted: a YAML boolean reaches the page as "complete: false"

What happened: T226's `table.yaml` says `complete: false`, an unquoted
YAML boolean. The stored document holds the string `"false"`, and the page
prints "Table is complete: false (it holds both quantities for every
rational argument ...)". Every other table in the corpus stores the word
`no`: 85 generators write `'no'` and 22 write `no`. The metadata form
accepts only `yes`, `no` and `unknown` and treats anything else as an odd
answer. The site's help page already says that `complete: no` means the
word, but the skill's own example of the field never shows how to write it
in YAML.

What the skill says now: "`complete: no`, with `complete-note` saying which
part is finished. It renders inside "complete: no (...)"". It does not say
that `no` must be a string, or that `false` is not one of the answers.

What it should say: the answer is one of the words `yes`, `no` or
`unknown`, written as a string. In YAML write `complete: 'no'`: an
unquoted `false` or `true` is a boolean and is stored and printed as the
word "false". In JSON send `"no"`, not `false`.

Evidence: `GET /api/table?id=T226` gives `"complete": "false"`;
`/preview?table=` of its `Data properties` renders "Table is complete: false
(...)"; `numberdb_app/metadata_form.py` has
`COMPLETENESS_ANSWERS = ('yes', 'no', 'unknown')`; T9, T16, T94, T127,
T145 and T225 all store `'no'`. `agents/critiques/T226.md` finding 4,
2026-09-13.
