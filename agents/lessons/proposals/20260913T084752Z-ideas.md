## `from sage.functions... import` fails outright after `import numberdb.sage`; use ball methods instead

What happened: a check script began with `import numberdb.sage as numberdb`,
then named ring imports, then `from sage.functions.other import floor`. The
last import raised `AttributeError: cannot access submodule 'function' of
module 'sage.symbolic' (most likely due to a circular import)`, raised from
`sage/symbolic/expression.pyx`. The same script without that line ran, and
so did a control that imports only `numberdb.sage`. So the symbolic function
modules cannot be imported at all this way: it is not a missing method but a
failed import. Everything the check needed exists as a method on balls
(`RealBall.psi`, `.cos`, `.sin`, `.log`, `ComplexBall.zetaderiv`,
`.barnes_g`), or in plain Python (`//` for floor).

What the skill says now: "What else the named imports do not bring: root
finding (`sage.numerical.optimize`), `RealBall.str`, and `QQ('1.25')`".

What it should say: add that `sage.functions.*` (`floor`, `gamma`, `psi`,
`zeta` as symbolic functions) cannot be imported after `numberdb.sage`; the
import fails with a circular-import error. Use the methods of
`RealBallField`/`ComplexBallField` elements, which are also the rigorous
ones.

Evidence: Sage 10.9. `/tmp/imp.py` printed `10.9` and then `AttributeError
cannot access submodule 'function' of module 'sage.symbolic'`; the control
`/tmp/imp0.py` printed `control ok`.

## Derivatives of the Hurwitz zeta function in ball arithmetic: `_zeta_series(n, a, deflate)`

What happened: `ComplexBall.zetaderiv(k)` differentiates the **Riemann**
zeta function only, and there is no `ComplexBall` method for
$\partial_s\zeta(s,a)$. The polynomial ring over `ComplexBallField` has
`Polynomial_complex_arb._zeta_series`, which wraps arb's `acb_poly_zeta_series`.
The first call, written as `(s0 + t)._zeta_series(a, False, 2)`, raised
`TypeError: an integer is required`. The argument order is
`_zeta_series(n, a, deflate)`: the truncation length first.
`(P(-1)+t)._zeta_series(2, CBF(x), False)` then gives
$[\zeta(-1,x),\ \zeta'(-1,x)]$ as its coefficients. With `deflate=True` at
$s_0=1$ it drops the $1/(s-1)$ pole. So
$L'(1,\chi)=q^{-1}\sum_a\chi(a)\,[\text{coeff}_1-\log q\cdot\text{coeff}_0]$
is a ball computation in which the poles cancel exactly.

The results were checked against independent routes.
$\exp(\zeta'(-1,x)-\zeta'(-1))$ agreed with $\Gamma(x)^{x-1}/G(x)$ to 88
digits at five $x$. $\gamma+L'(1,\chi_D)/L(1,\chi_D)$ agreed with PARI's
`lfun(L,1,1)/lfun(L,1)` to 60 digits at seven $D$.

What the skill says now: it lists arb functions (`zeta`, `zetaderiv`,
Hurwitz `zeta(s, a)`), and nothing on derivatives in $s$ of the Hurwitz zeta
function or of Dirichlet $L$-functions.

What it should say: for $\zeta'(s,a)$ and $L'(s,\chi)$ use
`PolynomialRing(CBF,'t')`, `(s0 + t)._zeta_series(n, CBF(a), deflate)`;
the length comes first, and `deflate=True` removes the pole at $s_0=1$. It is
an underscore method, so the generator should say which Sage version it was
run on.

Evidence: `/tmp/chk2.py` (the K-function rows) and `/tmp/ek.py` (seven
discriminants against PARI), 2026-09-13, Sage 10.9.
