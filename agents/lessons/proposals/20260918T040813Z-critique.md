# Proposed from the T320 critique, 2026-09-18

## The audit's unlinked-family check is off between a table and its own near-namesake

What happened: T320, "Complementary Shapiro polynomials $Q_n$", has a
Definition reading "the sequence $Q_n\in\mathbb Z[x]$ defined together with the
Shapiro polynomials $P_n$ by ...". "Shapiro polynomials" is the title of T319,
which the corpus holds and which this table does link, elsewhere. The audit
answered `{"findings": [], "clean": true}`, and it would have answered the same
if the table had linked T319 nowhere at all, because its unlinked-family check
skips that pair by construction.

The rule, in `audit_table.py`: for each other table it takes the title with the
LaTeX stripped, and

    if own and (name.lower() in own.lower() or own.lower() in name.lower()):
        continue

`own` here is "Complementary Shapiro polynomials" and `name` is "Shapiro
polynomials", so the containment holds and the check never looks at the prose.
The guard is there for a good reason -- it stops a table being told to link
itself under a variant of its own name -- but the tables it silences are
exactly the neighbours most likely to need the link: "Bernoulli numbers" and
"Generalized Bernoulli numbers", "Hermite polynomials" and "Hermite polynomials
in probabilist's convention", any "X" and any "complementary X", "generalized
X", "X of the second kind". The check is off in both directions for every such
pair.

Two other things the same run met, which together make the point that linking
is the author's job here and not the tool's:

* An `HREF` in a **Definition** is refused outright -- "Definition links to
  another table; a cross-reference belongs in Similar tables or a comment" --
  so the skill's "link the first mention, once per section" does not reach the
  Definition at all, and the link has to go in `Comments` or `Similar tables`
  instead. (This half is already proposed, six times over, from the repair runs
  of 2026-09-16 and 2026-09-17; it is repeated here only because it is what a
  contributor will try first after reading the paragraph above.)
* The check also matches on the title alone, so a family named by a phrase the
  title does not use -- "the Rudin-Shapiro rule" for T319 -- is invisible to it
  whatever the titles are.

What the skill says now: "Is anything named that should be linked? ...
`audit_table` finds the easy cases; you can see the ones where the phrase
differs from the title." That is true and it is not the whole rule: the phrase
here is *identical* to the title and the audit still says nothing.

What it should say: the audit's unlinked-family check stands down whenever one
title contains the other, so between a table and its own near-namesake --
"complementary X" and "X", "generalized X" and "X", "X of the second kind" and
"X" -- a clean audit is not evidence that the link is there. Check that pair by
reading. And since a Definition may not carry an `HREF`, the place for it is
the first mention in `Comments` or the relation in `Similar tables`.

Evidence: 2026-09-18, T320 critique. `GET /api/table/T320/audit` ->
`{"tid": "T320", "title": "Complementary Shapiro polynomials $Q_n$",
"findings": [], "clean": true}`, on a document whose Definition names the
Shapiro polynomials without linking them.
`numberdb_app/management/commands/audit_table.py`, the family loop after
`own = _bare_title(tree.get('Title') or '')`, has the containment `continue`
quoted above; `_FRAGMENT` does not empty either bare title, so both reach it.
