## Power-series `exp()` can pull in symbolic Sage under named imports
What happened: while repairing T334, a Sage check first tried to get the Todd
series from `PowerSeriesRing(QQ, "x")` as `(x / (1 - (-x).exp())).log()`.
Run through `agents/sage.sh` after `import numberdb.sage` and named imports,
that failed before any table computation with
`AttributeError: cannot access submodule 'function' of module 'sage.symbolic'`,
via `sage.data_structures.stream` importing `sage.functions.other.binomial`.
The same check worked after replacing the power-series `exp()`/`log()` call
with explicit Bernoulli coefficients for `log(x/(1-exp(-x)))`.

What the skill says now: it says named imports can leave some Sage machinery
unavailable, and names root finding, `RealBall.str`, and decimal strings for
`QQ`, but not power-series exponential.

What it should say: when writing a generator or program snippet under named
Sage imports, power-series `exp()` may fail for the same reason as
power-series `log()` and `inverse()`. If the needed series has known
coefficients, compute those coefficients directly rather than routing through
symbolic Sage.

Evidence: T334 repair, 2026-09-18. `/tmp/t334_math_check.py` failed on
`(-x).exp()` with the traceback above; the replacement using
`log_q_coefficient(1)=1/2` and
`log_q_coefficient(2k)=-B_{2k}/((2k)(2k)!)` then matched all seven stored
entries and confirmed the checks through `n=11`.
