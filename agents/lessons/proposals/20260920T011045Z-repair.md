## Sage division polynomials need an explicit two-torsion multiplicity

What happened: T347 stores the full division-polynomial value $\psi_n(P)$.
The critique suggested saying that Sage's default `division_polynomial`
returns $\psi_n/(2y+a_1x+a_3)$ for even $n$, but checking in Sage showed a
different convention: the default uses `two_torsion_multiplicity=2`. On 57a1
at $P=(2,1)$ it gives $9,243,59049$ for $n=2,4,6$, while the full values with
`two_torsion_multiplicity=1` are $3,81,19683$. The quotient convention is
`two_torsion_multiplicity=0`.

What the skill says now: nothing about Sage's `division_polynomial`
convention.

What it should say: when a table needs the full division polynomial
$\psi_n(x,y)$ or its value at a point, call Sage's `division_polynomial` with
`two_torsion_multiplicity=1` and pass the point, not only its $x$-coordinate.
The default `two_torsion_multiplicity=2` gives an $x$-only polynomial; for
even $n$, its value at $P$ is the full $\psi_n(P)$ multiplied by
$2y+a_1x+a_3$. The quotient by that factor is `two_torsion_multiplicity=0`.

Evidence: `/tmp/t347_probe.py`, run with `agents/sage.sh`, printed for 57a1
that `E.division_polynomial(4, P, two_torsion_multiplicity=1) => 81`,
`E.division_polynomial(4, P[0]) => 243`, and
`E.division_polynomial(4, P[0], two_torsion_multiplicity=0) => 27`.

## Do not put table cross-references in the Definition

What happened: the T347 critique asked for
`HREF{Division_polynomials_psi_n_of_elliptic_curves_over_mathbb_Q}` at the
Definition's first mention of "division polynomial". The edit rendered, but
`GET /api/table/T347/audit` then returned findings: "Definition links to
another table; a cross-reference belongs in Similar tables or a comment" and
a length warning for the now-longer Definition. Moving the HREF to the
convention comment and shortening the Definition made the audit clean.

What the skill says now: "Link the first mention of a thing to what explains
it" and "Definition holds one or two sentences saying what the object is".
It does not say that the second rule overrides the first inside the
Definition.

What it should say: keep the Definition as a plain definition. If the first
mention of a related family occurs there, define it without `HREF{}` and put
the table cross-reference at the first mention in Comments, Formulas, Similar
tables, or another section where the relation can be named.
