## The client preflight can fail on an empty draft with no `Numbers` section

What happened: T396 was created as an empty draft, following the stage-two
claim-first workflow. Running the generator with `NUMBERDB_PUBLISH=1` did not
send any entries. The client first called its writability preflight, which posts
an empty upsert to `/api/table/T396/entries`, and the server refused that
request with `A value in these entries cannot be read as a number. 'str' object
has no attribute 'items'`. A full-document write containing the checked prose
and the generated `Numbers` section filled the draft successfully, and the
generator then verified all stored entries.

What the skill says now: create the draft before building, then fill it with a
generator. It does not say that a draft with no `Numbers` section may trip the
client's empty-entry preflight before the generator sends the real entries.

What it should say: if `Generator.publish()` refuses an empty draft before
computing entries, with an error from the empty upsert preflight rather than
from one of the values, fill the first revision with a full checked document or
otherwise add an empty `Numbers` section before using the entries-only publish
path. Do not create a second title to get around the refusal; the draft has
already claimed the proposal.

Evidence: on 2026-09-22, `NUMBERDB_PUBLISH=1 agents/sage.sh
generators/characteristic-polynomials-matroids/generate.py` for T396 failed
inside `numberdb._write.check_writable()` with the server message above. A
subsequent `PUT /api/table/T396` carrying the same prose and 147 generated
entries succeeded, and `verify(sample=None)` reported `147/147 matched`.
