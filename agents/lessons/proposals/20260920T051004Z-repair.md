## Use PARI directly when Sage irreducibility pulls in missing polynomial machinery

What happened: while checking T284, a Sage script using the skill's named-import style rebuilt the stored integer polynomials and called `f.is_irreducible()`. On the irreducible test polynomial `x^3 - x - 1`, that raised `ImportError: cannot import name PolynomialSequence_generic`, through Sage's polynomial factorization path. A reducible control polynomial returned `False`, so checking only a reducible example would have hidden the problem. Importing PARI directly with `from sage.libs.pari import pari` and using `bool(pari(f).polisirreducible())` worked on both controls.

What the skill says now: it says to import `numberdb.sage` before named Sage imports, and it lists some things named imports do not bring, including root finding, `RealBall.str`, and decimal-string rationals. It does not mention polynomial irreducibility or factorization.

What it should say: for integer polynomial irreducibility checks in a named-import generator, if `f.is_irreducible()` or `f.factor()` reaches missing Singular or polynomial-sequence machinery, call PARI directly:

```python
from sage.libs.pari import pari

irreducible = bool(pari(f).polisirreducible())
```

Run both an irreducible and a reducible control, because the reducible case may return before Sage reaches the failing path.

Evidence: `/tmp/t284_repair_check.py` failed on 2026-09-20 with `ImportError: cannot import name PolynomialSequence_generic` at `f.is_irreducible()`. `/tmp/t284_irred_workaround.py` then printed `sage is_irreducible raised ImportError ...` and `pari polisirreducible True` for `x^3 - x - 1`, and `sage is_irreducible False` and `pari polisirreducible False` for `(x^2 + 1)(x + 1)`.
