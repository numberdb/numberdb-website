# Lessons proposed by the T435 build, 2026-09-23

## `group parameters` must still name hidden component parameters

What happened: T435 was created with parameters `m1`, `m2`, `m3` and a hidden
component parameter `part`, but its display grouping was
`group parameters: [[m1, m2, m3]]`. The draft page showed the prose, but the
entries endpoint refused every generated entry with "entry 0 names a parameter
'part' that the table does not declare. Declared: m1, m2, m3." The omitted
parameter was not only omitted from the visual grouping; it was omitted from
the nesting shape used to parse entries.

What the skill says now: it explains that `group parameters` controls grouped
labels and that `param-latex` replaces a group label, but it does not say that
the groups are also the parameter list used by the entries parser.

What it should say: when a table sets `Display properties: group parameters`,
the groups must name every parameter exactly once, including parameters hidden
from the parameter list such as `part` or `component`. If a hidden parameter is
not part of a grouped key, give it its own one-parameter group, for example
`[[m1, m2, m3], [part]]`.

Evidence: 2026-09-23, draft T435. The first fill attempt from
`generators/markov-triples/generate.py` was refused by `/api/table/T435/entries`
with the "part" parameter error. Rewriting the document with
`group parameters: [[m1, m2, m3], [part]]` let the same generator verify
`456/456 matched`.
