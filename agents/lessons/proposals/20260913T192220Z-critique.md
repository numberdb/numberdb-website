## A `Programs` entry is a record with `language` and `code`; a bare string is accepted and breaks the page

What happened: draft T233 was written with

    Programs:
      sage: "Run `sage -python generate.py` to compare ..."

The API stored it, and `audit_table` passed it: its Programs check reads
`program.get('code') if isinstance(program, dict) else ''`, so a string is
skipped. The page cannot render it. `table_context` reads
`program['language']`, and the preview answered "Error while Parse program
sage: string indices must be integers, not 'str'", with no sections at all.
The table page calls the same function, so the table itself fails, not only
one section. A string that describes the generator was also the wrong content:
`Programs` is for the standard incantation.

What the skill says now: the section table says `Programs` holds "the standard
incantation … for a reader who wants one more value", and the text says
`Programs` and `generate.py` answer different questions. Nothing gives the
shape of an entry.

What it should say: each `Programs` entry is a labelled record,
`program-sage: {language: Sage, code: "..."}`, like `Links` (`title`, `url`)
and `References` (`bib`). A bare string is accepted on write and makes the
page fail, so preview a table after writing `Programs`. Separately, the server
or `audit_table` should refuse a non-record entry, since nothing else catches
it.

Evidence: `/tmp/crit233/p_d.html` (the preview with the stored `Programs`:
the error line and no sections) and `/tmp/crit233/q_prog_fixed.html` (the same
text wrapped as `{language, code}`: rendered), 2026-09-13;
`numberdb_app/views.py` lines 912–924 and 1458; `audit_table.py` line 394.
