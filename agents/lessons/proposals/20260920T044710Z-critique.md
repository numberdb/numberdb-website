# Lessons proposed by the 20260920T044710Z critique run (T357)

## A `Programs` entry must be a record, not a sentence, and nothing tells you until somebody loads the page

What happened: T357 stored

    Programs:
      sage: "In Sage, compute $r = 1/(1/p + 1/q - 1)$ and then compute
             `(A(p) * A(q) / A(r)) ** n` in a `RealBallField`, with ..."

a string where the renderer wants a record with `language` and `code`. The
write API accepted it, `verify` has nothing to say about it, and
`audit_table` reported nothing -- its one `Programs` check reads
`program.get('code') if isinstance(program, dict) else ''`, so it guards
itself against exactly this shape and then stays silent. The table page is
where it fails: `table_context` does `program['language']`, gets
`TypeError: string indices must be integers`, and re-raises it as
`ValueError: Error while Parse program sage: ...`. The view does not catch
that, so the page is a 500 -- for the author now and for every reader if it
is published.

The trap is that a draft is the one thing whose page nobody can load. The
author cannot see it, a reviewer opening the queue cannot see it, and every
check that *can* be run on a draft passes.

What the skill says now: what `Programs` is *for* -- "the standard incantation
in Sage, PARI or mpmath for a reader who wants one more value" -- and nothing
about the shape it is written in. The section table in part 4 gives the field
shapes for `References` (`bib`, and `arxiv`/`doi`/`zbl`/`mr` beside it) and
for nothing else.

What it should say: a `Programs` entry is a record, one per label:

    Programs:
      program-sage:
        language: Sage
        code: |
          import numberdb.sage as numberdb
          ...

`language` picks the syntax highlighting (`Sage` gives Python's) and `code` is
shown verbatim. A string in place of the record is accepted by the API and by
the audit and makes the table page raise. And, more generally: neither
`verify` nor `audit_table` renders a table, so the *only* check that a
document can be displayed is to display it -- see the next lesson for how to
do that on a draft without a login.

Evidence: 2026-09-20, T357. `GET /api/table/T357/audit` returned two tag
findings and nothing about `Programs`. The page rebuilt from the same document
raised at `numberdb_app/views.py:914`, through `views.py:1461`,
`views.py:444`, `views.py:613`; with `Programs` replaced by
`{program-sage: {language: Sage, code: ...}}` and nothing else changed, the
same rebuild returned 200 and 731,648 bytes. T354, T355 and T356 carry the
record shape and render.

## `GET /preview?table=<yaml>` renders a document through the site's own code, with no account and no draft

What happened: the T357 critique had to read the rendered page of a private
draft. `/T357` is 404 to anybody without a session, and an API key does not
help -- the HTML routes authenticate by session, and `/preview/T357` makes the
same draft check. What does work, from anywhere, signed out:

    curl -s --get --data-urlencode "table@/tmp/doc.yaml" \
        https://numberdb.org/preview

`/preview` takes a whole document in the `table` query parameter and renders
it through `build_preview_context` -> `table_context`, which is the same
function the table page uses. It writes nothing, needs no account, and needs
no table to exist. That is how finding 1 above was located to a single field,
before any heavier machinery: send the prose sections and a handful of
entries, see what comes back.

Two limits worth knowing before relying on it. The request line is capped near
4 kB, so a document of any size has to go in pieces -- Title plus two or three
sections at a time, with `Numbers: [3.14]` standing in. And when
`table_context` raises, `/preview` catches it and shows the message in an
`alert-danger` banner with the rest of the page blank, where the table page
would return a 500; so a blank preview with a banner is the signal, and the
banner text names the field (`Error while Parse program sage: ...`).

Two things that are not faults of the document and will show up anyway:
`CITE{some-formula}` renders as the bare word unless the `Formulas` section is
in the same piece, and `Keywords` never renders at all, being index-only.

What the skill says now: nothing about `/preview`. Section 9 says a draft "is
invisible, in no listing, answers no search", which is true and leaves the
author with no way to see their own page before a reviewer does.

What it should say: check that the table renders before offering it for
review, because nothing else does -- `verify` compares numbers and
`audit_table` reads the document, and neither builds a page. `/preview` is the
way, it needs no credentials, and it takes the document a few sections at a
time.

Evidence: 2026-09-20, T357. `/preview?table=` with Title + Definition + Links
+ References returned the rendered prose with the Wikipedia citation numbered
`[3]`; with Title + Programs it returned the banner "Error while Parse program
sage: string indices must be integers, not 'str'" and an empty page; a
4000-character document answered 400 and a 3000-character one 200.
