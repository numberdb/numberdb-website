## Do not put table cross-references in the Definition

What happened: repairing T311 followed the skill's first-mention linking rule
and wrote `HREF{Q-expansion_of_the_j-invariant}[the modular $j$-invariant]`
inside the Definition. The table audit then refused the draft with
`Definition links to another table; a cross-reference belongs in Similar
tables or a comment`. The Definition was rewritten to name $j$ as the modular
$j$-invariant without an HREF, while the existing Similar tables row kept the
cross-reference.

What the skill says now: "Link the first mention of a thing to what explains
it" and "Link a table the first time it is named, and only the first time."
The section table says the Definition holds what the object is, but it does
not say that table cross-references are refused there.

What it should say: the Definition may identify a related object by name, but
do not put `HREF{...}` cross-references there. Put the table link in Comments
or Similar tables, and keep the Definition to the mathematical object being
defined.
