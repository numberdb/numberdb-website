# Lessons proposed by the T360 repair, 2026-09-20

## An external link title can trip the internal-table audit even when the link target is right

What happened: repairing T360 changed the Wikipedia link title from "Associated
Legendre functions" to the page's exact title, "Associated Legendre
polynomials". The URL was still the intended article about associated Legendre
polynomials, but `GET /api/table/T360/audit` then reported
`Links[Wiki] points outside for "Legendre polynomials", which this database
holds as T101 -- prefer HREF{Legendre_polynomials}`. The audit checks external
link titles for table titles the corpus already holds, and "Legendre
polynomials" is a substring of "Associated Legendre polynomials". Reverting
only the link title made the audit clean again.

What the skill says now: it says to link outward only to stable sources, and
to prefer a database table over an external link when the database holds the
thing itself. It does not say that the title of a correct external source can
look to the audit like a link to a different table.

What it should say: when the audit says a `Links` title points outside for a
table the database already holds, first check whether the title contains a
shorter table title as a substring. If the external link is for the larger or
more specific object, keep the URL and retitle the link so it names the source
without embedding the smaller table's title.

Evidence: T360 repair on 2026-09-20. Revision
`739711afe1e0932d0354839564dd4158ebf65ba189e23c030fa521c26b499c8d` changed
the link title to "Wikipedia: Associated Legendre polynomials" and the audit
reported the `Links[Wiki]` finding. Revision
`dfc07b838dad5269e3efbc7e24a0f355d2ae149e9764eb8e0a5c21c8ce9b7df4` retitled
it "Wikipedia: Associated Legendre functions"; `GET /api/table/T360/audit`
then returned `{"findings": [], "clean": true}`.
