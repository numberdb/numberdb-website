## A mirrored symbolic parameter row may stop being a polynomial row
What happened: T106 stores symbolic Jacobi rows with parameters `a,b`, because
$P_n^{(a,b)}(x)$ is a polynomial in $a$, $b$ and $x$ with rational
coefficients. The secondary-polynomial proposal was meant to inherit T106's
grid, but after the weight is normalised to a probability density,
$q_n^{(a,b)}(x)$ has coefficients with denominators such as $a+b+2$ and
$(a+b+2)(a+b+3)$. Those are rational functions in the parameters, not
polynomials over $\mathbb{Q}$, so a `Q[]` table cannot carry the symbolic
rows. The draft stores only the rational parameter grid from T106.

What the skill says now: inherit the grid of the table being mirrored, and
state the table type exactly.

What it should say: when a source table has symbolic parameter rows, re-check
that the new construction still lands in the table's value type. Normalising a
weight, taking a quotient, or applying a transform can turn polynomial
dependence on parameters into rational-function dependence; if the table type
is `Q[]`, those symbolic rows have to be omitted or made into a different
table type.

Evidence: `/tmp/jacobi_symbolic_check.py`, 2026-09-20, printed denominators
`a + b + 2`, `a^2 + 2*a*b + b^2 + 5*a + 5*b + 6`, and higher for
$q_2^{(a,b)}$, $q_3^{(a,b)}$ and $q_4^{(a,b)}$.

## Sage's orthogonal polynomial functions can pull in symbolic machinery
What happened: a scratch check for the Jacobi secondary polynomials imported
`jacobi_P` from `sage.functions.orthogonal_polys`. In the build environment
that import reached `sage.symbolic.function` and failed with
`AttributeError: cannot access submodule 'function' of module 'sage.symbolic'`.
The generator instead uses the binomial formula for $P_n^{(\alpha,\beta)}$,
which needs only `QQ` and a polynomial ring.

What the skill says now: with named imports, parts of Sage that reach for
uninitialised modules can be missing; it names power series operations,
determinants and symmetric-function expansion.

What it should say: add the classical-polynomial convenience functions under
`sage.functions.orthogonal_polys` to the list of imports that may drag in
symbolic machinery. For an exact table of a classical family, write the
recurrence, binomial formula or Rodrigues coefficient formula directly in
`QQ[x]`.

Evidence: `agents/sage.sh /tmp/jacobi_samples.py`, 2026-09-20, failed while
importing `jacobi_P`; the replacement scratch script and
`generators/jacobi-secondary-polynomials/generate.py` use no symbolic
function imports.
