## A multivariate shift does not guarantee a constant term
What happened: T312 stores HOMFLY-PT Laurent polynomials after multiplying by a monomial so the lowest exponent of each variable is zero. A critique suggested saying the shift gives every entry a nonzero constant term. Checking the stored polynomials in Sage showed this was false: for example the shifted $(v,z)$ entry for $7_4$ is `-v^6 + v^4*z^2 + 2*v^2*z^2 + 2*v^2 + z^2`, whose constant coefficient is zero. The table repair therefore says the entries are shifted into ordinary polynomial form instead.

What the skill says now: it says to verify a claim before writing it into a table, but it does not call out this multivariate trap.

What it should say: for a polynomial in two or more variables, shifting so that each variable has lowest exponent zero does not imply the monomial with all exponents zero is present. Check the constant coefficient before saying the shifted polynomial has a nonzero constant term; otherwise say only that the shift puts the Laurent polynomial into an ordinary polynomial ring.

Evidence: `/tmp/check_t312_constant.py` on T312, 2026-09-17, reported zero constant coefficient examples including `('7', '4', 'K', 'vz', '-v^6 + v^4*z^2 + 2*v^2*z^2 + 2*v^2 + z^2')`.
