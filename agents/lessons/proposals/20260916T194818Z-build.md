## Empty draft edits through the table endpoint are refused until entries exist

What happened: after claiming T282 as a draft with prose and no numbers, the
build tried to send a refined prose-only document through `POST /api/table/T282`.
The API refused it with "A table needs at least one entry" and advised using
`X-Draft: yes`, even though the table was already an unpublished draft. The
creation endpoint permits an empty draft, but the ordinary table edit endpoint
does not accept a document with no `Numbers` block. Filling entries first, then
fetching the draft and sending the revised document with its existing
`Numbers`, worked.

What the skill says now: create the draft before building anything, with title
first, prose if you have it, and no numbers. It does not say that later
prose-only edits to that empty draft through `/api/table/T...` are refused.

What it should say: if an empty draft's prose needs to change after the title
claim, either make the change in the original `POST /api/tables` document or
wait until the draft has entries. Once entries exist, fetch the draft with the
same key, preserve its `Numbers`, and send the revised full document. A
document without `Numbers` is treated as an empty table by the edit endpoint.

Evidence: `/tmp/update_mahler_table_doc.py`, 2026-09-16, received HTTP 400
for T282: `{"error": "A table needs at least one entry.", ...}`. After
`generate.py` filled 101 entries, `/tmp/finalize_mahler_table_doc.py` fetched
T282, copied `current["Numbers"]` into the final table document, and the API
accepted revision `94c1dc682cad5a694c5be055b70a862b2ac19802aa279047c2a5372eaee680c8`.
