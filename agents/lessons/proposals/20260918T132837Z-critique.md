# Lessons proposed by the T330 critique, 2026-09-18

Not in force. Format as in `agents/lessons/PROPOSALS.md`.

## A clean audit does not answer the one-table question once the naming parameter has more than four values

What happened: T330 holds the characteristic polynomials of twenty named
matrix families, indexed by `family` (twenty word-valued labels) and `n`, with
every order repeating under every family — the exact shape the skill describes
as "a parameter whose values are a handful of *names* … and which every other
parameter repeats under". `GET /api/table/T330/audit` answered
`{"findings": [], "clean": true}`. It was not that the check looked and was
satisfied: `_one_table_or_several` in
`numberdb_app/management/commands/audit_table.py` gives up before it looks,
because `MOST_LABELS = 4` and twenty is more than four ("a parameter with more
values than this is indexing something, not choosing between a few
quantities").

The threshold is right — T233 is indexed by 78 root systems and T241 by 22
distributions, and neither is two tables glued together — and T330's answer to
the question turns out to be a good one. But a contributor who reads "the tell
is structural, and the audit now reports it on a draft", runs the audit on a
draft with twenty named families and gets `clean` will reasonably conclude the
question was asked and answered. It was not asked. The band where the check
fires is two to four labels, and that is the band where the mistake is
cheapest to make and easiest to see by eye anyway.

What the skill says now: "**The tell is structural, and the audit now reports
it on a draft.** A parameter whose values are a handful of *names* … is one
table written twice". Nothing about when the check declines.

What it should say: that the check only asks when the naming parameter has a
handful of values, because many values are evidence of indexing rather than of
bundling — and so a clean audit on a table with twenty named labels means the
question was not put, not that it was answered. The thing to read instead is
the value column: one symbol true of every row (`$\chi_{A_n}(x)$`,
`$\gamma_K$`, `$\phi(G,x)$`) says one quantity whatever the label count, and
the word `value` says two.

Evidence: 2026-09-18, T330 critique. `GET /api/table/T330/audit` ->
`{"tid": "T330", "title": "Characteristic polynomials of the classical test
matrices", "findings": [], "clean": true}`, against `MOST_LABELS = 4` at
`numberdb_app/management/commands/audit_table.py:504` and the early return at
`:558`.

## Where prose carries the whole definition, check that the prose rebuilds the values

What happened: T330's `Definition` says only "for a named classical test matrix
$A_n$ … the characteristic polynomial $\det(xI_n-A_n)$". What each of the
twenty matrices *is* lives in three `Comments`, one sentence per family, and
those sentences are the only thing a second person has to build from. Nothing
in the corpus checks a sentence against a value: `verify` recomputes from the
generator, and the generator is not what the reader reads. So the reproducible
question — does this English rebuild this table? — was answered by
transcribing all twenty sentences into code that shares nothing with the
generator and recomputing $\det(xI_n-A_n)$ for $n = 2,3,4,5$: 80 polynomials,
no mismatch. It needed no Sage — `fractions.Fraction`, a fraction-free
determinant and Lagrange interpolation over $n+1$ integer points are enough for
an exact characteristic polynomial, and the whole check ran in under a second
on a laptop's Python.

This is the check that would have caught the failures the skill already
collects from the other direction: a table that "could not be reproduced from
its own definition" because it did not say which square root was taken, a
parameter constraint 702 of whose entries did not satisfy it. Both are
sentence-against-value disagreements.

What the skill says now: "Check new values against something independent. Not
the code that produced them". The independent thing it names is another
library, an identity, or OEIS.

What it should say: the table's own prose is an independent source, and the
cheapest one — where the definition of each object lives in a comment rather
than in code, transcribe the comments back into a program that shares nothing
with the generator and recompute a few small cases. A mismatch is a wrong
sentence, which no value check can find, and which is the only part of the
table a reader actually builds from. For exact linear algebra this needs no
Sage: `Fraction`, a fraction-free determinant and interpolation at $n+1$ points
give an exact characteristic polynomial.

Evidence: 2026-09-18, T330 critique. All twenty families of T330 rebuilt from
`comment-families`, `comment-toolbox-families` and
`comment-more-toolbox-families` in plain Python; 80 stored polynomials
compared, 0 mismatches; the same script confirmed `formula-clement`,
`formula-second-difference` and `formula-redheffer` over $n = 2..12$ and found
$\chi_{A_n}(x) = U_n((x-2)/2)$ for the second-difference family, a link to T99
the table does not make.
