## Measure the written entries, not raw interval objects, when a generator lowers `digits`

What happened: T317 stores complex intervals. `dry_run.py` computed all 466
entries correctly, but its size report used `str(value)` on the raw Sage
intervals and reported a 167.9 KB entries block even after the generator's
`digits` was lowered to 90. The first-fill path writes each value with
`numberdb._write.to_text(value, wanted, generator.format)`, and the same
entries measured through that path were 112.1 KB, with the longest stored
number 192 characters.

What the skill says now: run `agents/table-build/dry_run.py`; it measures the
entries, longest written entry and block size.

What it should say: for interval or ball values whose generator sets a
non-default `digits`, confirm the range with the same `to_text(..., wanted)`
path the fill will use before lowering precision or removing rows only to
satisfy the dry-run size warning. The dry run is still useful for exactness
and prose checks, but its block estimate can be conservative for raw interval
objects.

Evidence: T317 dry run on 2026-09-18 reported `466 entries, longest 328
characters ... block 167.9 KB`; `/tmp/measure-cusp-written.*.py` using
`to_text` and `_check_precision` reported `entries 466`, `digits 90`,
`longest 192`, `block_kb 112.0556640625`.

## Return a proven exact zero component exactly when a complex interval would otherwise carry no digits

What happened: T317's first fill was refused at the figure-eight knot:
`90 digits were asked for and this value carries 0`. SnapPy's verified cusp
shape enclosed a real part centered near zero with tiny radius, and
`to_text` wrote it as a real ball plus an imaginary decimal. The precision
checker treated the whole complex value as carrying zero digits. The mirror
formula proves that amphichiral knot cusp shapes are purely imaginary in this
convention; after the generator checked the interval contained zero, it
returned a complex interval with real component exactly `[0, 0]`, and the fill
accepted all 466 entries.

What the skill says now: decide exactness from the definition, never from the
digits; a value exactly rational is written exactly.

What it should say: the same rule applies componentwise to complex intervals.
If a theorem proves one component is exactly zero, and the interval computation
only encloses a tiny numerical neighborhood of zero, return that component as
exact zero after checking the enclosure contains it. Otherwise the written
ball can truthfully enclose the value but still fail the requested-digit
precision check.

Evidence: T317 fill first failed on `4,1,K`; after
`_pure_imaginary(z) = z.parent()(0, z.imag())` for amphichiral knots, the
write-format check passed `_check_precision` for all 466 entries and the
draft fill returned `{'entries': 466}`.
