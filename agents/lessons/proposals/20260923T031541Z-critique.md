## A chain of equalities is where the `$` delimiters come apart, and an odd count of them is always a fault

What happened: both formulas of T427 print raw LaTeX in the middle of a
sentence. The author wrote a chain of equalities and put a `$` between the
links of the chain instead of around the whole of it:

    $\lambda=\int_0^1 e^{\operatorname{li}(x)}\,dx$=\int_0^\infty e^{-x-E_1(x)}\,dx$=\int_0^\infty e^{-x+\operatorname{Ei}(-x)}\,dx$, where ...

MathJax pairs the first `$` with the second and stops, so the second integral
reaches the page as the literal characters `=\int_0^\infty e^{-x-E_1(x)}\,dx`
between two typeset ones. The second formula of the same table has **five**
dollars, an odd number, and there the failure is worse than ugly: the pairing
shifts by one, so the phrase `, where ` is set as mathematics (five italic
letters) and `\rho$ is the Dickman-de Bruijn function` is left as text with a
stray dollar in it. The prose and the mathematics change places.

Neither is visible in the stored YAML, which is the only thing a contributor
looks at while writing: every field is a plain string and each of those fields
reads perfectly well as an intention. `audit_table` does not see it either --
it reads the prose for editorial phrases, positional phrases, build narration
and unlinked corpus families, and never asks whether the mathematics in a
field is delimited. The audit on T427 is `clean: true`.

What the skill says now: "Use `$...$` for mathematics", and two accepted
lessons about `$$` arising when a comment is assembled from fragments whose
dollars end up touching. Nothing about the opposite slip, which is a *missing*
opening dollar rather than a doubled one, and nothing that would make a
contributor count them.

What it should say: mathematics that spans an equals sign spans the `$...$`
too -- write `$a=b=c$`, not `$a$=b$=c$` -- and the mechanical check that
catches every version of this is that the number of `$` characters in any one
prose field is even. An odd count is a fault with no exceptions, and it is
worth running over the document before publishing:

    for name, text in fields(document):
        assert text.count('$') % 2 == 0, name

An even count is not a clear bill of health (T427's first formula has eight
and is still wrong), so the reading of the rendered page is still the check
that matters. But the parity test is one line, it needs no browser, and it
would have caught the field where the prose and the mathematics swapped.

Evidence: T427, 2026-09-23, draft, rebuilt on sqlite by the recipe in
`docs/agent-environment.md` (1 record, status 200, 27,894 bytes).
`Formulas[formula-li]` (eight dollars, three intended math spans, one of them
delivered as text) and `Formulas[formula-dickman]` (five dollars). The site
serves stock `tex-svg` with `inlineMath: [['$','$'], ['\\(','\\)']]`
(`static/js/load-mathjax.js`), so no configuration rescues either one.
`GET /api/table/T427/audit` -> `{"findings": [], "clean": true}`.
