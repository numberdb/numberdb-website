## Screen the family's name, not the table's title: house-style titles fail on their own descriptors

What happened: five spectral-geometry proposals were screened with
`source_names_it`. Run on the **mathematical names**, all five passed:

    Dirichlet eigenvalue              en.wikipedia.org/wiki/Dirichlet_eigenvalue   OK
    Neumann eigenvalue                en.wikipedia.org/wiki/Dirichlet_eigenvalue   OK
    Steklov eigenvalue                arxiv.org/abs/1411.6567                      OK
    cross-product of Bessel functions dlmf.nist.gov/10.21                          OK

Run on the **proposed titles**, against the very same pages, four of five
failed:

    Dirichlet eigenvalues of the classical planar domains
      -> the source does not mention classical, domains
    Steklov eigenvalues of the classical planar domains
      -> the source does not mention classical, planar, domains
    Small eigenvalues of the Laplacian on the classical closed hyperbolic surfaces
      -> the source does not mention laplacian, classical, closed

None of those complaints is about the mathematics. `classical`, `planar` and
`closed` say *which rows the table holds*, and the corpus's own titles are
written that way -- T328 *Lebesgue constants of the classical interpolation
node families*, T329 *Eigenvalues of the classical symmetric test matrices*,
T219 *Volumes of the closed hyperbolic 3-manifolds of the Hodgson-Weeks
census*. No encyclopedia article will ever contain the row-selection clause of
a table title, so screening the title manufactures a complaint on every table
named in the house style, and a run that takes the complaint seriously either
renames its tables badly or drops good proposals.

The converse failure is in the same run and is worse, because it is silent:

    source_names_it('L-shaped domain',
                    'https://en.wikipedia.org/wiki/Dirichlet_eigenvalue')  -> None

That article does not contain the string "L-shaped" anywhere; I checked with a
regex over the stripped text and got zero hits. It passed because the check
tests the *distinguishing words separately*, and "shaped" and "domain" both
occur somewhere on a page about eigenvalues of domains. So a pass means every
word appears, not that the phrase does, and a two-word name made of common
words passes almost any page in its subject.

What the skill says now: "Cite a source for every proposal and run
`source_names_it` on it. Not as a formality: it is the only check that a family
is real and is called what you say."

What it should say: run it on the **name of the family**, the words a source
would use for the object -- "Steklov eigenvalue", "cross-product of Bessel
functions" -- and not on the proposed table title, which carries descriptors of
the row list that no source contains. And read a pass as "every one of these
words occurs on that page", which is weaker than it looks: for a short name
built from common words, confirm the phrase is there before believing it.

Evidence: 2026-09-21, ideation run `20260921T184313Z`, `/tmp/nb/screen1.py`,
`/tmp/nb/screen2.py` and `/tmp/nb/screen3.py` for the screen results;
`/tmp/nb/fetch.py`, which fetches the same URL, strips the tags and searches
for `.{150}L-shaped.{150}`, reporting zero hits.
