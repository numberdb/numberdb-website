## A complex ball containing a branch point is nan even where the exact point is not, so $\Lambda(\theta)$ via $\mathrm{Li}_2(e^{2i\theta})$ fails at an angle that came out as zero

What happened: T224's `Programs` defines the Lobachevsky function as
`(CB(0,2)*CB(theta)).exp().polylog(2).imag()/2`. Put into Kellerhals's
orthoscheme formula for $[3,3,6]$, it returned nan. The term
$\Lambda(\gamma-\theta)$ has $\gamma=\pi/6$ and $\theta=\arctan(1/\sqrt3)$,
two balls whose difference is `[+/- 5.46e-104]`. So $e^{2i(\gamma-\theta)}$ is
a ball around $1$, and arb answers nan for $\mathrm{Li}_2$ of it.
`Lambda(pi)` is nan for the same reason. `Lambda(RB(0))` is `0`, and
`CBF(1).polylog(2)` is $\zeta(2)$. Only an *inexact* ball over the branch
point fails. `CB(RB(1).add_error(1e-90)).polylog(2)` is nan.

What the skill says now: nothing about this. "An enclosure that contains
everything agrees with everything" warns that a nan ball passes a
comparison. The proposal on `RealBall.polylog` at $x=1$ covers the exact
real point, not a complex ball that merely contains it.

What it should say: a function evaluated at a ball that straddles a branch
point or a pole returns nan, even when its value at the exact point is
finite, and formulas that subtract equal angles produce such balls. Where
the function is known there (Clausen and Lobachevsky vanish at multiples
of $\pi$), test for it first:
`if (theta / pi).contains_integer(): return RB(0)`.

Evidence: 2026-09-13, `/tmp/t224_nan.py` via Sage:
`pi/6 - theta: [+/- 5.46e-104] -> nan`, `pi exact-ish: nan`, `exact 0: 0`,
`CB(1+/-1e-90): nan`. With the guard, `/tmp/t224_fix.py` gives `0 0` and
$\mathrm{Vol}([3,3,6])$ to 100 digits.

## A label copied from a source's table is a claim; check it against the diagram or definition printed beside it

What happened: T224 keys its rows by the Coxeter symbols of Kozma and
Szirmai's Table 1 (arXiv:2205.03945). For $\overline{DV}_3$ that table
prints $[4,3^{[1,1]}]$, but the diagram in the same row has a $6$-edge and
a fork. That is $[6,3^{1,1}]$, which Wikipedia uses and which the stored
volume $\frac58\Lambda(\pi/3)$ fits. $[4,3^{1,1}]$ is the Euclidean
$\tilde B_3$. The volume was checked against the source and agreed, so
nothing caught the label. The generator also turned every `^{...}` into
`^[...]`, which in this notation turns a branch ($3,4^{1,1}$) into a ring
($4^{[4]}$ style). Two more addresses therefore name other diagrams.

What the skill says now: "Check new values against something independent"
and "Verify a claim before writing it into a table", both about values and
properties. Nothing is said about labels and addresses, which freeze when
the table is published.

What it should say: an entry address transcribed from a source is checked
like a value. Compare it with the diagram, the definition or a second
source, because a misprinted label beside a correct value passes every
numerical check. When notation is transliterated for an address, the
transliteration must keep every distinction the notation makes. Braces
and brackets in a superscript mean different things.

Evidence: 2026-09-13, T224 critique. In `3dim_koszul-revision.tex`, lines
1197–1209 show the diagram with node label `$6$` and a fork, labelled
`$[4,3^{[1,1]}]$`. Wikipedia's "Paracompact uniform honeycombs" raw text,
line 3971, reads `{\bar{DV}}_3 ... [6,3<sup>1,1</sup>]`.
