## A prose-only draft should carry an explicit empty `Numbers` section

What happened: T227 was claimed as a draft with title, prose, parameters and
data properties, but no `Numbers` section. The first `generator.publish()` did
not reach any computed value. It failed in the client's preflight
`check_writable`, which sends an empty upsert so a long run can learn in its
first second whether it may write. The server answered HTTP 400:
`A value in these entries cannot be read as a number. 'str' object has no
attribute 'items'`. The real nonempty entry write was fine: after the dry run
and identity checks, a temporary wrapper skipped only that empty preflight and
`publish()` added all 42 entries.

What the skill says now: claim the table by creating a draft first, with
"Title first, prose if you have it, no numbers", then fill it with a
generator.

What it should say: a prose-only draft should still include `Numbers: []`.
That is still "no numbers", but it gives the entries endpoint the shape that
the client's empty-upsert preflight expects. If a first fill of a draft with
no `Numbers` section fails before computing anything with the error above,
the values are not implicated; add the empty section or skip only the
preflight and then send a nonempty entry batch.

Evidence: T227, 2026-09-13. `generator.publish()` failed before computation
with the HTTP 400 above; `/tmp/publish_glaisher_skip_empty_probe.py` patched
`numberdb._write.check_writable` to a no-op for the run, and the same
generator reported `<PublishOutcome T227: 42 added, 0 updated, 0 unchanged,
0 agreed, 0 left alone, 0 removed>`.
