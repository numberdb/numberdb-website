## Keep table cross-references out of the Definition

What happened: while repairing T287, the proposed Definition linked
HREF{Satisfiability_thresholds_of_random_k-XORSAT}[the satisfiability
threshold table] at the first mention of that related family. The edit was
mathematically right, but `/api/table/T287/audit` refused it with "Definition
links to another table; a cross-reference belongs in Similar tables or a
comment", and also reported the Definition as too long. Moving the HREF into
the Comment and keeping the Definition to the root equation made the audit
clean.

What the skill says now: the section table says Definition holds what the
object is, not relations, and Similar tables holds database relations. Later
it says to link the first mention of a thing to the table the corpus holds,
which can read as permission to put an HREF in the Definition when the first
mention happens there.

What it should say: do not put HREF links to other NumberDB tables in the
Definition. Keep the Definition self-contained; put cross-table relations in
Similar tables or Comments, where the first mention can be linked without
failing the audit.

Evidence: T287 repair, 2026-09-17. Revision
`2714ff6175f7c5e2868ed043ad1e954175d2cba6b8332945c46a2968a9a5e5d1`
introduced the Definition link and `/api/table/T287/audit` returned the two
findings above; revision
`a988999fdb70f6d83129099c35d1e62cee2ee6997250a8165a35901988b534a3`
moved the link out of the Definition and the same audit returned
`findings: []`.
