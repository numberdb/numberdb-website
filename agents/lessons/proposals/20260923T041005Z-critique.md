## An uncited Link renders as an orphan footnote number, just as an uncited Reference does

What happened: T432 declares four Links and cites three of them. Nothing in
the prose carries `CITE{OEISDigits}` or `CITE{WikiMarkovSpectrum}`. The
rendered page numbers Links and References in one sequence, so the reader gets

    Links  [2] OEIS A261613  [3] OEIS A261613 b-file
           [4] Wikipedia: Markov number  [5] Wikipedia: Markov spectrum

on a page that contains no `[3]` and no `[5]`. A reader who has learned that
these are footnote markers looks for the sentences that produced them and
there are none. `audit_table` does not see it: `unresolved_citations` checks
that every `CITE{}` names a Link or a Reference, and has no check in the other
direction, so the table audits clean.

The b-file case is the one that shows the cost is not only tidiness. T432's
`rigour details` says "the 72-digit decimal recorded in CITE{OEISConstant}",
and the 72 digits are in the b-file, not in the sequence entry -- the uncited
link was the correct source for the sentence that cited the other one. Citing
it both removes the orphan and makes the provenance true.

What the skill says now: the field table gives References the anti-pattern
"uncited decoration", and states the rule alone -- "**A reference is for
citing, not for listing.** `CITE{Koshy}` in a comment earns its place; a
bibliography nobody points at is furniture." Links get a different
anti-pattern, "anything the database holds itself", which is about linking
outward to something the corpus already has. So as written the skill forbids
an uncited Reference and says nothing about an uncited Link, while the page
renders the two in one numbered list and makes them the same fault.

What it should say: extend the rule to both fields, since the rendering does.
Beside "A reference is for citing, not for listing", add that the same is true
of a Link: `Links` and `References` share one numbering on the page, so a Link
nothing cites renders as a number the page never uses. Either cite it where it
belongs or drop it. A link declared and not cited is usually a sign that the
sentence it was meant for was never written -- which is what happened here,
and citing it fixed a provenance claim rather than only a footnote.

A test would assert the sentence about Links sharing the numbering, and
`audit_table` could carry the check: the set of Link and Reference keys minus
the set of keys any `CITE{}` names should be empty.

Evidence: 2026-09-23, T432 critique. Document via `GET /api/table?id=T432`;
rendering via `GET /preview?table=...` in four pieces, all 200, showing the
`[2]`--`[5]` list above with `[3]` and `[5]` unreferenced.
`GET /api/table/T432/audit` returns `{"findings": [], "clean": true}`.
`https://oeis.org/A261613/b261613.txt` holds 72 digits at indices 0--71 whose
concatenation is exactly the stored fractional part
`180717104711806478057792649049167621476305627670882734805388896650560768`.
