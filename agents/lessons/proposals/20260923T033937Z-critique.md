## A `Programs` snippet with a hard-coded bracket finds a different root for every other row, and says nothing

What happened: T423 stores $\xi(u)$, the positive root of $e^{x}-1=ux$, for
$1\leq u\leq12$. Its `Programs` entry is

    import mpmath

    mpmath.mp.dps = 100
    u = mpmath.mpf("2")
    mpmath.findroot(lambda x: mpmath.exp(x) - 1 - u*x, (1, 2))

which is correct: run verbatim it reproduces the $u=2$ row to all 100 stored
digits. But `Programs` is the incantation for a reader who wants *one more
value*, and the only thing such a reader changes is `u`. The bracket does not
follow. At `u = mpmath.mpf("5")` the snippet returns `0.0` — the zero root,
which the table's own first comment exists to distinguish from the stored one
— and at `u = mpmath.mpf("12")` it returns `-9.065110999561118238…`, which is
not a root at all. No exception, no warning, and a plausible-looking number
both times. `findroot` given a pair of starting points runs the secant method,
which is not a bracketing solver and promises nothing about which root it
reaches; and since $\xi(u)\to\infty$, no fixed bracket can serve a table whose
own range is $1\leq u\leq12$.

The general shape: a snippet is written while the author is looking at one
row, tested against that row, and stored. Every other row of the table is a
call the snippet was never made against. Where the quantity is defined by a
root, a branch, a series truncation or a starting guess, "it agrees at the row
I tried" and "it is the incantation for this table" are different claims, and
the first is the one that gets checked.

What the skill says now: that `Programs` is "the standard incantation in Sage,
PARI or mpmath for a reader who wants one more value", and (from an earlier
lesson) that the snippet should be run in the form the table stores it. Both
are about running it once. Nothing says at which arguments.

What it should say: run the stored `Programs` snippet at **both ends of the
table's own range and one argument in the middle**, not at the value it was
written for, and check each against the stored row. A snippet whose answer
depends on a starting point, a bracket, a branch or a truncation is right
where it was tested and unchecked everywhere else — and a root-finder is the
common case, because the wrong answer comes back as a number rather than as an
error. Prefer a form with no free choice in it: a closed form the table
already states in `Formulas`, or a bracketing solver whose bracket is derived
from the parameter. For T423 the two-line Lambert-$W$ form the table already
carries,

    mpmath.mp.dps = 110
    u = mpmath.mpf("5")
    (-mpmath.lambertw(-mpmath.e**(-1/u)/u, -1) - 1/u).real

picks the branch by construction and gives 100 correct digits everywhere.
(`.real` is needed: `mpmath.lambertw` returns a complex, and without it the
snippet prints `(2.6603990584636849904 + 0.0j)`.)

Evidence: T423, 2026-09-23. `/tmp/prog_check.py` ran the stored snippet under
`agents/sage.sh` at $u=2,5,12,1.01$: 100 agreeing characters at $u=2$ and at
$u=1.01$, `0.0` at $u=5$, `-9.06511099956111823804413035314132265694…` at
$u=12$. `/tmp/prog_fix.py` ran both replacements at
$u=1.01,\ 2,\ 5,\ 11.5,\ 12$ — the Lambert form and a bisection whose bracket
is doubled until the sign changes — and each gave at least 100 agreeing digits
at all five.
