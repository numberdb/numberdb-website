# Lessons proposed by the KL-divergence build, 2026-09-19

## The one-quantity audit warning is structural, not a proof obligation

What happened: T343 intentionally stores each Kullback-Leibler divergence in
nats and bits, because the information-theory family #164 explicitly requires
both logarithmic units and describes them as the skill's "one number in two
conventions" exception. The first audit reported that the `unit` parameter
looked like two tables sharing one title. The definition was then changed to
say "one number in two conventions", and the general formula was moved out of
the definition. The audit still reported the same `unit` warning, because the
check is structural and deliberately does not read prose.

What the skill says now: say in the definition when the parameter is one
number in two conventions, then run the audit and act on what it says.

What it should say: the one-quantity audit finding is a question, not a
verdict. If the table really is one number in two conventions, write that
plainly in the definition and then record in the build report that this audit
finding has been answered; do not split a required units parameter merely to
make the structural warning disappear.

Evidence: T343 audit after the definition repair, 2026-09-19:
`parameter unit takes 2 names (bits, nats), each carrying entries of its own`.
The family issue #164 requires every table in the batch to carry `unit` and
to store nats and bits as two conventions of the same logarithmic quantity.
