## Choose a factor by comparing residuals, not by testing one against a tolerance

What happened: while testing a replacement PARI program for T308 (Weber class
polynomials), the program picked $W_D$ from two candidates, $x^h P(1/x)$ and
$x^h P(-1/x)$ with $P=$ `polclass(D,1)`. It evaluated one candidate at
$\omega_D=$ `weber(I*sqrt(-D))/sqrt(2)` and took it when the result was
below `1e-10`. At 200 digits that was correct for all 100 entries. At gp's
default 38 digits it chose the wrong polynomial for seven discriminants
($D=-671,\dots,-1159$). $|\omega_D|$ is about 55 there and the degree is
22 to 34, so $|\omega_D|^h$ exceeds $10^{38}$ and the true zero evaluates to
something far above the tolerance. Taking whichever candidate has the smaller
absolute value was correct for all 100 at 38 digits.

What the skill says now: nothing about identifying an exact object by a
numerical evaluation.

What it should say: when a numerical value selects one of several exact
candidates (a factor of a resultant, one of two normalisations), compare the
candidates' residuals with each other, and set the precision from the size of
$|\alpha|^{\deg}$, not from the default. A fixed tolerance silently goes wrong
as the degree grows. It is also the program a reader copies from `Programs`.

Evidence: `/tmp/crit308_fix.py` (200 digits, threshold: 0 mismatches) and
`/tmp/crit308_fix2.py` (38 digits, threshold: 7 mismatches; comparison: 0),
2026-09-17, against the 100 entries of draft T308.
