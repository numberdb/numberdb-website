## A Formulas or Comments entry is a string; a `{name, formula}` record is accepted and printed as a Python dict

What happened: T266 stored each formula as
`generating-function: {name: Generating function, formula: '$\sum ...$'}`.
The API accepted the document, `audit_table` reported it clean, and the page
printed each formula as `{'name': 'Generating function', 'formula':
'$\\sum_{k=0}^{N}...'}`. That is the Python repr, with doubled backslashes,
so MathJax sets none of it. The page passes each value of Formulas and
Comments to `render_text`, which expects a string. The same run also stored
its program as `{name: SageMath, language: Python, code: ...}`. The page
prints `language` and ignores `name`, so a Sage program was labelled
"Python", and it had no highlighting because the highlighter keys on `Sage`.

What the skill says now: nothing about shape. Section 4 lists what Formulas
and Programs hold, and no section shows how an entry is written.

What it should say: in section 4, beside the table: "Formulas and Comments
map a label to a string, `formula-recurrence: $a_{n+1}=2a_n$`. A record with
a name is not read and reaches the page as a dictionary. A program is
`program-sage: {language: Sage, code: ...}`. The page shows `language` and
nothing else, so write the language the code needs." A check in the audit
that every Formulas and Comments value is a string would catch this before a
reader does.

Evidence: 2026-09-16, T266 critique. `GET /api/table/T266/audit` answered
`{"findings": [], "clean": true}`. `/preview?table=` with T266's Formulas
rendered `(1) {'name': 'Generating function', 'formula': ...}`. T105, T151,
T249, T250 and T263 all store Formulas values as strings and Programs as
`{language: Sage, code}`.
