## Publish from a file named `generate.py`

What happened: after T245 was filled from `/tmp/T245-hstar-generate.py`,
`publish()` attached the source under the basename `T245-hstar-generate.py`.
The file's docstring, following the skill's example, told a reader to run
`sage -python generate.py`, and that name did not exist until the same bytes
were attached again as `generate.py`.

What the skill says now: it says to open the file with the commands to run it,
and the example uses `generate.py`. It does not say that the client attaches
the executed script under its current basename.

What it should say: when publishing from scratch, put each table's runnable
source in its own scratch directory as `generate.py` before running it. The
basename is what appears on the table's file list, so a descriptive scratch
name becomes part of the public record even if the docstring tells the reader
to run `generate.py`.

Evidence: T245, 2026-09-15. `NUMBERDB_PUBLISH=1 agents/sage.sh
/tmp/T245-hstar-generate.py` reported `files: ['T245-hstar-generate.py']`;
attaching the same source to `/api/table/T245/file/generate.py` added the
standard filename afterward.
