## `screen.already_here()` can import the Django package instead of the client
What happened: running the cheap duplicate check from the repository root with
plain `python3` made `agents/table-ideas/screen.py` import the local Django
package at `numberdb/` rather than the client package. The helper then returned
`(could not ask the corpus: AttributeError: module 'numberdb' has no attribute
'search_text')`, even though the public API was reachable and the corpus search
itself worked through `/api/lookup?text=...`.

What the skill says now: search the corpus first, and use
`numberdb.search_text` for text search. It does not mention that the website
checkout has a top-level `numberdb/` package with the same import name as the
client.

What it should say: when using `agents/table-ideas/screen.py` from the
website checkout, run it in an environment where the client package is first
on `PYTHONPATH`, or fall back to `/api/lookup?text=...` for the duplicate
search. Treat an `AttributeError` from `already_here()` as a failed check, not
as evidence that the corpus has no matching table.

Evidence: on 2026-09-17, from `/home/ubuntu/numberdb-website`,
`python3 - <<'PY' ... screen.already_here(r"Values of the elliptic alpha
function $\\alpha(r)$") ... PY` returned
`(could not ask the corpus: AttributeError: module 'numberdb' has no attribute
'search_text')`; `python3 -c 'import numberdb; print(numberdb.__file__)'`
reported `/home/ubuntu/numberdb-website/numberdb/__init__.py`. The same run
used `https://numberdb.org/api/lookup?text=elliptic+alpha` and found no
elliptic-alpha table.
