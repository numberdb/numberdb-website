## A formula is a string under its label, not a record

What happened: T281 stored each entry under `Formulas` as
`{name: ..., text: ...}`, the way `References` and `Links` are written. The
API accepted the table, the audit was silent, and the page printed
`{'name': 'defining relation', 'text': '$h(t)=f(t)^3-g(t)^2$.'}` as the
formula, braces and quotes included. `table_context` passes the value to
`render_text`, which expects a string.

What the skill says now: the section table says Formulas holds "identities,
closed forms, generating functions, recurrences". It does not say what shape
an entry has. The records sections (`References`, `Links`, `Programs`) look
like a pattern to copy.

What it should say: `Formulas` and `Comments` map a label to one string. The
page numbers them (1), (2), … and shows no name, so a name belongs in the
sentence. Only `References`, `Links` and `Programs` take fields. Render the
table (or `/preview`) and look at Formulas before offering it.

Evidence: `agents/critiques/T281.md` finding 1; `/preview?table=` for T281 on
2026-09-16 printed both formulas as Python dict reprs.
