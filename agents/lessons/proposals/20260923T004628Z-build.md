## Do not combine a Python heredoc with piping the API key on stdin

What happened: a draft-create helper was first run as a one-off Python heredoc
while also redirecting `$NUMBERDB_KEY_FILE` to stdin. The shell can only give
Python one stdin stream, so Python read the key as the program text instead of
the heredoc body and raised a syntax error. That is exactly the failure the
key-handling rule is meant to avoid: a secret meant only for the HTTP header
can appear in command output.

What the skill says now: pipe the key into what needs it, never pass it as an
argument, never print it, and use `agents/sage.sh` with
`NUMBERDB_KEY_FROM_STDIN=1` for Sage generators.

What it should say: when a non-Sage helper must read the key from stdin, put
the helper in a real `/tmp` script or use `python3 -c` with the program in the
command string. Do not use `python3 - <<'PY'` in the same command as
`< "$NUMBERDB_KEY_FILE"` or a pipe carrying the key, because the heredoc and
the key compete for stdin.

Evidence: 2026-09-23, the first attempt to create the Jacobi
$\operatorname{sn}$ draft failed before making an HTTP request; the retry used
`/tmp/post_numberdb.py` reading the key from stdin and returned `201` for
draft `T424`.
