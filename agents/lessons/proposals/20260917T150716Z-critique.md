## A formula that names a symbol defined in a linked table must use that table's indexing

What happened: T305 (Adams–Bashforth coefficients) writes
$\beta_{s,j}=\int_{s-1}^{s}\ell_{s,j}(x)\,\mathrm{d}x$ with $\ell_{s,j}$ the
Lagrange basis polynomial for the $s$ nodes $0,\ldots,s-1$, and lists
"Lagrange basis polynomials for equally spaced nodes" in Similar tables. That
table defines $\ell_{d,i}$ for the nodes $0,\ldots,d$, indexed by degree, so
T305's $\ell_{s,j}$ is its $\ell_{s-1,j}$. A reader who follows the link to
check $\beta_{3,0}=5/12$ integrates that table's $\ell_{3,0}$ over $[2,3]$
and gets $-3/8=\beta_{4,0}$. Each table is right by its own definition, and
the audit passes both.

What the skill says now: "Define notation where you use it", and link the
first mention of a family the corpus holds. Nothing about agreeing with the
notation of the table linked.

What it should say: when a formula uses an object the corpus holds and links
it, write the object in that table's notation, index for index, or say how
they differ in the same sentence. A link invites the reader to look the
object up there, and a shifted index sends them to the neighbouring row.

Evidence: T305 draft `Formulas: formula-integral` and
<https://numberdb.org/Lagrange_basis_polynomials_for_equally_spaced_nodes>
(Definition: "for the nodes $0, 1, \dots, d$ is $\ell_{d,i}(x)$"); critique
`agents/critiques/T305.md`, finding 1.
