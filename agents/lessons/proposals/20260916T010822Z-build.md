## A prose-first draft without `Numbers: []` cannot be rewritten before it is filled
What happened: T254 was claimed through `POST /api/tables` with `X-Draft: yes`,
carrying prose and parameters but no `Numbers` section. A later whole-document
draft edit with the final prose was refused with "A table needs at least one
entry", even when the request sent `X-Draft: yes`. Sending one nonempty
replacement to `/api/table/T254/entries` filled the draft; after that, the
full-document prose edit with flattened `Numbers` and the generator publish
path both succeeded.

What the skill says now: create the draft before building, with title first
and prose if available, no numbers; then fill it once with a generator.

What it should say: when a draft is claimed through the API before values are
ready, include `Numbers: []` even though it is still empty. If a draft already
exists without that section, do not try to rewrite it while it is empty. Send
the first nonempty entries block through the entries endpoint, then do any
whole-document prose edit with the numbers flattened as records.

Evidence: T254 on 2026-09-16. `POST /api/table/T254` with the final prose
answered HTTP 400, "A table needs at least one entry";
`/tmp/fill_heat_entries.py` sent 51 entries and returned revision
`90bd4cf29e4f96406d04d3bc5db24a33d3bd15180e85ec299aabeaa30a0f0e46`; the
subsequent generator run reported `51 unchanged`.
