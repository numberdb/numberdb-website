## Singular `spectrum()` needs a local ordering

What happened: the monodromy table for T291 used Singular's `gmssing.lib`
`spectrum(F)` as an independent check. With
`ring r = 0,(x,y),dp; poly F = x^3+y^4; spectrum(F);`, Singular answered
`? local ordering expected` and returned an empty list when the result was
assigned. Repeating the same computation with `ring r = 0,(x,y),ds;` returned
the six spectral numbers of $E_6$.

What the skill says now: it says to run a control before trusting a
measurement, and it has a lesson about not naming a Singular polynomial like
a ring variable. It says nothing about the monomial ordering required by
`gmssing.lib`'s spectrum routine.

What it should say: when using Singular's `gmssing.lib` `spectrum()` as an
independent check, create the ring with a local ordering such as `ds`. Run a
known control first, because with a global ordering the routine can fail in a
way that looks like an empty spectrum if the caller only inspects the assigned
list.

Evidence: `/tmp/monodromy_probe.py` with `dp` gave `? local ordering expected`;
`/tmp/monodromy_probe_ds.py` with `ds` returned
`(-5/12,1),(-1/6,1),(-1/12,1),(1/12,1),(1/6,1),(5/12,1)` for $x^3+y^4$,
2026-09-17. T291's generator then checked all 87 rows against
`spectrum(F)` in `ds` rings.
