## `Generator.verify()` checks numbers, not generated entry comments

What happened: T284's generator returned comments with each value. After a
repair edited nine live comments from fragments into sentences,
`generator.verify(sample=None)` still reported `47/47 matched, 0 differing`,
because it compares only the stored number with the recomputed number. A later
`publish()` from the unchanged generator would have rewritten the nine repaired
comments while looking numerically clean.

What the skill says now: "`verify()` recomputes and compares against the
stored table"; nothing says generated comments are outside that comparison.

What it should say: when a generator returns per-entry comments, check those
separately against the live table before republishing after a prose repair.
`verify()` is a number check, not a full row check.

Evidence: `cat "$NUMBERDB_KEY_FILE" | NUMBERDB_KEY_FROM_STDIN=1 agents/sage.sh
generators/salem-numbers-less-than-1.3/generate.py` reported 47/47 matched on
2026-09-20 while the generator still produced the old fragment comments.
After updating `entry_comment()`, `/tmp/check_t284_comments.py` run through
`agents/sage.sh` reported `all 47 comments match`.
