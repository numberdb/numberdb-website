# Lessons proposed by the 2026-09-23 build run

## An API-created draft with no `Numbers` section can refuse `Generator.publish()`

What happened: T453 was created through `POST /api/tables` with `X-Draft: yes`
and no `Numbers` section, as the build prompt asks for a prose-only claim.
The generator dry-run and identity checks passed, but the first fill with
`generator.publish(message="chi-squared quantiles")` failed before computing
entries. The client preflight sends an empty upsert to `/api/table/T453/entries`
to check writeability; the server tried to merge that into a draft whose
current document had no entries section and refused with
`A value in these entries cannot be read as a number. 'str' object has no
attribute 'items'`. Sending the computed records directly to the entries
endpoint as a replacement filled the table, and subsequent `verify()` runs
worked.

What the skill says now: create a draft with title first, prose if you have it,
and no numbers; then fill it with the generator.

What it should say: until the client or server treats a missing entries section
as an empty one during the preflight upsert, a prose-only API draft may need an
explicit empty `Numbers` section created by the site, or the first fill must
send the full entries block as a replacement rather than through
`Generator.publish()`. If `Generator.publish()` refuses an empty draft before
computing entries with a message about a value that cannot be read, inspect
whether the draft has a `Numbers` section before debugging the generator's
values.

Evidence: `cat "$NUMBERDB_KEY_FILE" | NUMBERDB_KEY_FROM_STDIN=1
NUMBERDB_PUBLISH=1 agents/sage.sh
generators/quantiles-chi-squared-distribution/generate.py`, 2026-09-23,
failed at `numberdb._write.check_writable` with the refusal above; direct
replacement via `/api/table/T453/entries` stored 476 entries, and
`verify(sample=None)` then reported `476/476 matched, 0 differing, 0 missing,
0 extra`.
