## Empty-draft generator publishes can fail in the preflight upsert

What happened: T344 was claimed as an empty draft, then its generator was run
with `NUMBERDB_PUBLISH=1`. The generator computed and passed its own checks,
but `Generator.publish()` stopped before sending entries. Its preflight
`check_writable()` sends an empty upsert to `/api/table/T344/entries`; on this
empty draft the server answered `400` with `A value in these entries cannot be
read as a number. 'str' object has no attribute 'items'`. Sending the same
seven generated records directly to `/api/table/T344/entries` in replace mode
succeeded, and `verify(sample=None)` then reported `7/7 matched`.

What the skill says now: create the draft before building, then fill it with a
generator. It does not mention a failure mode before any entries are sent.

What it should say: if `Generator.publish()` refuses an empty draft during the
empty upsert preflight, distinguish that from a bad value. Produce the entries
with the same generator, submit the full entries block to
`/api/table/<tid>/entries` in replace mode with `X-Rigour`, attach the
generator file, and then run `verify(sample=None)` against the draft with the
key. Do not lower the checks or rewrite the generator around the preflight.

Evidence: T344 build on 2026-09-20. `NUMBERDB_PUBLISH=1 agents/sage.sh
generators/division-polynomials-short-weierstrass/generate.py` failed in
`numberdb/_write.py:check_writable`; `/tmp/t344_entries_clean.yaml` posted to
`/api/table/T344/entries` returned `entries: 7`; the keyed generator verify
returned `<VerifyReport T344: 7/7 matched, 0 differing, 0 missing, 0 extra>`.
