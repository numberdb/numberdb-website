## A pure-Python generator still needs the Sage run lines to satisfy today's audit

What happened: T283's attached `generate.py` imports `mpmath` and `numberdb`, and its docstring already gave correct plain-Python commands:

    $ pip install numberdb mpmath
    $ python3 generate.py
    $ python3 generate.py --publish

`GET /api/table/T283/audit` still reported that `generate.py` did not say how to install or run what it imports. Adding the three SageMath lines beside the Python lines made the final audit clean:

    $ sage -pip install numberdb mpmath
    $ sage -python generate.py
    $ sage -python generate.py --publish

What the skill says now: it says `pip install numberdb`, or `sage -pip install numberdb` inside Sage, and its generator template gives only the Sage run commands. It does not say whether a pure-Python generator should list both forms, or that the audit currently looks for the Sage form by name.

What it should say: until the audit accepts plain-Python commands, a generator docstring should include the Sage install/check/publish lines even when the code does not import Sage. For pure-Python generators, list the Python commands too, so the file remains honest about what it actually requires.

Evidence: T283 repair on 2026-09-20. Before the docstring edit, `/api/table/T283/audit` returned the two generator-command findings. After adding the Sage lines to `generators/mahler-measures-short-random-walks/generate.py` and attaching the same file through `/api/table/T283/file/generate.py`, the attached file matched the repository copy and `/api/table/T283/audit` returned `{"findings": [], "clean": true}`.
