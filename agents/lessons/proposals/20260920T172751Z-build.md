## `ComplexBall.legendre_Q(type=3)` can return `nan` on valid rational rows

What happened: while building T375, Sage's arb method
`CBF(5/4).legendre_Q(CBF(1/3), type=3)` returned `nan + nan*I`, and the same
happened for degree `2/3` at `x=5/4`. Increasing the guard from 64 through 256
bits did not change it. The same rows are finite: mpmath's
`legenq(1/3, 0, 5/4, type=3)` returned
`0.7399436413158613667970740313...`, and arb evaluated the DLMF
hypergeometric formula with a radius below `1e-125`.

What the skill says now: a previous lesson says that Legendre's function of
the second kind lives on `ComplexBallField` and to use
`ComplexBall.legendre_Q(n, m, type)`, checking the imaginary part before taking
the real part.

What it should say: for Legendre $Q_\nu(x)$ values on $x>1$, treat a `nan`
from `ComplexBall.legendre_Q(..., type=3)` as a failed computation, not as a
singularity or a reason to drop the row. Check the row against an independent
method, and use the DLMF hypergeometric representation in arb when it gives a
finite enclosure.

Evidence: `/tmp/numberdb_w3_probe_nonfinite.py` tested
`nu=1/3,2/3`, `x=5/4` at guard bits `64,96,160,256`; all direct arb calls
returned `nan + nan*I`, while mpmath returned finite real values. The final
generator `generators/legendre-q-values/generate.py` computes the table from
the hypergeometric formula and checks all 792 rows against mpmath, the degree
recurrence, the $Q_0,Q_1$ formulas, and the integer-degree relation to T133.
