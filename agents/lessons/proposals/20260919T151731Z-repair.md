## Use `verify()` to compare existing rows after an additive publish
What happened: while checking T293 after an earlier additive repair, running its generator with `preview(overwrite=False)` returned `<PublishOutcome T293: 0 added, 0 updated, 0 unchanged, 0 agreed, 1171 left alone, 0 removed, not sent>`. That proved there were no missing rows for the generator to add, but it did not compare the 1171 stored values. A separate `generator.verify(sample=None)` run reported `<VerifyReport T293: 1171/1171 matched, 0 differing, 0 missing, 0 extra>`.

What the skill says now: it says "`preview()` computes and compares and sends nothing" and separately says `verify(sample=None)` checks every entry.

What it should say: after an additive publish or repair that used `overwrite=False`, use `verify(sample=None)` for the stored-value comparison. `preview(overwrite=False)` is still useful for seeing what would be added, but existing rows can be reported as "left alone" rather than compared.

Evidence: T293 repair on 2026-09-19. `agents/sage.sh generators/regulators-elliptic-curves-real-quadratic-fields/generate.py` printed `1171 left alone`; `agents/sage.sh /tmp/t293_verify_driver.py generators/regulators-elliptic-curves-real-quadratic-fields/generate.py` printed `1171/1171 matched`.
