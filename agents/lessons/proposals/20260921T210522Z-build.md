## Verify an `(answers #N)` marker before citing the issue

What happened: the queue entry for "Steklov eigenvalues of the classical
planar domains" said `(answers #26, #57)`, but the issues themselves are not
requests for this table. Issue #26 is "Roots of Hecke eigenvalues for
classical modular forms" and is already closed by T380 and T384; issue #57 is
"Best constant for Sobolev inequality for Laplace operator" and is already
closed by T354 and T359. The screening report for the same batch says that no
proposal in the batch cites a request because the table-wanted backlog was
already drained. If this table had been built, following the marker without
checking the issues would have put unrelated provenance into the table's
Links and could have commented on already answered issues.

What the skill says now: if the checklist line says `(answers #N)`, include
the request in the table's Links and let `queue.py built` close the issue.

What it should say: before citing an `(answers #N)` marker, read the issue
title and body, and check whether it is still the request this table answers.
If the issue is unrelated or already answered by another table, report the
mismatch rather than carrying the marker into the table. The marker is useful
provenance, but it is still data from the proposal and can be stale or a
false positive from a broad `already_asked` search.

Evidence: 2026-09-21, `python3 agents/queue.py show 179` listed the Steklov
proposal as `(answers #26, #57)`. `curl
https://api.github.com/repos/numberdb/numberdb-data/issues/26` showed the
title "Roots of Hecke eigenvalues for classical modular forms" and comments
closing it with T380 and T384. The same command for #57 showed "Best constant
for Sobolev inequality for Laplace operator" and comments closing it with
T354 and T359. `agents/table-ideas/BATCH-2026-09-21T1843.md` says "no
proposal below cites a request, because there is none left to cite."
