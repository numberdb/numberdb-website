## Named Sage imports: `QQ(a) / 24` raises about a module you never mentioned, and `sage.functions.other` will not import at all

What happened: a T337 check needed the Bernoulli numbers and a factorial. The
file followed the skill's generator template — `import numberdb.sage as
numberdb` first, then named imports — and two ordinary lines failed with
errors that name neither the line nor anything the file imports.

    from sage.functions.other import factorial

        File "sage/symbolic/expression.pyx", line 14220, in init
          sage.symbolic.expression
        AttributeError: cannot access submodule 'function' of module
        'sage.symbolic' (most likely due to a circular import)

and, with only `from sage.rings.rational_field import QQ` imported,

    QQ(-1) / 24

        File "sage/rings/rational_field.py", line 1124, in _an_element_
          return Rational((1, 2))
        AttributeError: module 'sage.rings' has no attribute 'real_mpfr'

Twelve frames of `sage.structure.coerce`, ending in a module the file never
mentions. The cause is that dividing a `Rational` by a Python `int` sends Sage
to `discover_action`, which builds an element of the coercion candidate and
lands in `real_mpfr`, which nothing has imported. `QQ(-1) / QQ(24)` works;
so does `QQ(-1) / 24` after an explicit `import sage.rings.real_mpfr`, which
confirms the diagnosis. Adding `PolynomialRing` does **not** fix it, so "import
a bit more of Sage and hope" is not a strategy.

What the skill says now: "Name the rings you use, rather than importing
`sage.all`", with a list of what named imports do not bring — root finding,
`RealBall.str`, `QQ('1.25')`. And, for a different reason (exactness above
2^53), "write every division between Sage rationals, `QQ(a) / QQ(b)`".

What it should say: add these two to that list, and note that the
`QQ(a) / QQ(b)` rule has a second reason. Under named imports a division
between a Sage rational and a Python `int` can raise `AttributeError: module
'sage.rings' has no attribute 'real_mpfr'` from inside the coercion machinery,
naming a module the file never imports; writing both sides as `QQ(...)` keeps
the operation inside one parent and never reaches `discover_action`. And
`sage.functions.other` — the obvious home for `factorial`, `binomial`, `abs`
— cannot be imported from a cold start at all: it pulls `sage.functions.trig`,
then `sage.symbolic.function`, and raises a circular-import `AttributeError`.
Use `math.factorial`, or `sage.arith.misc` (`bernoulli`, `factorial`,
`binomial`), which imports cleanly.

Both are the kind of failure that reads as a broken Sage rather than a missing
import, which is what makes them expensive: the traceback's last line is about
`real_mpfr` or `sage.symbolic`, and the fix is on a line that mentions
neither.

Evidence: 2026-09-19, T337 critique, three runs of `agents/sage.sh
/tmp/coeff.py` against `numberdb/builder:latest` (SageMath in the builder
image, Python 3.12). Final run printed `QQ/int: AttributeError: module
'sage.rings' has no attribute 'real_mpfr'`, `QQ/QQ: -1/24`, `QQ/int after
importing real_mpfr: -1/24`. T337's and T336's own `Programs` blocks both
already work around the first by writing `from math import factorial`.

## A table joining a family the corpus already holds: check the Definition is not true of its sibling

What happened: T337 ($\hat A$-genus polynomials) is the fourth of a batch —
T334 Todd, T335 Chern character, T336 Hirzebruch $L$ — of universal
characteristic-class polynomials, each defined by a multiplicative sequence.
Its Definition reads "the homogeneous component $\hat A_n(p_1,\dots,p_n)$ of
the $\hat A$-class, written in Pontryagin classes and defined by Formula
CITE{formula-component}", and its Formula `formula-component` is T336's
letter for letter with $L_n$ replaced by $\hat A_n$: the same Pontryagin
roots, the same $\prod_i Q(x_i)$, the same $Q$ defined nowhere in either.

So the Definition, together with the formula it cites, is a true statement
about the Hirzebruch $L$-polynomials. What separates the two tables is a
second formula that the Definition does not point at. T334 and T336 both
carry the series in the Definition itself — "It is defined by the
characteristic power series $Q(x)=\sqrt{x}/\tanh\sqrt{x}$ through Formula
CITE{formula-component}" — and T337's revision message is "shorten A-hat genus
definition", so the clause was there and was cut.

The same edit dropped the other clause its siblings carry, the one naming what
the class is a class *of*. T337 inherited T336's comment "the convention here
is $p_i=(-1)^i c_{2i}(E\otimes\mathbb C)$" without inheriting the Definition's
"of an oriented real vector bundle $E$", so $E$ reaches the reader with no
antecedent anywhere above it. Nothing catches that: the audit checks `CITE`
and `HREF` targets, not whether a symbol was ever introduced.

What the skill says now: "**Definition** | one or two sentences saying what
the object *is*", and "precisely enough that two people would build the same
table". It says a table should search the corpus for the family before
starting, and it says to link what the corpus already holds. It does not say
to read the sibling's definition afterwards.

What it should say: when a table joins a family the corpus already holds —
one function of several, one convention of two, one member of a batch — read
the sibling table's Definition beside your own and ask whether yours is *false
of theirs*. If the two are interchangeable, the distinguishing fact is
somewhere else on the page and the Definition is not doing its job. The
cheapest form of the test: substitute the sibling's symbol into your
Definition and the formula it cites, and see whether anything is now wrong.
The second half of the test costs nothing either: a comment copied across from
a sibling arrives with the symbols its old Definition introduced, and those
have to come with it or be reintroduced.

Evidence: 2026-09-19, drafts T337 and T336, `GET /api/table?id=...` for both.
T337 `Definition` and `Formulas.formula-component` against T336's; T337
`Comments.comment-variables` identical to T336's, with `$E$` undefined in
T337. The whole page was rebuilt (sqlite draft-render recipe, 6 records,
status 200, 32,337 bytes) to confirm nothing between the Definition and that
comment introduces $E$. `GET /api/table/T337/audit` answers `clean: true`.
