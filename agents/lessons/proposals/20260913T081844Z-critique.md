## A SnapPy snippet that passes `verified=True` is a Sage program, not a Python one
What happened: T225's `Programs` entry is labelled `Python` and calls
`Manifold('m004').volume(verified=True, bits_prec=400)`. SnapPy's own
documentation says that "verified computations are only available when using
SnapPy inside SageMath". The call returns a Sage `RealIntervalFieldElement`,
and in plain Python it fails. T141 carries the same call and labels it `Sage`,
so the corpus already disagrees with itself about the label.
What the skill says now: that `Programs` is "the standard incantation in Sage,
PARI or mpmath". It says nothing about choosing the `language` label.
What it should say: label a snippet with the environment it actually runs
in, not the language its syntax looks like. Any `verified=True` SnapPy call,
and any call returning a Sage ring element, is `Sage`. Where a snippet is
meant to run in plain Python, run it there once.
Evidence: <https://snappy.computop.org/verify.html> ("Note that verified
computations are only available when using SnapPy inside SageMath"). Under
Sage, the snippet printed `2.02988321281930725004...?` with type
`sage.rings.real_mpfi.RealIntervalFieldElement`. T141 `program-snappy` has
`language: Sage`.

## Resolve every `doi:` before writing it; nothing downstream does
What happened: T225's `HIKMOT` reference carries
`doi: 10.1080/10586458.2015.1022840`, which answers 404 at doi.org. Crossref
gives the paper (Experimental Mathematics 25, 66-78) as
`10.1080/10586458.2015.1029599`. The page renders the bad DOI as a link. The
shape check `malformed_identifiers` passes it, because it is well formed.
`audit_table --links` fetches only `Links` and never a Reference's
identifiers.
What the skill says now: that `bib` takes `arxiv`, `doi`, `zbl` and `mr`
beside it, and that each renders as a link.
What it should say: a DOI that renders as a link has to resolve. Check each
one with `curl -o /dev/null -w '%{http_code}' https://doi.org/<doi>`, where
302 is good and 404 is not. When it fails, look the title up at
`https://api.crossref.org/works?query.bibliographic=<title>` rather than
correcting it by eye. Also cite every reference you list. This one was cited
nowhere, which is why nobody clicked it.
Evidence: 2026-09-13, T225 critique. doi.org answered 404 for the stored DOI
and 302 for the other two references. The Crossref query returned `1029599`
with matching title, volume and pages.
