## A program that prints a list has to be compared with the rows, not only run

What happened: the Sage program under T286's `Programs` builds pairs
`(minimal polynomial, root)` and ends with `sorted(pairs)[:10]`. Python sorts
a tuple by its first component, so the list came out in Sage's order on
polynomials. It started with $\theta_4$, was out of order, and left out
$\theta_{10}$. The program runs without error, and its output contains the
plastic ratio and most of the first rows, so a check that it runs, or that
it produces the first entry, passes.

What the skill says now: nothing about `Programs` beyond "the standard
incantation". The proposal already in `PROPOSALS.md` ("run it before writing
it down") checks one entry.

What it should say: when a program prints several values, compare its output
line by line with the rows it claims to reproduce, in order. When sorting
pairs, give the sort key explicitly (`key=lambda t: t[1].lower()` for an
interval).

Evidence: T286 critique, 2026-09-17. The program's output began
`x^3 - x^2 - 1 | 1.46557123188`, and with the key added it gives rows 1 to 10
exactly.
