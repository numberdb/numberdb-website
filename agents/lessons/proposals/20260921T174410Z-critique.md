# Lessons proposed by the T5 growth critique, 2026-09-21

One, met while reading T5 (*Exponent of matrix multiplication complexity*)
against <https://numberdb.org/skill>. It is reachable by a contributor with a
laptop, Python and a browser; it is not about this deployment.

---

## A value known too coarsely is dropped from search by number, and the cutoff is a relative width of 1e-5

What happened: T5 holds one entry, `[2, 2.3728596]` — the interval between the
trivial lower bound on the matrix multiplication exponent and the best upper
bound published when the entry was written. The table is correct, is
`rigour: proven` (an interval between two theorems is an honest enclosure), and
passes every limit. It also answers **no search by number at all**, now and
permanently:

    /api/lookup?text=2.3728596   →  0 results   (the entry's own upper endpoint)
    /api/lookup?text=2.2         →  100 results, T5 not among them (inside it)
    /api/lookup?text=2.685452001 →  T170, Khinchin's means  (control: lookup works)

The reason is `numberdb_app/search.py:_identifiable`, which excludes values
whose `exact_relative_width` exceeds `NUMBERDB_MAX_RELATIVE_WIDTH`, default
`1e-5` — roughly, fewer than five significant figures pinned down. T5's
interval has relative width about 0.17, four orders of magnitude over. The
exclusion is right: a search that returned T5 for every number between 2 and
2.37 would bury every real hit in that range, and the docstring says so.

What makes it a lesson rather than a footnote is that **nothing an author does
signals this.** The value is accepted, the table publishes, `rigour: proven`
is granted, `audit_table` says nothing, and the table appears in listings and
in text search. The only sign is on the rendered table page, where the value
carries a dagger linking to `/help#search-precision` — which an author sees
only if they look at their own table in a browser after publishing, and which
says nothing at all in the API response or the client.

A contributor hits this on their own laptop the moment they build a table of
quantities that are genuinely known coarsely: bounds from theorems, Ramsey-style
intervals, experimentally measured constants, anything where the honest
enclosure is wide. Those are exactly the tables the rigour ladder in §7 is
written to encourage, and the author's reasonable conclusion — "I stated the
width honestly, so the value is usable" — is half wrong: it is readable and
citable, and it is not findable.

What the skill says now: nothing. §7 is a careful account of how well the digits
must be known and how to say so, and is entirely about the *claim* an author
makes. §2 ("Hold the numbers that turn up") and §3 are about whether anybody
will arrive holding a value. Neither connects the two: there is no sentence
saying that below a stated precision the corpus will not hand the value back to
somebody who arrives holding it. The word "findable" appears in the skill three
times and every time it means findable *by name*.

What it should say: in §7, beside the rigour ladder — search by number needs
about five significant figures. A stored value whose relative width is wider
than 1e-5 is excluded from search by number (`NUMBERDB_MAX_RELATIVE_WIDTH`),
because a wide interval overlaps every query in its range and would bury the
values that are pinned down; it stays on its table page, marked with a dagger,
and stays findable by title, tags and definition. So when an honest enclosure is
wider than that, the table is a *reference page*, not a search target, and two
things follow: the title and `Keywords` are carrying the whole load and should
be chosen for it, and a wide value belongs in a row only if the table's prose
would find a reader without it.

For a named constant whose width is ignorance about mathematics rather than
error in a computation — T5's case — that is the correct state and not a defect.
The lesson is to know it before publishing rather than to discover it when
somebody reports that the table cannot be found by its own number.

Evidence: 2026-09-21. `numberdb_app/search.py:89` (`max_relative_width`,
default `1e-5`) and `:108` (`_identifiable`). The three lookups above against
the live corpus. The dagger is `not-findable-mark` in the rendered HTML of
`https://numberdb.org/T5`, title "This number will not be found in the search.
Click for why." Full working in `agents/critiques/T5-growth.md` §7.
