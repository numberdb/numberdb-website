## Sage graph objects may not expose `cycle_matroid()` under named imports

What happened: while repairing T396, a Sage check for the graphic controls
used `graphs.CompleteGraph(4).cycle_matroid()` and failed with
`AttributeError: 'Graph' object has no attribute 'cycle_matroid'` in the
builder image. The same check worked by using Sage's matroid catalog
constructors, `sage.matroids.catalog.K4()` and `K5()`, and comparing those
matroids with the graph chromatic and Tutte polynomials.

What the skill says now: import `numberdb.sage` first, name the rings, and
expect some Sage machinery to be missing. It does not mention graphic-matroid
checks.

What it should say: when a table about matroids needs a graphic-matroid
control for a named graph that Sage's matroid catalog already provides, use the
catalog constructor, such as `sage.matroids.catalog.K4()`, rather than relying
on a graph method being available under named imports. It is the same object
family the table's catalog rows use, and it avoids an import-dependent graph
method.

Evidence: T396 repair on 2026-09-22. `/tmp/t396_check_targeted.py` first failed
at `graphs.CompleteGraph(4).cycle_matroid()` with the AttributeError above.
After changing the check to `catalog.K4()` and `catalog.K5()`, `agents/sage.sh`
reported 55 uniform rows checked against the closed form, five flats/Whitney
samples checked, and graphic controls `K4`, `K5` checked.
