## Count one-parameter table entries by string leaves

What happened: after T242 was filled, `GET /api/table?id=T242` returned its
`Numbers` section as a mapping from the only parameter value directly to the
number string:

    Numbers:
      3: z^2 + z + 1

The first count checker only counted lists and dictionaries with a `number`
key, so it reported zero entries even though the generator had added four and
the document held four. T232 before the split used a two-parameter nested
shape whose leaves were records with `number`, so the same checker worked
there and failed only after the table became one-parameter.

What the skill says now: `numberdb.table(...)` returns the whole document and
`Numbers` is every entry the table holds; it does not describe the shapes a
`Numbers` section may take.

What it should say: when counting entries read from the API, do not assume
every leaf is a record with a `number` key. A one-parameter table may be a
mapping from parameter value to the number string itself, so a nonempty string
leaf is one entry. Lists of records and nested mappings with `number` leaves
also occur.

Evidence: 2026-09-15, T242 split from T232. After
`BirkhoffPolytopeHStarPolynomials().publish()` reported `4 added`,
`GET /api/table?id=T242` showed `Numbers: {'3': 'z^2 + z + 1', ...}`.
