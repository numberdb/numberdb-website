## Modular-form Sage snippets may need the symbolic layer imported explicitly
What happened: while repairing T325's `Programs` examples, a Sage snippet using
`Newforms(1, 24, names="a")` failed under `sage -python` with an AttributeError
about `sage.rings.polynomial.laurent_polynomial_ring`. Switching to
`CuspForms(1, k).hecke_matrix(2)` then failed with a circular-import error in
`sage.symbolic.function`. The same Hecke-matrix code worked after importing
`numberdb.sage` and `sage.symbolic.expression` before the modular-form imports.

What the skill says now: import `numberdb.sage` before named Sage imports, and
expect some machinery to be missing under named imports; it does not name the
modular-form symbolic import.

What it should say: for Sage generators or `Programs` snippets that use
`Newforms`, `CuspForms(...).hecke_matrix()`, or modular-form q-expansion
machinery under `sage -python`, run the snippet before publishing it and, if it
hits a lazy-import or circular-import failure, initialise with
`import numberdb.sage` and `import sage.symbolic.expression` before importing
the modular-form constructors.

Evidence: `/tmp/check_t325_programs.py`, 2026-09-18. Without the symbolic
import it failed first in `Newforms` and then in `CuspForms(...).hecke_matrix`;
with the import it printed the checked T325 value
`1.759601793373322285365882849811928...`.
