## An unauthenticated sweep of the API stops at 60 requests an hour, and a helper that ignores the status code reports that as "nothing found"

What happened: I wanted the list of proposals other workers were holding, so I
asked `/api/claim?family=N` for each of families 150-239 -- ninety requests,
with plain `urllib` and no `Authorization` header, inside a `try/except` that
skipped a family it could not read. It answered:

    total standing claims 150-239: 0

Not an error. A number, and a plausible one. Repeating the same ninety
requests through a helper that attaches the API key returned **49** standing
claims across four workers. The difference is the key: `/api/` allows **60
requests per hour per IP** for an anonymous caller and **1000 per hour per
key** (`numberdb_app/throttle.py:47,51`; window `NUMBERDB_RATE_LIMIT_WINDOW`,
60 minutes by default). A ninety-family sweep spends the anonymous budget
about two-thirds of the way through and every request after that is a 429:

    HTTPError 429 {"error": "Rate limit exceeded (60 requests per 60 minutes).
    An API key raises this limit; see /help#section-api.", "retry_after": 1820}

The refusal is well-made -- it is JSON, it says the limit, it sets
`Retry-After`, and it names the remedy. What went wrong was entirely on my
side: an `except Exception: continue` turned two-thirds of a survey into
silence, and the surviving third into an answer. The failure is invisible
precisely because the endpoint's honest empty answer and its rate-limited
answer both come back as "no rows".

This is not specific to `/api/claim` or to a campaign runner. Any loop over
the API -- checking a list of constants against `/api/lookup`, pulling a
family's tables one at a time to compare conventions, re-reading values to
verify a generator -- crosses 60 requests quickly, and a reader following the
skill will be doing exactly that from a laptop. The same shape appears in this
repository's own helper: `agents/queue.py`'s `held_by_others()` returns
`set()` on any non-200, so a rate-limited caller is told nobody holds anything.

What the skill says now: nothing about rate limits, and nothing about checking
a status code before believing an empty result.

What it should say: two sentences, in whatever section covers talking to the
API.

* Use your key for anything that makes more than a handful of requests. The
  anonymous limit is 60 requests per hour per IP; a key raises it to 1000, and
  the key is the only difference between a sweep that works and one that
  quietly truncates.
* When a loop over the API returns nothing, check the status code before
  believing it. A 429 and an honest empty answer look identical to any code
  that only reads the body -- so make the loop stop on a non-200 rather than
  skip the row, and honour `Retry-After` if you mean to continue.
