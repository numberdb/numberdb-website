# Lessons proposed by the T315 critique, 2026-09-17

## The numbers come first on the page, so a symbol in the column header or in an entry comment is read before any prose defines it

What happened: T315 stores a Laurent family as a shifted representative. Its
column header reads $q^{-a}t^{-b}Kh_K(q,t,T)$ and each of its 479 entry
comments reads `$a=-9, b=-3$` or the like. Its Definition says "shifted into
ordinary polynomial form" and stops; $a$ and $b$ are defined in the second
`Comments` field, which on the rendered page comes after the numbers, after
the Definition, after the parameter list and after three formulas. A reader
who arrives holding one of these polynomials meets the symbol several hundred
times before meeting its definition. Its two sibling tables put the shift in
the Definition in one clause -- T139 "listed as $t^{-m}V_K(t)$ with nonzero
constant term", T314 "listed as $a^{-m}F_K(a,z)$ with $m$ the lowest exponent
of $a$" -- and read much better for it.

What the skill says now: where each thing goes ("Definition: one or two
sentences saying what the object *is*"; "Comments: conventions, caveats"), and
that the value column's header "is a claim about every value under it". It
does not say what order a reader meets those in, and the section table reads as
if the Definition were the top of the page.

What it should say: the numbers block is rendered *above* the Definition, so
the first prose a reader sees is the column header and the entry comments.
Any symbol that appears there -- a shift exponent, a normalisation constant --
is read before the field that defines it, whichever field that is. When a
table stores a representative rather than the object itself, name the
representative in the Definition, in the same form the header uses; the
comment then carries the worked example rather than the definition.

Evidence: 2026-09-17, T315 read against T139 and T314. The rendered page (479
rows, 497 KB) puts `table-number-section-outer-container` before
`table-section-title">Definition`; the first row shown is `0 1 $K$: q^2 + 1,
comment: $a=-1$`, and the sentence defining $a$ is the fifth block of prose
below it.

## Test a `Programs` snippet through Sage's preparser, not with `sage -python`

What happened: T315's `Programs` block is Sage, and contains
`sum(c*q^(e[0]-a)*t^(e[1]-b)*T^(e[2]) for e, c in Kh.dict().items())`. Run
under `sage -python`, which has no preparser, `^` is exclusive-or and the line
either fails or silently computes something else; run in the Sage REPL, which
is what the block is written for, it is exponentiation. Checking the block the
way a reader will use it took two lines:

    from sage.repl.preparse import preparse
    import sage.all
    exec(compile(preparse(SNIPPET), 'snippet', 'exec'), dict(sage.all.__dict__))

That reproduced the table's stored entry for $5_2$ character for character on
SageMath 10.9, and confirmed that the comment written into the snippet
(`# q^13*t^5 + q^11*t^5*T^2 + ...`) is what Sage actually prints.

What the skill says now: "`sage -python` has no preparser, so `factorial(30)`
is a Python `int`" -- about a *generator*, whose file really is run that way.
Nothing about the `Programs` block, which is the opposite case: it is written
for the REPL and `^` there is correct.

What it should say: a `Programs` block is REPL input, so `^` is right in it
and `sage -python` is the wrong way to check it. Preparse and exec it in the
`sage.all` namespace, and compare the result against a row of the table --
which also checks the output shown in the snippet's own comments, the part a
reader compares against before running anything.

Evidence: 2026-09-17, T315 critique, `/tmp/t315_program_check.py` run through
`agents/sage.sh`: `matches stored 5_2 entry: True`, and `Kh(0_1) = q + q^-1`,
which is the table's own formula for the unknot.
