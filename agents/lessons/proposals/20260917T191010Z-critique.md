# Proposed from the T311 critique, 2026-09-17

## LaTeX written in a plain Python string silently becomes control characters

What happened: T311's Definition renders "Let $\gamma_2(au)^3=j(au)$ ... for
prime $\ell<br>e3$". The stored string holds three literal tab characters
where `\tau` should be, and a literal newline where `\ne` should be. Nobody
typed a tab. The Definition was edited from a Python session, and the text was
written as an ordinary string literal rather than a raw one:

    text = "$\gamma_2(\tau)^3=j(\tau)$ for prime $\ell\ne3$"

Python keeps `\g` and `\e` (they are not escapes, only a DeprecationWarning)
and converts `\t` to a tab and `\n` to a newline. `json.dumps` then faithfully
sends one backslash-g, one tab, one backslash-e, one newline, the API accepts
it -- it is valid prose, nothing is malformed -- and the page draws "au" and
"e3". `audit_table` answered `{"findings": [], "clean": true}` on the table
afterwards.

The LaTeX that this destroys is not exotic. Every one of these is a control
character in a plain Python literal: `\tau` `\theta` `\times` `\to` `\top`
(tab), `\ne` `\neq` `\nu` `\nabla` (newline), `\frac` `\forall` `\flat`
(form feed), `\beta` `\binom` `\bar` (backspace), `\alpha` `\approx` `\angle`
(bell), `\varepsilon` `\vec` (vertical tab), `\rho` `\rightarrow` (carriage
return). A definition that survives review is one that happened not to use
them.

What the skill says now: nothing. It says nothing about backslashes, escaping,
or JSON at all -- grepping the published skill for "backslash", "escape" or
"json" returns no line. It shows LaTeX in YAML documents, where the problem
does not arise, and does not say that editing a field from Python is
different.

What it should say: write LaTeX in a **raw** string (`r"$\tau$"`), or keep it
in the YAML document and send that. A plain `"...\tau..."` in Python is a tab,
the API accepts it, the audit passes it, and the page prints "au". The fault
is invisible in the document a reader of the repository sees -- T311's
`table.yaml` has the correct `\tau`; only the stored copy is damaged -- so it
is found by fetching the rendered page or by looking at the bytes
(`repr(numberdb.table('T311')['Definition'])` shows the tab at once).

Evidence: 2026-09-17, T311 critique.
`curl -H 'X-API-Key: ...' https://numberdb.org/api/table?id=T311` returns
`"Let $\\\\gamma_2(\\tau)^3..."` in its wire bytes -- `\\gamma` escaped,
`\tau` not -- and the rendered HTML from `/preview?table=` contains
`Let $\gamma_2(&#9;au)^3=j(&#9;au)$` and `for prime $\ell<br>e3$`.
`generators/modular-polynomials-gamma2/table.yaml` in the repository is
correct, so the two disagree.

## `\sqrt[n]{...}` in an `HREF` caption truncates the link at the bracket (second occurrence)

What happened: T311's Similar-tables entry
`HREF{Class_polynomials_of_gamma_2_sqrt_3_j}[Class polynomials of $\gamma_2=\sqrt[3]{j}$]`
renders as

    <a class="HREF" href="...">Class polynomials of $\gamma_2=\sqrt[3</a>{j}$]

The caption parser ends the caption at the first `]`, which is the one closing
`\sqrt[3`. The reader gets a link whose text stops inside an unclosed square
root and a stray `{j}$]` printed after it.

This is the same rule as the proposal of 2026-09-13
(`20260913T064851Z-repair.md`), which met it as `HREF{...}[$[3,5,3]$]` and is
still unaccepted. The trigger here is worth adding because it is the common
one: the caption was the linked table's **own title**, copied across, and that
title contains `\sqrt[3]{j}`. Anybody linking a table whose title uses
`\sqrt[n]`, `\overline[..]`, or any LaTeX optional argument will write a
caption that breaks, and will have done nothing unusual to get there.

What the skill says now: `HREF{slug}[caption]`, with nothing about what may go
inside the brackets.

What it should say: a caption is read to the first `]`, so no `]` may appear
inside one -- including LaTeX optional arguments such as `\sqrt[3]{j}`. When
the table's title carries one, shorten the caption
(`[Class polynomials of $\gamma_2$]`) rather than copying the title.
`audit_table` will not catch it: its own mask, `HREF\{[^}]*\}(\[[^\]]*\])?`,
truncates at the same place and so sees a well-formed caption.

Evidence: 2026-09-17, T311 critique; the rendered HTML above came from
`/preview?table=` carrying T311's `Similar tables`.
`numberdb_app/management/commands/audit_table.py`, `_prose_faults`, has the
matching regex; the audit returned `{"findings": [], "clean": true}`.
