# Lessons proposed by the T430 critique, 2026-09-23

Format and scope as `agents/lessons/PROPOSALS.md`. Nothing here is in force.

Both are true for a contributor with a laptop, Sage and `pip install
numberdb`: one is the shape the site's renderer requires of a field the skill
names but never spells out, and one is what MathJax does to a `$…$` that
contains a link.

---

## `Programs` is a mapping with `language` and `code`; a bare string there makes the table page a 500

What happened: T430 stored

    Programs:
      Sage: "Run the attached generator with SageMath: …"

which is the obvious reading of the skill's line "`Programs` | the standard
incantation for a reader who wants one more value". The write API accepted it.
`GET /api/table/T430/audit` answered `{"findings": [], "clean": true}`. And
the table page cannot render: `numberdb_app/views.py:961` does
`render_text(program['language'])` and then `program['code']`, indexing a
`str` by `'language'` raises `TypeError`, `table_context` re-raises it as
`ValueError` at `views.py:1507`, and `render_table` at `views.py:489` does not
catch it. `/preview` shows the whole failure in one line —
`Error while Parse program Sage: string indices must be integers, not 'str'`
— and renders nothing else. `/preview/<tid>` and `/review/<tid>` go through
the same function, so a draft in this state cannot be reviewed either.

The shape every published table uses, and the one that renders:

    Programs:
      program-sage:
        language: Sage
        code: |
          R.<x> = ZZ[]
          polynomials = {n: chebyshev_U(n, x) for n in [0..100]}

(`T99`, `T7`, and every other table with a program; `GET /api/table?id=T99`
returns it verbatim.) `language` is matched against a small table of
highlighters — `Sage` maps to `python`, anything else to no highlighting — so
it is a language name and not a caption.

What the skill says now: the section table says `Programs` holds "the standard
incantation for a reader who wants one more value", and §6 says "`Programs`
and `generate.py` answer different questions". Neither says the field is a
mapping of named programs, nor that each one is itself a mapping with
`language` and `code`. Every other section in that table takes prose, so a
string is what an author reaches for.

What it should say: in the section table, `Programs` | *named programs, each
a mapping with `language` and `code`* | *the generator*. And a sentence worth
having on its own, because it is the only field in the document whose shape
can take the page down: a `Programs` entry that is a string rather than a
mapping is accepted by the API and by `audit_table`, and the table page then
answers 500. Preview the document before offering it; `/preview` calls the
same `table_context` the page calls, and `build_preview_context`'s docstring
says so ("an editor that previews through different code from the page is
worse than no preview").

The audit could catch it in one line. `audit_table.py:447` already reads the
field and writes `code = (program.get('code') or '') if isinstance(program,
dict) else ''` — the `else ''` branch is exactly the broken document, stepped
over so the range-staleness check does not crash. A finding there instead of
an empty string would have caught T430 before it was offered.

Evidence: 2026-09-23, draft T430. `GET /api/table?id=T430` shows the string;
previewing that `Programs` block alone answers 200 with the error line and no
table; previewing the same stub with `{language: Sage, code: "print(1)"}`
renders. Audit clean throughout.

## A `$…$` must not span a `HREF{}`: MathJax finds no fragment, and re-pairs the delimiters with the next `$`

What happened: T430's second comment reads

    …along the Fibonacci branch they approach $4-HREF{Golden_ratio#phi}[\varphi]$,
    and along the Pell branch they approach $1+\sqrt2$.

The renderer turns the `HREF{}` into an `<a>`, so the `$` that opens the
formula and the `$` that closes it end up on opposite sides of an element.
MathJax 3 does not carry inline math across an element boundary, and it does
not complain: it simply does not see that fragment, and then pairs the two
*remaining* dollars — the one that was closing the first formula and the one
that was opening the second — into a fragment of its own.

Run over exactly that HTML with `mathjax-full@3` and the site's delimiters
(`inlineMath: [['$','$'],['\\(','\\)']]`), the document contains **one** math
item, and it is

    ", and along the Pell branch they approach "

So the reader sees the literal text `$4-`, a link whose caption is the literal
text `\varphi`, the words *,andalongthePellbranchtheyapproach* set as italic
mathematics, and then `1+\sqrt2$.` printed as English. One `$` on the wrong
side of a link destroys the rest of the sentence, and nothing anywhere says
so: the stored YAML looks right, `audit_table` is clean, and no `merror` is
produced.

What the skill says now: it gives the right form in passing —
`HREF{Feigenbaum_constants#delta}[$\delta$]` and
`HREF{Golden_ratio#phi}[$\varphi$]`, with the mathematics *inside* the
caption — but only as examples of linking one entry, and it never says that
the other arrangement fails. It does have the neighbouring lesson, that a `<`
in mathematics ate the rest of a section.

What it should say: the mathematics goes inside the caption, never around the
link. Write `HREF{Golden_ratio#phi}[$\varphi$]`, not
`$HREF{Golden_ratio#phi}[\varphi]$`, and where the link sits inside a larger
formula, close the formula first: `$4-{}$HREF{Golden_ratio#phi}[$\varphi$]`,
or lift the link out of the formula altogether ("$4-\varphi$, where $\varphi$
is HREF{Golden_ratio#phi}[the golden ratio]"). The same check that counts `$`
per field catches this one too if it is done after the `HREF{}` is expanded:
a `$` on one side of a link and its partner on the other is always a bug.

Evidence: 2026-09-23, draft T430, comment `accumulation`. `/preview` gives
`…approach $4-<a class="HREF" href="Golden_ratio?entry=phi">\varphi</a>$, and
along…`; `mathjax-full@3` (`tex` → `svg`, packages base + ams) over that
string reports one math item, `", and along the Pell branch they approach "`,
and no error. The control in the same run — the same sentence with the
dollars inside the caption — typesets two fragments and keeps the link.
