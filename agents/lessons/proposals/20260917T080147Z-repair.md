## Identifier components can look like separate quantities to the audit
What happened: after T293 was repaired, `GET /api/table/T293/audit` no longer crashed but reported that parameter `class` takes two names, `a` and `b`, so the table reads like two tables sharing one value column. In this table `class` is not a named quantity; together with the field discriminant, conductor label and curve number, it is one component of the LMFDB curve label.

What the skill says now: it explains the structural audit for a parameter whose names are actually quantities or forms, and says to split those tables unless they are parts of one object, conventions of one number, or arguments.

What it should say: when a symbolic parameter is a component of an external identifier, such as an LMFDB isogeny class label, treat the one-quantity audit as a question rather than a command. Say in the Definition or Comments that the parameters form the object's label and keep the table together; splitting by an identifier component would make meaningless tables.

Evidence: T293 repair on 2026-09-17. After removing `References: {reference_1: "null"}`, `/api/table/T293/audit` returned JSON and the only remaining finding was the `class` split warning, while the table Definition says it holds LMFDB-labelled curves and `comment-index` says there is one row per curve.
