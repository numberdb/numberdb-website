## The generator attachment name follows the script basename
What happened: repairing T348 from a scratch file named `/tmp/T348-generate.py`, `fill_draft_once()` replaced the entries correctly but attached the source as `T348-generate.py`. Posting the same body to `/api/table/T348/file/generate.py` updated the canonical attachment, but the public API has no delete operation for the extra scratch-named file.

What the skill says now: it says the attached generator should be opened as `generate.py` and run with `sage -python generate.py`, but it does not say that the filename is what the client records when it attaches source files.

What it should say: when a generator run will attach its own source, run it from a file whose basename is the filename readers should see, normally `generate.py`. A renamed scratch copy can compute the right entries while leaving the table with a stray attachment under the scratch basename.

Evidence: T348 repair on 2026-09-20. `NUMBERDB_PUBLISH=1 agents/sage.sh /tmp/T348-generate.py` returned `files: ['T348-generate.py']`; a subsequent `POST /api/table/T348/file/generate.py` updated `generate.py`, and `/files/T348` listed both names.
