# Proposed lessons from the T421 critique, 2026-09-23

Nothing here is in force. Format as in `agents/lessons/PROPOSALS.md`.

## `complete` answers yes, no or unknown, and `true` passes every check

What happened: T421 stores `complete: true` under `Data properties`. The API
accepted it, `audit_table` reports the table clean, and the page renders
"Table is complete: true" -- verbatim, because the view prints the value and
appends `complete-note` in parentheses. Every other table in the corpus says
`yes` or `no`: T7 renders "Table is complete: yes (it holds the single number
named by the definition ...)", T25 and T99 "Table is complete: no". The site
itself knows the vocabulary is closed -- `numberdb_app/metadata_form.py` has
`COMPLETENESS_ANSWERS = ('yes', 'no', 'unknown')` and sets `complete_is_odd`
on anything else, so the edit form flags it -- but nothing a run touches does,
and a generator or a hand-written document never goes through that form.

What the skill says now: it shows `complete: no` with a `complete-note`, and
explains that the note renders inside "complete: no (...)". It never says what
`complete` may answer, so a contributor writing YAML reaches for the boolean
their language uses.

What it should say: `complete` answers `yes`, `no` or `unknown`. It is printed
as written, so `true` reaches the page as "Table is complete: true", which no
other table says. `complete-note` finishes that sentence in parentheses, and
is worth having on a `yes` as much as on a `no`: T7's says which number it
holds and which table holds the scaled ones.

Evidence: `GET /api/table?id=T421` (`"complete": "true"`); the same document
through `numberdb.org/preview` renders `Table is complete: true`; `curl
https://numberdb.org/T7 | grep 'Table is complete'` gives the `yes` form;
`GET /api/table/T421/audit` answers `{"findings": [], "clean": true}`.

## The audit asks the one-table question only of a table with two parameters

What happened: T421 has one parameter, `constant`, taking the three names
`radial-shear`, `azimuthal-shear` and `axial-inflow`. That is the exact shape
the skill warns about -- a parameter whose values are a handful of names -- and
the audit said nothing, because `_one_table_or_several` in
`numberdb_app/management/commands/audit_table.py` returns immediately when
`len(params) < 2`. The check looks for the same grid repeated once per label,
and a one-parameter table has no grid to repeat. (T421's answer happens to be
the good one: the three are parts of one similarity solution. That is a
judgement nobody was asked to make.)

The column-heading half of the same question is narrower than it reads too:
`_column_names_its_quantity` fires only when `number-header` is one of ten
generic *words* (`value`, `number`, `constant`, ...). T421 heads its column
`$F'(0)$, $G'(0)$, $-H_\infty$`, a list of three symbols of which one is true
of each row -- the same admission that no symbol is true of all of them, in
LaTeX rather than in English -- and it passes.

What the skill says now: the rule, at length, and then "the audit now reports
it on a draft", which reads as a promise that the check will ask.

What it should say: the check asks a table with two or more parameters. A
table with one parameter whose values are names, and a table whose
`number-header` lists several symbols instead of naming one, are the two
shapes it cannot see -- ask yourself, because nothing will ask you.

Evidence: T421's clean audit beside its one-parameter, three-name document;
`audit_table.py` lines around `if len(params) < 2: return` and
`GENERIC_HEADERS`.

## A reference nobody cites is not reported by anything

What happened: T421 declares four `References`. Three are reached by `CITE{}`;
`Cochran` -- the 1934 paper where these three constants were first computed
accurately, and a name the table's own `Keywords` advertises -- is reached by
nothing, and renders as `[2]` in a numbered list with no way into it from the
prose. The audit checks the other direction only: `CITE{X} is not a Link or a
Reference`.

What the skill says now: "A reference is for citing, not for listing.
`CITE{Koshy}` in a comment earns its place; a bibliography nobody points at is
furniture." The rule is there; nothing enforces it, and a run that adds a
bibliography while writing the prose separately will not notice.

What it should say: the same sentence, with the warning that the audit checks
`CITE` to target and never target to `CITE`, so an uncited reference is
invisible to every check. Read the `References` keys against the `CITE{}`
markers before offering a draft -- it is one grep over the document.

Evidence: T421's document; `grep -n "CITE" audit_table.py` shows the single
direction, at the `'CITE{%s} is not a Link or a Reference'` finding.
