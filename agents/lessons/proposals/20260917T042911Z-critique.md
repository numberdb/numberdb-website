## A key used in both `Comments` and `Formulas` is numbered once and anchored twice

What happened: T291 has a formula keyed `suspension` and a comment keyed
`suspension`. On the rendered page the Formulas section reads `(1)`, `(4)`,
the Comments section reads `(3)`, `(4)`, and no block is `(2)`. The HTML has
`id="suspension"` twice. The block labels are numbered by key across both
sections, so a reused key gets one number and loses the other.
`HREF{#suspension}` cannot say which block it means. Neither the API nor
`audit_table` refused or reported it.

What the skill says now: nothing. It says a parameter's key is an address, but
not that keys in `Comments` and `Formulas` share one numbering and one set of
anchors.

What it should say: keys in `Comments` and `Formulas` are anchors on the same
page, and they are numbered together. Give every block a key that is unique
across both sections. A formula and a comment on the same subject want
different keys (`suspension` and `suspension-eigenvalues`), and often the
comment is the formula written out in words and should go.

Evidence: 2026-09-17, draft T291. `/preview?table=` with its `Comments` and
`Formulas` returned 200, with labels `(1)`, `(4)`, `(3)`, `(4)` and two
`id="suspension"` blocks. `GET /api/table/T291/audit` reported only the
length of the Definition.
