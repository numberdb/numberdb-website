## Polynomial `.factor()` can reach missing Sage modules under named imports
What happened: the gamma2 class-polynomial generator first tried to factor the
exact polynomial `H_Delta(x^3)` with Sage's polynomial `.factor()` after
`import numberdb.sage` and named imports only. In the Sage image used for
table builds this failed before doing mathematics, with
`ImportError: cannot import name PolynomialSequence_generic`, reached through
Singular's polynomial-sequence machinery. PARI's exact `factor` on the same
integer polynomial worked, and the selected factor was still checked against
PARI's independent `polclass(Delta, 5)` and against degree counts from reduced
forms.

What the skill says now: it says to expect missing Sage machinery under named
imports, and names power-series methods, matrix determinants, and symmetric
functions as examples. It does not mention ordinary polynomial factorization.

What it should say: exact polynomial `.factor()` may also pull in unavailable
Sage modules in the build environment. If factoring is a mechanical exact
step rather than the independent check itself, use an exact backend such as
PARI factorization or write the needed arithmetic directly, and keep an
independent mathematical check for the selected factor.

Evidence: on 2026-09-17, `/tmp/numberdb_gamma2_factor_probe.py` failed at
`(H(x**3)).factor()` with `ImportError: cannot import name
PolynomialSequence_generic`. Changing that line to `pari(H(x**3)).factor()`
computed all 100 discriminants with factors of degrees `h` and `2h`, and
each degree-`h` factor agreed with `pari.polclass(Delta, 5)`.
