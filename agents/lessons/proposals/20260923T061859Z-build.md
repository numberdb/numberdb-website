## A direct-fill helper must ask `digits_for()` after per-entry precision is known

What happened: T443 returns per-entry precision, with the left tail of the
Hastings-McLeod table kept to four significant digits and the central range
kept to ten. The first direct `submit_entries` helper copied from earlier
empty-draft workarounds did
`wanted = generator.digits_for(params)` before computing the entry, but the
generator had not overridden `digits_for()`, so every row was validated
against the table-wide default of ten digits. The run stopped before sending
anything with `T443 entry -8: 10 digits were asked for and this value carries
2`, even though `value()` returned `{"number": "2.0", "digits": 4}`.

What the skill says now: it says to use the per-entry `{"number": x,
"digits": n}` form when the left end loses digits, and separate proposed
lessons say that fresh empty drafts sometimes need a direct-fill helper
instead of `Generator.publish()`. It does not say that such a helper has to
preserve the generator's per-entry precision contract.

What it should say: if a direct helper bypasses `Generator.publish()` and
builds an `Entries` object itself, either override `digits_for(params)` to
return the row's precision or read `entry["digits"]` after `_entry()` returns
and use that for `_check_precision()` and `entries.add(..., digits=...)`.
Otherwise a generator that correctly returns per-entry digits can still be
validated and submitted as though every row claimed the table-wide default.
Also preserve trailing zeros when formatting a measured decimal: `2.000`
carries four significant digits, while `2.0` carries only two.

Evidence: T443, 2026-09-23. The first
`NUMBERDB_KEY_FROM_STDIN=1 NUMBERDB_PUBLISH=1 agents/sage.sh
generators/hastings-mcleod-painleve-ii/generate.py` stopped locally with
`T443 entry -8: 10 digits were asked for and this value carries 2`. After
overriding `digits_for()` and formatting `2.000`, the same command filled
1001 entries, `verify(sample=None)` reported `1001/1001 matched`, and the
audit returned `clean: true`.
