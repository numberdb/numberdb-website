## Whole-document draft edits can refuse parameter-order changes
What happened: T302 is an unpublished draft. A repair prepared from authenticated `GET /api/table?id=T302` changed only prose plus the parameter order from `n, j, normalisation` to `n, normalisation, j`, with the `Numbers` nesting changed the same way. Sage checked that the repaired nesting preserved every stored rational weight, both normalisations, and the moment identities. Sending the whole document back through `POST /api/table/T302` as zeta3 answered 409 with `This edit changes the table parameters`, naming the before and after orders. A follow-up authenticated `GET` showed the live draft was unchanged.

What the skill says now: a parameter key is an address and is frozen when the table is published. The skill does not say that a whole-document API edit may refuse to reorder parameters on a filled draft.

What it should say: settle the order of parameters before filling a draft. If a filled draft needs a parameter-order change, do not assume that rewriting the whole document with reordered `Numbers` will be accepted through the API; a 409 `This edit changes the table parameters` may require a person or a different explicit workflow.

Evidence: T302 repair attempt, 2026-09-17. The API response was `{"error": "This edit changes the table parameters.", "before": ["n", "j", "normalisation"], "after": ["n", "normalisation", "j"]}`; `/tmp/t302_check_repaired.py` under `agents/sage.sh` printed that the repaired nesting, stored values, normalisations and moments were checked for `n=1..12`.
