# Lessons from the T347 build, 2026-09-20

## The elliptic-curve constructor may need more than `numberdb.sage` initialises

What happened: the first probe for T347 used the named import
`from sage.schemes.elliptic_curves.constructor import EllipticCurve` after
`import numberdb.sage as numberdb`, then called
`EllipticCurve([0, 0, 1, -1, 0])`. Under `agents/sage.sh` that raised
`ImportError: cannot import name PolynomialSequence_generic`. Importing
`EllipticCurve` from `sage.all` made the probe work, but a table generator
should not import `sage.all`, and `agents/table-build/dry_run.py` reports it.

T347 avoided the constructor in the generator. It read the exact compact
Cremona records with `CremonaDatabase().allcurves(N)`, stored the five
sign-normalised generator points explicitly, and wrote the generalized
Weierstrass group law in exact rational arithmetic for the independent
`x(nP)` check. The public `Programs` snippet can still use ordinary Sage,
where `from sage.all import EllipticCurve` is the expected reader interface.

What the skill says now: the generator section says to import `numberdb.sage`
before named Sage imports, and warns that some machinery reached by named
imports is missing. Its examples are power-series methods, matrix
determinants, `SymmetricFunctions(...).expand()`, root finding, `RealBall.str`,
and parsing decimals as rationals. It does not mention elliptic-curve object
construction.

What it should say: if a generator relies on a Sage object constructor, test
that exact named-import path under `dry_run.py` before committing to it.
`sage.all` working in a probe does not mean the generator has a portable
import. When a constructor pulls in unavailable Sage machinery, either use the
exact lower-level data the source already provides, or write the needed
arithmetic directly and leave the `sage.all` convenience form to `Programs`.

Evidence: 2026-09-20 build of T347. `/tmp/probe_eds.py` and
`/tmp/probe_cremona_curve.py` failed with `PolynomialSequence_generic` under
the named constructor import; the same probe worked with `from sage.all import
EllipticCurve`. The committed generator
`generators/elliptic-divisibility-sequences-elliptic-curves-q/generate.py`
passes `agents/table-build/dry_run.py`, and its public Sage program was tested
separately.
