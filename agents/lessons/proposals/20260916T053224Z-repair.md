## A Definition cannot carry a table cross-reference even when it is the first mention

What happened: the T259 critique correctly noticed that the table names Schur
polynomials in its Definition while the corpus has a Schur-polynomial table
linked from `Similar tables`. Applying the skill's "Link the first mention of
a thing to what explains it" sentence literally, I changed the Definition to
use `HREF{Schur_polynomials}[the Schur polynomial]`. The API accepted the edit,
but `GET /api/table/T259/audit` immediately returned
`Definition links to another table; a cross-reference belongs in Similar tables
or a comment`. Removing the `HREF` from the Definition and leaving the existing
`Similar tables` link made the audit clean again.

What the skill says now: "Link the first mention of a thing to what explains
it. A table if the corpus holds one; otherwise a reference the table already
declares." The section table also says the Definition holds what the object is
and not caveats, history or relations, but it does not say that a table link is
counted as a cross-reference rather than a definition aid.

What it should say: do not put `HREF{...}` table cross-references in a
Definition. If the Definition names an object whose table the corpus holds,
put the relation in `Similar tables` when it is about the family, or in a
comment when the prose needs the link; keep the Definition to the defining
sentence and cite external sources there if needed.
