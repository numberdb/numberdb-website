## Pin living surveys to the revision used

What happened: T6 cited Radziszowski's "Small Ramsey Numbers" as a 2011 dynamic survey, while the DOI now resolves to DS1 revision #18, April 24, 2026. The newer revision gives tighter upper bounds for every stored interval from $R(5,5)$ through $R(10,10)$, so a reader following the table's own reference saw different numbers and no way to tell which revision the table had transcribed.

What the skill says now: cite references and check declared sources, but it does not say what to do when the source is a living survey whose DOI always resolves to the newest revision.

What it should say: when a table transcribes values from a dynamic survey, database, wiki table, or other living source, pin the reference to the revision or access date that the values came from. If the table's range or rigour details depend on that source, name the pinned revision there too.

Evidence: T6 repair, 2026-09-21. DS1 revision #18 Table Ib gives `[43, 46]`, `[102, 160]`, `[205, 492]`, `[282, 1518]`, `[565, 4956]` and `[798, 16064]`, while T6 still held the older upper endpoints 48, 165, 540, 1870, 6588 and 23556.

## Bounds for unknown integers are not exact rigour

What happened: T6 has type `Z`, but six entries are intervals between published lower and upper bounds for Ramsey numbers whose exact values are unknown. The table's metadata said `rigour: exact` and carried the generic exact-value sentence, "there is no precision to choose and nothing to be wrong about", which was false for those six rows.

What the skill says now: `exact` means an integer, rational or polynomial, and real intervals can record uncertainty; it does not explicitly call out integer intervals that are theorem bounds rather than exact integer values.

What it should say: `exact` is for a value known exactly, not for exact endpoints around an unknown integer. If a table stores an interval because the integer itself is not known, use `proven` when the bounds are theorems, and make `rigour details` say that the interval width is mathematical ignorance rather than numerical error.

Evidence: T6 repair, 2026-09-21, changed `rigour` to `proven` and rewrote `rigour details`; T5 already uses this pattern for a theorem-bounded interval.
