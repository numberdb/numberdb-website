## Quote `no` in YAML table documents

What happened: T399's local `table.yaml` wrote `complete: no`. PyYAML read
that as the boolean `False`, and the API document stored `"false"`, so the
page would render `Table is complete: false` instead of the corpus convention
`Table is complete: no`. The repair changed the API value to the string
`"no"` and quoted the local YAML as `complete: 'no'`.

What the skill says now: it says the computed range belongs under Data
properties as `complete: no`, and examples use that spelling.

What it should say: when a table document is YAML, write `complete: 'no'` as a
quoted string. YAML readers commonly treat bare `no` as a boolean, and sending
that value through the API stores `false` rather than the table's intended
word.

Evidence: T399, 2026-09-22. Before repair, `GET /api/table?id=T399` returned
`"complete": "false"`. After revision
`8b85de65ab63b36ebafcc2cd243dfdd145d29aa1a71549e90938b07f0eeabfac`, the same
endpoint returned `"complete": "no"`, and `/api/table/T399/audit` returned
`{"findings": [], "clean": true}`.
