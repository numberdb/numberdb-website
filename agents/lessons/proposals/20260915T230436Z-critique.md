# Proposed by the T251 critique run, 2026-09-15

## `CITE{}` also cites a formula or a comment in the same table

What happened: T251 wants its `rigour details` to say which formula the
generator computed, and its `Similar tables` relations to say which identity
makes the relation. It writes `CITE{formula-radial-sum}` and
`CITE{formula-jacobi}`, using the keys of its own `Formulas` entries. That
works: the renderer resolves them and prints a link reading `(2)` and `(4)`,
the numbers those formulas carry on the page. `CITE{comment-forms}` resolves
the same way against a `Comments` key.

Two things follow that an author cannot guess:

* The numbering is **global and in render order**, not per section. The page
  lays out `Formulas` before `Comments` whatever order the document writes
  them in, so a table with nine formulas and five comments numbers the
  formulas `(1)`-`(9)` and the comments `(10)`-`(14)`. A `CITE` to the first
  comment prints `(10)`.
* A `CITE` to a key the document does not define renders as the key itself in
  a `CITE-broken` span, not as an error. `audit_table` does catch that one, but
  only if you run it.

What the skill says now: "Use `$...$` for mathematics, `CITE{key}` for a
reference or link, and `HREF{slug}[caption]` for a table here." `CITE` is
described only as pointing outward, at a `Links` or `References` key. Nothing
says a table can cite itself. So a contributor who wants `rigour details` to
name the formula it checked against writes the formula out a second time, or
writes "the Jacobi-polynomial identity above" -- which is the pointing the
skill elsewhere tells them not to do -- because the field that would let them
name it is not documented.

What it should say: alongside the `CITE{key}` sentence, that the key may also
be a key of this table's own `Formulas` or `Comments`, in which case it
renders as that item's number on the page and links to it; that the numbering
runs across `Formulas` and then `Comments` in the order the page lays them
out, so it is not the position within the section; and that this is how
`rigour details`, a `Similar tables` relation or a comment names an identity
without restating it. It is the answer to "Name the thing, do not point at
it" for a formula: `CITE{formula-jacobi}` stays right when the section is
reordered, where "the identity above" does not.

Evidence: 2026-09-15, T251. A document with `Formulas: {formula-a, formula-b}`
and `Comments: {comment-a, comment-b}` and a definition reading
`A test of CITE{formula-a}, CITE{comment-a} and CITE{Wiki}.` was sent to
`/preview?table=`; it rendered

    A test of <a class="CITE" href="#formula-a">(1)</a>,
    <a class="CITE" href="#comment-a">(3)</a> and
    <a class="CITE" href="#Wiki">[1]</a>.

with the `Formulas` block labelled `(1) (2)` and the `Comments` block `(3)
(4)`, in that order on the page, though the document listed `Comments` first.
T251 uses six such citations and all six resolve.
