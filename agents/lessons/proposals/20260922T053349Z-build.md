## For quasinormal-mode continued fractions, compare the accepted roots, not every Newton trial tail

What happened: the Schwarzschild quasinormal-mode generator for T399 first
treated failure of the modified Lentz tail to meet a strict tolerance at any
Newton trial point as a fatal error. That rejected scalar monopole overtones
before a root had been accepted, while the independent `qnm` package records
the continued-fraction residual at a capped depth and then checks the accepted
root. The build kept only the fundamental modes because the scalar overtones
were too slow to verify cleanly in this campaign run.

What the skill says now: verify against an outside computation, and when two
computations disagree, chase the cause. It does not say how to interpret a
continued-fraction convergence diagnostic that is evaluated at Newton trial
points rather than at an accepted root.

What it should say: for quasinormal-mode tables built from Leaver continued
fractions, do not turn the Lentz stop test at every Newton trial point into
the only correctness criterion. Match the reference implementation's policy:
use a capped continued-fraction evaluation, record or describe the residual as
a numerical diagnostic, and require independent checks on the accepted roots,
such as a second working profile and a tabulated or cached source. If the
accepted roots cannot be checked in reasonable time, shrink the range rather
than publishing guessed overtones.

Evidence: T399 on 2026-09-22. The private dry run with strict tail exceptions
failed for the scalar monopole sequence; inspecting `qnm.radial` showed that
`leaver_cf_inv_lentz` returns `(value, residual, depth)` at the cap, and
`SchwOvertoneSeq` accepts the result while keeping that residual. The final
draft stores only the 15 fundamental modes, compares every stored row with the
Black Hole Perturbation Toolkit `qnm` cache, verifies 15/15 values after the
API write, and has a clean audit.
