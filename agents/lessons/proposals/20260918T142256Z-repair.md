## Keep API edit messages ASCII when they are sent as HTTP headers
What happened: repairing T331 added the correct accented keyword `Kac-Murdock-Szegő matrix` to the document body, and the first API write used "add the Szegő keyword" in `X-Edit-Message`. The request failed before reaching the server: Python's standard `http.client` encodes header values as latin-1, and `ő` is outside that range. Changing only the header text to `Szego` let the same YAML body, still containing `Szegő`, commit successfully.

What the skill says now: it says accents belong in titles or keywords when a reader will type them, and it says to write through the API with an edit message. It does not say that the table body and the HTTP headers have different character limits.

What it should say: when writing through `/api/table/<tid>`, keep `X-Edit-Message` and other API header values ASCII, or at least latin-1. Put non-ASCII mathematical names in the document body, not in the revision-message header.

Evidence: `/tmp/t331_repair.py apply`, 2026-09-18, first failed with `UnicodeEncodeError: 'latin-1' codec can't encode character '\u0151'`; replacing only the header word with `Szego` committed revision `5819a99d88c8e4cd49d15078e79799eb5a468f91916ce0bd600d6dab82f091b4`.
