## Convert ecnf-data base-change labels before using Sage's Cremona database

What happened: T292 checked real-quadratic elliptic-curve L-values marked as
base changes in ecnf-data against the product of the two rational-curve
L-values. The ecnf-data `base_change` field names rational curves by LMFDB
label, for example `192.d6`. Sage's `CremonaDatabase().allcurves(N)` is keyed
by Cremona labels, and looking up `192.d6` directly selected the wrong curve.
The product then disagreed with the number-field value for the row
`2.2.8.1-72.1-a`.

What the skill says now: nothing specific about ecnf-data base-change labels
or Sage's Cremona label convention.

What it should say: when ecnf-data names a rational elliptic curve and Sage's
Cremona database is the independent source, convert the LMFDB label with
`sage.databases.cremona.lmfdb_to_cremona(label, CremonaDatabase())` before
calling `allcurves`. A disagreement between the base-change product and the
number-field value is not evidence for either value until the labels have
been checked.

Evidence: T292 build, 2026-09-17. The dry run first failed on
`2.2.8.1-72.1-a`: the number-field L-value was
`0.822110581747...`, but the product from the unconverted labels was
`0.642644632...`. After converting `192.d6` and the other labels with
`lmfdb_to_cremona`, the full dry run reported 572 entries computed with no
disagreements, and `verify()` on the filled draft reported `572/572 matched`.

## Repeated row links and equations can be the whole size problem

What happened: T292's first clean dry run kept the proposed complete range,
572 isogeny classes with conductor norm at most 150, but each row comment
repeated an LMFDB URL and a full Weierstrass equation. The generated block was
198.2 KB, over the half-soft-limit target. Removing the repeated URL lowered
the block to 168.4 KB, still over target. Keeping only the representative
curve label, conductor ideal and rank lowered the block to 127.4 KB without
shrinking the mathematical range.

What the skill says now: measure the table before choosing the range, and
entry comments should state facts a reader would recognise.

What it should say: when a table is over the size target because every entry
comment repeats a long external URL, equation or defining data, first ask
whether a compact source label identifies the row and whether the generator
or data attachment preserves the long data. Trimming repeated comments can
keep a complete rectangle that would otherwise look too large.

Evidence: T292 dry runs on 2026-09-17. The final dry run reported
`572 entries, longest 75 characters at D=5,class=a,conductor=121.1, block
127.4 KB`.
