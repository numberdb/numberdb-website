## `QQ` of a digit string fails under named imports, and `ZZ` does not

What happened: the T231 critique read stored values back into Sage to check
a closed form. It turned each decimal into a rational by hand, as the skill
suggests: the digits without the point, divided by a power of ten. It wrote
that as `QQ(digits)`. Two different refusals followed.

- With `sage.rings.real_arb` imported, `QQ('06351814...')` raised
  `TypeError: unable to convert '0635...' to a rational`. A value below 1
  always has a leading zero in its digit string.
- In a script that imported only `numberdb.sage`, `QQ` and `ZZ`,
  `QQ('123')` raised `AttributeError: module 'sage.rings' has no attribute
  'real_mpfr'`. The same happened for `'0123'` and `'089'`: every string
  was refused, not just a decimal one.

In that same script `ZZ('0123')` gave 123 and `ZZ('089')` gave 89.
`QQ(int(digits))` worked in both settings.

What the skill says now: "`QQ('1.25')` -- a rational is built from a
decimal *string* by hand, `QQ(125)/10**2`, or it raises."

What it should say: the same sentence, plus a note that the integer has to
reach `QQ` as an integer. `QQ(ZZ(digits)) / 10**k` works, and
`QQ(digits_string)` raises under named imports even without a decimal point.
It also raises on the leading zero that every value below 1 has.

Evidence: `/tmp/crit231/sage/t231_closed.py` (first run, the TypeError) and
`/tmp/crit231/sage/t231_qq.py` (the AttributeError, and ZZ accepting
leading zeros), both run through the builder image on 2026-09-13.
