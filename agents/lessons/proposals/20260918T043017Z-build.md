## In the named-import Sage environment, parse rational strings by their slash instead of calling `QQ(text)`

What happened: after filling T321, the read-back check fetched the stored
`Numbers` mapping from `/api/table?id=T321` and tried to parse entries such as
`"9/2"` with `QQ(value_text)`. In the `agents/sage.sh` environment this raised
`AttributeError: module 'sage.rings' has no attribute 'real_mpfr'`, before any
table value could be checked. Splitting the string at `/` and building
`QQ(ZZ(numerator)) / QQ(ZZ(denominator))` worked.

What the skill says now: it says `QQ('1.25')` is not initialised under named
imports, and that a rational built from a decimal string should be built by
hand.

What it should say: do the same for stored rational text such as `9/2` when
running under named imports. Parse the numerator and denominator explicitly,
then build the Sage rational from Sage integers.

Evidence: 2026-09-18, `/tmp/legendre_readback.py` against draft T321. The first
run failed at `QQ(value_text)` for the stored value `9/2`; the second run
parsed the numerator and denominator explicitly and checked all 167 stored
values against Euler's criterion, the known small values, and the $L^4$ identity.
