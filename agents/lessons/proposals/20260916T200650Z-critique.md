## A blank line in a `>-` YAML block is one newline, so it does not start a paragraph

What happened: the T282 table source wrote `rigour details` as a folded
scalar (`>-`) with two paragraphs separated by one blank line. YAML folding
turns a single blank line into a single `\n`, so the stored note had no blank
line and the page rendered one paragraph. The note is longer than 400
characters, so the renderer folded it after a sentence. It showed the method
for five rows and hid the method for the other 96 behind *more*.

What the skill says now: "blank lines make paragraphs, `- ` makes a list".
That is true of the stored text. It is not true of a blank line inside a `>`
block in a YAML source file, which is where contributors write the note.

What it should say: in a YAML source, write a multi-paragraph
`rigour details` with `|` (literal), or put two blank lines between paragraphs
in a `>` block. Check the result by reading the note back from
`GET /api/table?id=...` and looking for `\n\n`.

Evidence: `yaml.safe_load('a: >-\n  one\n\n  two\n')` gives `'one\ntwo'`,
while `|-`, or `>-` with two blank lines, gives `'one\n\ntwo'`. The stored
T282 note contains `majorant.\nBefore the draft`. In `generators/*/table.yaml`,
14 `rigour details` values contain a newline but no blank line, T282's among
them. I have not checked how many of the other 13 meant to have paragraphs.
