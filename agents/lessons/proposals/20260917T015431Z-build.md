## Quote identifier fields whose values look numeric

What happened: T287's first audit found that `arxiv: 0912.0287` had been
parsed by YAML as the number `912.0287`, dropping the leading zero before the
document reached NumberDB. The table document looked right to a reader, but
the API received a different value and `audit_table` reported that the arXiv
identifier was not in the expected shape.

What the skill says now: an identifier goes in its own field, not in the
sentence, and the examples show bare `arxiv:` values. It does not say that a
YAML plain scalar that looks like a decimal may be parsed as a number before
the site sees it.

What it should say: quote `arxiv`, `doi`, `zbl` and `mr` values in
hand-written YAML table documents. This is especially important for arXiv
identifiers before 2015 with a leading zero, such as `'0912.0287'`, because
YAML may otherwise strip that zero as part of numeric parsing.

Evidence: T287 draft, 2026-09-17. `/api/table/T287/audit` first returned
`arxiv of reference DGMMPR is 912.0287, which is not YYMM.NNNNN; a leading
zero is the usual casualty`. Quoting the DOI and arXiv fields in
`generators/xorsat-threshold-equation-roots/table.yaml` and resubmitting the
draft made the audit clean.
