## A title must not be the accepted name of a *different* number, and the corpus's own prose is where to check

What happened: T8 is titled "Euler's constant e". In modern usage *Euler's
constant* is $\gamma = 0.5772156649\ldots$, and this database holds that
number — `search_real_ball(0.5772156649015329, 1e-15)` returns T16 (Stieltjes
constants) and T231 (Euler-Lehmer constants). Worse, two tables here already
*use the phrase for $\gamma$ in their prose*: T231 and T230 both carry the
comment "$\gamma=\ldots$ is Euler's constant, the Stieltjes constant
`HREF{Stieltjes_constants#0}[$\gamma_0$]`". So the corpus says the phrase
means one number in two tables' comments and another number in a third
table's title. The table's own `Links[1]`, the Wikipedia article on $e$, does
not use the phrase at all, and the article that *is* titled "Euler's constant"
is about $\gamma$.

What a reader gets, measured on the live corpus:

    search_text("Euler's constant")  -> 20 results
      4 T8   Euler's constant e        <- the only title carrying the phrase
      7 T231 Euler-Lehmer constants
      T16, which actually holds gamma, is not in the twenty at all.

Somebody typing the standard name of $\gamma$ is offered one table that
appears by name to be about it, and it is a different number.

What the skill says now: §2 says "A title is what a search reaches" and tests
it by *what a reader would type who is holding one of these numbers* — a test
that T8 passes, since somebody holding 2.718 does find it. It says nothing
about the reverse direction: a title that answers a query it should not,
because the name belongs to something else.

What it should say: before fixing a title, search the corpus for the *name* as
well as for the family, and read what comes back. If another table's prose
already uses that name for a different object, or the reference the table
itself cites uses it for a different object, the name is not yours to put in a
title. Prefer the name the cited source uses ("Euler's number"), and where the
ambiguous name is worth carrying at all, carry it in a `Comments` line that
says which number it usually means and links that one — `Comments` is indexed
at the lowest weight, so the phrase still reaches the table, and it reaches it
attached to the disambiguation instead of to the claim. Do not put such a name
in `Keywords`: `Keywords` has the same weight as the title, so it reproduces
exactly the mis-hit the retitling was meant to remove.

Evidence: T8 critique on 2026-09-22, `agents/critiques/T8.md` §1. The searches
above are live and reproducible; the two comments are in
`numberdb.table('T231')['Comments']['comment-euler-constant']` and the same
key of T230. The Wikipedia leads are from
`en.wikipedia.org/api/rest_v1/page/summary/E_(mathematical_constant)` and
`.../Euler%27s_constant`. A smaller instance of the same confusion is in this
repository already: `agents/lessons/proposals/20260913T152809Z-repair.md` is
titled "get Euler's constant as `-psi(1)`", meaning $\gamma$, written while
T8 claimed the name for $e$.
