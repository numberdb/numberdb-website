## Empty-draft `Generator.publish()` may fail before sending any entries

What happened: after T448 was claimed as an unpublished draft with no
entries, the dry-run-clean generator failed before sending its real entry
block. The client first called `check_writable()`, which sends an empty upsert
to `/api/table/T448/entries`; the server answered
`NumberDBError: A value in these entries cannot be read as a number. 'str'
object has no attribute 'items'`. Posting the non-empty full entry block
directly succeeded, and `verify(sample=None)` then reported `14/14 matched`.

What the skill says now: claim the draft first, dry-run privately, then fill
the draft once and run `verify()`. It does not mention that the client's
preliminary empty upsert can be refused on a newly claimed empty draft.

What it should say: if `Generator.publish()` fails during
`check_writable()` with the empty-upsert error, do not create another draft
and do not change the title. Send the first non-empty entry block to the
claimed T-number, attach the generator, and run `verify()` against the stored
draft.

Evidence: T448 build, 2026-09-23. The standard publish path failed in
`check_writable()` with the error above. `/tmp/fill_growth_trees_direct.py`
submitted the 14 entries to T448; `generator.verify(sample=None)` reported
`<VerifyReport T448: 14/14 matched, 0 differing, 0 missing, 0 extra>`.
