## A component proved exact must be *returned* exact, or the page prints `[0, 0]`

What happened: T317 holds 466 complex cusp shapes. Twenty of them -- the
amphichiral knots -- are purely imaginary, and the table proves it: the mirror
formula $\tau(S^3\setminus\bar K)=-\overline{\tau(S^3\setminus K)}$ with
$\bar K=K$ forces the real part to zero. SnapPy's verified computation returns
an enclosure of zero with tiny radius (`0.?e-117`), which carries no
significant digits at all, so the first fill was refused: "90 digits were
asked for and this value carries 0". The generator fixed that by replacing the
real component with an exact zero **inside the same ball field**:

    def _pure_imaginary(z):
        return z.parent()(0, z.imag())

The fill then accepted all 466 entries, and the fix is mathematically right.
But `to_text` writes a zero-width ball as a zero-width *interval*, so all
twenty rows are stored and rendered as

    [0, 0] + i * 3.46410161513775458705489268301174473388561050762076125611...

That spelling is legal, and it means the opposite of what the generator
established. `numberdb_app/test_interval_spelling.py` says why the two
spellings exist: "a zero-width interval is written as an interval --
`[3/2, 3/2]`, not `3/2` -- so that the page says which of the two things it
is: a value declared exact, or interval arithmetic that landed on a point."
The computation did not land on a point; a theorem put it there. Writing it
`[0, 0]` tells a reader the weaker of the two things, in brackets, on the only
twenty rows of the page where a value does not look like a number.

What the skill says now: "decide exactness from the definition, never from the
digits; a value exactly rational is written exactly", and the table of what
`value()` may return, where `int`/`Fraction` are the exact branches and
`ComplexBallField(prec)(x)` is the interval one. Nothing says the two can be
mixed inside one complex value, and nothing warns that `parent()(0, imag)`
stays on the interval branch.

What it should say: the exactness rule applies **componentwise**, and it has
to be carried in the *type* of the component, not only in its value. A complex
value whose real (or imaginary) part is exactly zero, or exactly rational, by
a theorem is written by returning that component as an `int` or a `Fraction`
beside the ball -- the client's `ComplexInterval` writes each component by its
own rule (`_write.py`, `_complex_text`) -- not by putting an exact zero into a
ball field, which writes `[0, 0]` and claims only that an interval computation
happened to land there. The same applies to the imaginary part of a value
proved real. Check the written form, not the object: run the value through
`numberdb._write.to_text(value, digits)` and read what comes out before the
fill.

Evidence: T317 draft, 2026-09-18. Twenty of 466 stored numbers begin
`[0, 0] + i * `; the `Programs` block's own output for $4_1$ is
`0.?e-117 + 3.464101615137754587...*I`; commit da25f9e added
`_pure_imaginary`; `agents/lessons/proposals/20260918T001830Z-build.md`
records the exactness half of the lesson and not the writing half.

## An index parameter whose values are words trips the two-tables rule, and the answer is a sentence, not a split

What happened: T317's index is $n$, $k$ and a third parameter `knot` taking
`K` and `mirror` -- because $n$ and $k$ name a Rolfsen knot, and a Rolfsen
knot is two knots when it is chiral. `GET /api/table/T317/audit` reports

> parameter knot takes 2 names (K, mirror), each carrying entries of its own,
> so this reads as 2 tables sharing one title and one value column

which is the right question to ask of that shape and the wrong verdict here.
Nothing about `K` and `mirror` names a *quantity*: one quantity is listed, and
the parameter finishes the index the way $k$ finishes $n$. The check cannot
see it, because its escape hatch is `_reads_as_a_number` -- an argument
spelled `0, 1, 2` steps aside, an argument spelled `K, mirror` cannot.

The rule's own docstring gives the remedy: "if they are one object in several
parts, or one number in several conventions, say so in the definition and
leave them together." T317 does say so, in its Definition ("and their distinct
mirror images") and again in a comment, and the value column is headed with a
symbol rather than the word `value`.

What the skill says now: "Where several named objects share a subject but not
a name, make several tables", and "seven functions evaluated at the same
rational $x$ are still seven functions". Both are about quantities. Neither
mentions the case where the words index the *argument*.

What it should say: a parameter whose values are words is not by itself a
second table. Ask what the words name. If they name quantities -- `form:
ehrhart | h-star`, `quantity: psi | H` -- that is several tables. If they name
which member of the family the row is about -- a mirror image, a conjugate, a
branch, a sign -- it is one table with a spelled-out index, and the way to
settle it is to name the choice **in the Definition**, so that a reader and
the audit both meet the answer before the question. A table that does this
should expect the audit to ask anyway and should answer it in the critique
rather than split.

Evidence: T317 and T313 (published) both carry `knot: K | mirror` over the
same 466 knot-and-mirror rows; T317's audit reports the finding and T313's
does not, because the rule is only asked of drafts. The rule is
`audit_table.py` `_one_table_or_several`, and its `_reads_as_a_number`
exemption is what a word-valued argument falls outside of.
