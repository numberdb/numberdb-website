# Lessons proposed by the T327 critique, 2026-09-18

Format as in `agents/lessons/PROPOSALS.md`. Nothing here is in force.

## `AA(x)` on an algebraic eigenvalue raises `NameError: QQbar_I` when the rings are imported by name

What happened: reading T327, whose generator "computes the eigenvalues of
$A_n^{\mathsf T}A_n$ in Sage's algebraic real field", I wrote the obvious
recomputation in the style the skill prescribes -- rings imported by name,
never `sage.all`:

    from sage.matrix.constructor import matrix
    from sage.rings.rational_field import QQ
    from sage.rings.qqbar import AA

    B = A.transpose() * A
    ev = sorted(AA(x) for x in B.eigenvalues())

It worked on the Parter matrices of order 2 to 5 and stopped at order 6:

    NameError: name 'QQbar_I' is not defined

from inside `sage/rings/qqbar.py`, at `iv = QQbar_I * (arg.conjugate() -
arg) / 2`. `B.eigenvalues()` returns `QQbar` elements, and coercing one into
`AA` can reach a branch of `exactify` that uses a module-level `QQbar_I` which
nothing has created: it is there after `sage.all` is imported, and a program
that imports its rings by name never makes it. Which matrices reach that
branch is not something a caller can predict, and that is the worst part of
it: the same code passed on every order up to 5 and raised at 6, so a check
written on a small example says nothing about the one that matters.
`B.change_ring(AA)` fails differently and just as obscurely,
`AttributeError: module 'sage.rings.polynomial' has no attribute
'laurent_polynomial_ring'`.

One route works under both import styles:

    ev = sorted(B.charpoly().roots(AA, multiplicities=False))

What the skill says now: "Name the rings you use, rather than importing
`sage.all`", followed by the list of what the named imports do not bring --
root finding, `RealBall.str`, `QQ('1.25')`. Algebraic numbers are not on that
list, and the whole point of the list is that each item costs somebody an
hour.

What it should say: add the algebraic fields. Under named imports, coercing a
`QQbar` element into `AA` -- which is what `matrix.eigenvalues()` hands back
for an exact matrix -- can raise `NameError: QQbar_I`, and `change_ring(AA)`
raises about `laurent_polynomial_ring`. Take exact eigenvalues as
`M.charpoly().roots(AA, multiplicities=False)`, which needs nothing extra.
Worth saying in the same breath: a `NameError` or an `AttributeError` naming
an internal Sage module is almost always this, not a bug in your code, and the
answer is a different route rather than `import sage.all`.

Evidence: 2026-09-18, T327 critique, SageMath 10.9. `/tmp/t327_probe.py` and
`/tmp/t327_probe2.py`, the same three routes on a $6\times6$ Parter matrix
with and without `import sage.all` first: without, one of three works; with,
all three do.

## A `Programs` snippet has to end on a number the table holds

What happened: T327's Sage program builds the $3\times3$ Hilbert matrix over
$\mathbb{Q}$, forms $B=A^{\mathsf T}A$, and calls `B.eigenvalues()`. It runs,
it raises nothing, and it prints three eigenvalues -- not a condition number,
which is what the table holds. The last step, the ratio of the extremes and a
square root, is in the definition and not in the program, so a reader who
copies the snippet gets three numbers none of which is in the table and no
way to tell whether they have the right matrix. One more line closes it, and
the result is the stored entry to all hundred digits.

This is the failure that survives "run the snippet": the snippet ran. What it
did not do was answer the table's own question.

What the skill says now: "`Programs` is the standard incantation in Sage, PARI
or mpmath for a reader who wants one more value." It names the purpose and
stops, and a snippet that computes an ingredient rather than the value
satisfies every check in the corpus.

What it should say: the test for a `Programs` block is not that it runs but
that its last line prints a value this table stores, at parameters the table
stores, and that you compared the two. Where the snippet builds an object
whose indexing convention differs from the table's -- T327's program indexes
from 0 while its comment defines the Hilbert matrix 1-based -- say so in the
snippet, because the reader is reading the two side by side.

Evidence: 2026-09-18, T327. `/tmp/t327_check.py`: the snippet as published
returns `[7.221798187768998?e-6, 0.014963911040425818?, 1.983362200494720?]`;
`sorted(B.charpoly().roots(AA, multiplicities=False))` and one division and a
square root give `524.056777586060817870782845927782638928...`, against the
stored `hilbert, 3` of `524.05677758606081787078284592778...`.

## The API route that reads a table is not the route that writes it

What happened: reading a draft through the API, `GET /api/table/T327` answers
`{"error": "Use POST or PUT."}` -- it is the write route, which takes the
T-number in the path. The read route takes it in the query string, `GET
/api/table?id=T327`, and accepts the address as well as the number, `GET
/api/table?id=Cos_pi_times_x_at_rational_numbers`. The audit is a third shape
again, back in the path: `GET /api/table/T327/audit`. The error message names
the methods the route does accept and not the route that would have worked,
so the first reading of it is "I need to POST", which is the opposite of what
a reader wants.

What the skill says now: it documents `numberdb.table('T119')` from the client
and `POST /api/tables` for creating a draft. The read route is not written
down, and somebody with `curl` and an API key -- the position anybody is in
before the client is installed, and the position every check in a CI job is in
-- guesses the symmetrical one and gets a message that reads like a
permissions problem.

What it should say: one line beside the `POST /api/tables` sentence. Reading
is `GET /api/table?id=<T-number or address>`; writing is `POST` or `PUT` to
`/api/table/<T-number>`; the audit is `GET /api/table/<T-number>/audit`. A
draft answers all three to a request carrying its owner's key and "does not
exist" to anything else.

Evidence: 2026-09-18, T327 critique; both routes with the zeta3 key against
numberdb.org.
